## Summary

将日记从「对话中触发 + Worker 占位内容」重构为「AI 依据当天记忆与上下文、模仿人类书写」的完整闭环：

1. **生成逻辑升级**：素材采集新增「当日记忆」（`memory_records.createdAt ∈ 当天`），Prompt 重写为模仿人类日记的口吻（保留反虚构红线）；生成能力抽成新共享包 `@aervox/diary`，API 与 Worker 复用同一套 Prompt/素材/解析逻辑。
2. **后端定时任务**：Worker 现有 diary 任务接入真实 AI 生成（不再占位），并懒创建每个租户的默认每日计划兜底；同日已存在日记则跳过（与按需路径不冲突）。
3. **每天首次打开**：前端首次打开当天（localStorage 日期标记）调用按需生成接口，瞬时把「日记」卡临时覆盖到侧边第一卡片槽（与学习模式联动同模式，不写持久配置）。
4. **菜单栏「日记」**：新增「日记」菜单项 + 日记对话框（今日日记 + 历史回看 + 「让思思现在写」手动立即生成/改写）。

用户已确认：生成时机以「首次打开时立即生成」为主；卡片形态用「临时覆盖槽位」；对话框支持「回看 + 手动立即生成」。

## Assumptions & Decisions

- **生成时机**：每日首次打开即时生成（主触发）；Worker 每日计划为兜底保障（同日已生成则跳过）。二者共用同一生成服务与同一日记主行唯一索引，无重复日记。
- **「当天记忆」定义**：`memory_records` 中 `createdAt` 落在当天窗口（`[本地零点, 当前时刻]`）且 `isDeleted=0` 的记录（含 `short_term/long_term` 等层）。
- **人类写日记**：仅重写 Prompt 风格约束，不引入新表/新状态；反虚构红线不变。
- **localDate 时区**：全链路统一服务器/浏览器本地时区（`en-CA`），Worker 修正原有 UTC 前缀偏差。
- **无 LLM 配置**：按需与定时路径均模板降级（诚实标注 `generatedBy:'template'`），延续 `AERVOX_LOOP_PROVIDER` 现有约定。
- **新包归属**：`@aervox/diary` 属 L1 层（依赖 contracts/database/agent-loop，禁依赖宿主），无需改 `import-boundary.mjs` 规则（正则内核天然覆盖）。
- **不做的**：不改 message/outbox/权限模型；不动 `diary_material_buffers` 摄取链路（保留）；不做日记编辑/删除 UI。
