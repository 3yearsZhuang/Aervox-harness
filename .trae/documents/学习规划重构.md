# 学习能力重构：今日学习精简 + OpenMAIC 式学习规划 + 待办同步

## 概要

参考 `reference/OpenMAIC` 的 PBL planner（单次结构化生成模式），重构工作台学习能力：

1. **去除今日学习下的「快速练习」**：练习作答面板迁入错题本弹窗（错题重练依赖它），今日学习不再提供 3 题自测入口。
2. **「计划」重构为「规划」**：新建 REST 端点，单次 LLM 调用生成「里程碑 + 任务」结构化学习路线图（OpenMAIC planner-single-call 模式），校验清洗后落库，前端展示可勾选路线图。旧 study-plans（CAP-017 考试日倒计时计划）API/UI 直接替换删除。
3. **「目标 / 复习」数据同步进待办清单**：进行中目标与到期复习自动出现在待办清单中，勾选后回写后端状态。「日记提醒」子页签仅从 UI 移除（后端日记/通知 API 与 Worker 保留，后续单独改造）。

用户已确认的决策：
- 目标/复习/日记提醒：**数据同步进待办**（日记不并入，后续改造）
- 规划生成方式：**单次结构化生成**（OpenMAIC planner-single-call 模式）
- 旧 study_plans：**直接替换**（删旧 API/UI，新建数据模型）

## 改动方案

### A. 数据库（packages/database）

**`src/schema/learning.ts`**：
- 删除 `studyPlans` 表定义（物理表不执行 DROP，SQLite 本地库遗留无害）。
- 新增三张表（参照 OpenMAIC milestone/microtask 结构）：
  - `learningPlans`：id、tenant 列、topic、level（beginner/intermediate/advanced）、title、description、learningObjective、gains(json string[])、status（active/archived）、timestampColumns
  - `planMilestones`：id、tenant 列、planId(→learningPlans.id)、order、title、description、briefing、completionCriteria、debrief、status（active/completed）、timestampColumns
  - `planTasks`：id、tenant 列、milestoneId(→planMilestones.id, cascade)、order、title、description、hints(json)、status（todo/done）、timestampColumns
- 索引：三表 tenant 索引 + planId/milestoneId 索引。

**`src/schema/init.ts`**：为三张新表补 `CREATE TABLE IF NOT EXISTS` DDL（沿用现有幂等模式）。

**`src/repositories/types.ts` + `src/repositories/sqlite/learning-repository.ts`**：
- 删除 studyPlan 相关方法（createStudyPlan/listStudyPlans/getStudyPlan/updateStudyPlan/updateStudyPlanPrediction/archiveStudyPlan 及 DTO）。
- 新增：`createLearningPlan(structure)`（事务写入 plan+milestones+tasks）、`listLearningPlans(includeArchived)`（聚合 milestones/tasks）、`getLearningPlan(id)`、`setPlanTaskStatus(taskId, status)`（含里程碑推进：任务全 done → 所在 milestone completed + 下一个 milestone active）、`archiveLearningPlan(id)`。

### B. API（apps/api/src/modules/learning）

**新文件 `plan-generation.ts`**（完全对照 `diary/generation.ts` 的端口模式）：
- `PlanModelPort`：`generate({tenant, system, user}) → Promise<string>`。
- `createLlmPlanModelPort(llmConfigService)`：getConfig → createOpenAICompatProvider → 消费 `provider.stream()` 拼接全文。
- `buildPlanSystemPrompt(topic, level, dailyMinutes)`：中文提示词，移植 OpenMAIC planner-system.md 的核心规则：紧扣主题不套模板、里程碑是「做项目的阶段」不是章节目录、任务 2-4 个且递进、hints 引导不代做、最后一个里程碑必须收尾整合、gains 3-5 条能力收获；要求输出**单个 JSON 对象**（无代码围栏）。
- `extractJsonObject(raw)`：剥离 ```json 围栏、截取首个平衡 `{...}`（兜底模型输出散文包裹 JSON）。
- `validatePlanOutput(parsed)`：结构校验返回 gaps 数组（title/description/learningObjective 非空、gains 3-5 条、milestones 2-6 个且各含 2-4 个有 title 的 task）。
- `hydratePlan`：分配 id（`plan_/ms_/mt_` 前缀 + 时间戳，参照 diaryId）、order、初始状态（milestone[0] active、其余照序、task 全 todo）。
- `renderTemplatePlan(topic, level)`：scripted/非 llm 模式确定性模板规划（3 里程碑 × 2 任务），测试与降级用。
- `LearningPlanGenerationService.generate(tenant, {topic, level, dailyMinutes})`：AERVOX_LOOP_PROVIDER !== 'llm' → 模板；否则单次调用 → 解析 → 校验失败带 gaps 重试一次（OpenMAIC 模式）→ hydrate → 落库返回。

**新文件 `plan-routes.ts`**（或在 index.ts 注册，路由风格对齐现有 learning 路由）：
- `POST /v1/learning-plans/generate` body `{topic, level?, dailyMinutes?}` → 生成并落库，返回完整规划（生成中前端展示 busy 态；LLM 未配置返回 400 明确错误）。
- `GET /v1/learning-plans`（`?includeArchived=true` 可选）。
- `GET /v1/learning-plans/:planId`。
- `PATCH /v1/plan-tasks/:taskId` body `{status: 'todo'|'done'}` → 返回更新后的完整规划（含里程碑推进结果）。
- `POST /v1/learning-plans/:planId/archive`。
- `learning/index.ts`：注册新路由，装配 `createLlmPlanModelPort`（llmConfigService 已在 app ctx，参照 diary 模块装配方式）。

**`cap016-017-routes.ts`**：删除 `/v1/study-plans*` 全部路由段（CAP-016 练习报告路由保留）。

## 假设与决策

1. **旧 study_plans 物理表不 DROP**：SQLite 本地库遗留表无副作用，避免迁移风险；schema 与仓储层代码删除即可。
2. **日记/通知后端完全不动**：仅删 UI 与 api-client 引用；`/v1/diaries`、`/v1/notifications`、Worker 的 review-notifier / diary-generator 保留（日记后续单独改造）。
3. **复习「记得/忘了」语义保留**：待办勾选 = 记得（correct），「忘了」作为旁侧按钮，保证间隔复习数据质量不因入口迁移而丢失。
4. **规划生成走同步 REST 请求**：单次 LLM 调用在请求内完成（与日记按需生成同模式），不做异步任务队列；前端 busy 态覆盖等待期。
5. **scripted 模式模板降级**：`AERVOX_LOOP_PROVIDER` 非 llm 时用确定性模板规划，测试不依赖真实 LLM（对齐 diary 的 renderTemplateDiary 模式）。
6. **提示词中文化并裁剪 OpenMAIC 规则**：保留主题忠实、阶段化而非章节化、hints 不代做、收尾整合等核心硬规则；舍弃 instructor 角色、scenario、语言策略等 OpenMAIC 运行时专属内容。
7. 「中间件重构期间不许改动路由文件」约束：近期合入的刷题模式/插件管理均已改动路由并通过门禁，判断该限制期已过；如 ci-code 报错再评估。
