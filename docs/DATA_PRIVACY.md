> 版本：v0.1（评审候选）  
> 更新日期：2026-08-24  
> 负责人：待指定  
> 关联文档：[PRD](../PRD.md) · [架构设计](ARCHITECTURE.md) · [AI 质量与安全](AI_QUALITY_SAFETY.md)

本文定义数据用途、分类、授权、AI 召回期限、用户可见保留期限、删除传播、导出和审计基线。目标地区和正式保留期限须在上线前由安全/隐私与法务负责人批准；下表中的默认值是工程设计基线，不替代地区法律意见。

## 1. 核心原则

1. **用途限定**：为回答、学习记录、复习、记忆、日记、分析或安全分别取得必要权限，不以“一次同意”覆盖未来用途。
2. **最少数据**：模型上下文只包含完成当前任务必要的信息；日志、分析和审计不复制完整私人内容。
3. **召回与保留分离**：AI 何时不能再使用某条内容，与用户何时不能再查看历史是两套期限。
4. **事实与派生分离**：消息/作答是来源；摘要、掌握度、记忆树、Embedding 和日记是派生数据，必须保留来源和失效关系。
5. **即时禁用、异步清除**：撤销或删除后立即禁止模型、检索和插件继续使用；物理清除可异步，但有 SLA、重试和审计。
6. **用户拥有控制权**：查看、纠错、导出、锁定、忘记、删除和退出不能依赖客服或模型判断。
7. **默认私人**：学习数据、记忆和日记默认不公开、不出售、不训练；分享必须逐项发起并预览。

## 2. 数据角色与范围

- **数据主体**：个人用户；P3 机构/监护模式中仍不能把组织方等同于数据主体。
- **工作区**：所有业务数据归属一个 Workspace。个人、组织、本地和自托管工作区必须隔离；跨工作区访问默认禁止。
- **处理者/供应商**：身份、模型、对象存储、通知、分析和错误监控供应商须建立清单，记录用途、数据地区、保存策略、子处理者、删除能力和合同状态。
- **管理员**：默认不能浏览用户内容；有明确支持/安全工单、最小范围、时限、审计和必要审批时才可访问。
- **插件/外部集成**：是独立权限主体。安装不代表获得数据，必须按 scope 授权，可撤销、过期和审计。

## 3. 数据分类

| 等级 | 示例 | 默认控制 |
|---|---|---|
| Public | 用户主动发布并确认的知识网页、公开题包 | 公开前脱敏预览、来源/版本/AI 标识、撤回和缓存清理 |
| Internal | 系统配置、聚合容量指标、无用户内容的运行元数据 | 员工最小权限、变更审计 |
| Confidential | 账户、目标、会话、作答、知识点、记忆、日记、附件、模型上下文 | 传输/静态加密、工作区隔离、用途同意、导出/删除 |
| Restricted | 安全事件、健康/情绪表达、未成年人数据、设备捕获、凭据、支付/法务资料 | 默认不进入普通记忆/日记/分析；专门权限、短保留、访问审计和专项评审 |

“情绪内容”不自动等同于需要永久保存的健康信息。普通陪伴响应可在会话中发生，但安全危机原文、医疗推断和未经确认的敏感属性不得进入长期/系统记忆。

## 4. 同意与偏好

`ConsentGrant` 至少按以下 purpose 分开：

- `core_learning`：保存目标、会话、作答、错题和复习；核心功能所需。
- `model_processing`：把必要上下文发送到已披露的模型供应商；必须显示供应商类别和跨境/地区情况。
- `memory_short`、`memory_long`：短期整理与长期个性化分开控制；关闭长期记忆不能阻断基础问答。
- `daily_diary`：日记开关，并在 `contentScopes` 中分别允许学习、互动片段、情绪表达和附件摘要。
- `analytics_optional`：非必要产品分析；拒绝后核心功能可用，使用伪匿名 `subjectId`。
- `external_sync:{provider}`、`plugin:{id}:{permission}`：第三方和插件逐项授权。
- 未来的 `screen`、`microphone`、`camera`、`notifications`：逐设备、逐能力授权，不由账户条款替代系统权限。

同意记录包含政策版本、范围、授予/撤销时间、来源界面和证据。撤销只影响后续处理时，界面必须说明历史数据会保留还是删除，并提供相应操作。

<a id="privacy-retention"></a>

## 5. 召回、保留与删除基线

| 数据/层级 | AI 自动召回期限 | 用户可见/业务保留 | 删除/失效规则 |
|---|---|---|---|
| 原始会话与 MessageVersion | 当前会话及临时记忆窗口；默认最后活动后 6 小时自动进入上下文，之后需用户主动打开或按明确检索规则选取 | 默认账户存续期内可见，用户可配置历史保留；正式默认值上线前批准 | 删除后立即禁止召回；在线副本/索引/缓存 24 小时内清除，引用和派生数据重建 |
| 临时记忆 | 数小时，默认 6 小时，可按活跃会话延长 | 仅作为 AI 召回层；精确内容由来源消息承载，不另造永久副本 | TTL 到期停止自动召回并删除临时投影，不等于删除用户历史消息 |
| 短期记忆 | 默认 7～30 天滚动；再次验证可延长 | 过期后可归档为用户可见版本或删除，按产品设置和必要性批准 | 衰减/过期停止召回；删除来源后重新验证，证据不足即失效 |
| 长期记忆 | 默认无普通 TTL；受相关性、置信度、用户控制和目的限制 | 账户/工作区存续期，或用户删除/目的终止前 | 用户事实和敏感偏好需确认；纠错、撤销或证据删除后降权/失效/删除 |
| 系统记忆树投影 | 从有效长期记忆动态召回 | 可重建结构，不作为独立永久内容真源 | 来源失效后立即停止使用并重建节点/边；账户删除时清除 |
| 日记及版本 | 默认不自动作为模型事实召回；只有用户在当前任务中选择或明确确认片段时使用 | 账户存续期或用户逐篇/批量删除；历史版本可导出 | 删除日记不删除来源；删除来源会把相关段落标为不可验证并停止后续使用 |
| 附件/OCR/Embedding | 仅在用户当前任务、收藏或有效记忆授权范围内 | 原件和派生物分别显示；默认随来源保留 | 删除原件时显示派生物影响；对象、OCR、缩略图、向量和缓存 24 小时内清除 |
| 可选分析事件 | 不进入模型上下文 | 原始事件建议不超过 90 天，聚合数据不超过 13 个月；上线前审批 | 撤销后停止新事件；支持 subjectId 断联/删除；不以真实 userId 为必填 |
| 安全事件 | 只供安全处置，不进入普通教学/日记召回 | 按严重性、调查和地区规则最小化；上线前形成专项表 | 访问受限；期满清除内容，可保留去标识统计和必要审计 |
| 审计/tombstone | 不进入模型和产品推荐 | 为证明权限/删除操作保留的最小元数据；期限上线前审批 | 不含原文、Embedding 或可逆摘要；不能用来恢复被删除内容 |
| Turn/TurnStreamEvent | 仅在有效会话、同意和在线重放窗口内使用；事件正文不得成为独立记忆来源 | `MessageVersion` 是会话历史真源；MVP 正文事件默认仅保留 24 小时在线重放，最小事件元数据/tombstone 按审计期限 | 来源删除、撤权或重放窗口结束后清除事件正文；可追加不含正文的 `redacted`，不得通过事件副本恢复已删内容 |
| RecoveryControlLedger | 不进入模型、检索、分析或产品推荐 | 仅保留假名化控制引用、eventId、幂等键、sequence、时间与防篡改证据；保留期必须覆盖最老可恢复备份及审批的法定/审计期限 | 独立故障域；不是用户内容副本。到期清除/轮转前必须确保所有可恢复备份已过期或已具备等效控制覆盖 |
| 备份 | 不可在线召回 | 加密备份按已公示周期轮转；建议最长 35 天，需法务/灾备批准 | 删除内容不从旧备份单项修改；恢复时先校验并重放独立 `RecoveryControlLedger`，防止复活 |

长期记忆和系统记忆中的“永久”仅表示不按时间自然过期，不表示不可删除、不可纠正或可超出原目的使用。

## 6. 四段记忆的隐私规则

- 临时层保存精确内容是为了短期上下文连续性；不得把“精确”误解为无限期复制到日志、分析或向量库。
- 短期摘要首次压缩必须保留关键约束、时间、尝试、错误和例子；同时删除与学习无关、无后续价值的敏感细节。
- 客观学习事件（完成题目、答错知识点）可按规则自动形成长期候选；用户身份事实、经历、称呼、敏感偏好必须由用户确认；掌握度可推断但标记 `inferred` 和依据。
- 系统记忆是长期记忆的树状投影。canonical parent 构成无环层级；跨主题边单独存储并各自有证据。不能用树节点规避原始来源删除。
- 每次创建、压缩、晋升、合并、降权、纠错和删除记录算法、模型/Prompt 版本、证据范围、权限和 actor。
- 记忆被锁定只阻止自动衰减；不阻止用户删除、账户注销、安全纠错或法定清理。

## 7. 日记数据窗口

日记不能依赖“生成时仍未过期的临时记忆”，否则晚于 6 小时生成会丢失早期素材。每次生成需固化连续滚动窗口：

- `localDate`：`cutoffAt` 按用户 IANA 时区映射得到的日记日期标签，不要求窗口从本地零点开始；
- `timezoneSnapshot`：生成计划生效时的时区及 DST 规则版本；
- `previousCutoffAt`：上一条已完成或已确定跳过的日记截止点；首次运行使用 `initialWindowStart`；
- `cutoffAt`：该篇日记允许纳入素材的 UTC 截止时点；
- `sourceWindowStart/End`：`(previousCutoffAt, cutoffAt]` 的有效素材窗口；
- `contentScopes` 与 `permissionSnapshot`：生成时允许的内容类型；
- 来源 ID、来源版本和最小 tombstone；来源正文不复制到 `DiarySource`。

滚动周期素材缓冲保存来源引用和必要的结构化事实，覆盖到生成完成或 `bufferClosedAt` 补写期限；它不是第五层记忆，也不能延长原始内容的业务保留。生成后按目的删除缓冲。用户撤销日记授权后，未执行任务和缓冲立即失效。修改生成时间只改变未来截止点，已锁定截止点不移动；停用/重新启用默认以重新启用时点建立新的 `initialWindowStart`，不回填停用期间素材。系统必须以上一截止点作为下一窗口起点，避免跨午夜、DST 或计划变更造成重叠/空洞。

## 8. 删除传播

```text
用户请求删除/撤销
  -> 对 RecoveryControlLedger durable append deny/revoke event
  -> 幂等提交主事务：标记来源不可用 + 写 DeletionRequest/Outbox
  -> 同步阻断 AI 召回、搜索、插件和外部同步
  -> 异步清除/重建：摘要、短/长期记忆、树边、日记来源状态、
     错题/复习派生、FTS、Embedding、缓存、对象、通知和供应商副本
  -> 验证无召回 + 回填审计证据
  -> 备份到期；恢复时校验 ledger 水位并按序重放
```

删除 SLA：立即停止在线使用；24 小时内完成 Aervox 控制的在线存储清除/重建；外部处理者按合同 SLA，若不能满足则不得承载相应数据。失败进入队列重试和告警，用户可查看进度。删除失败不能以“后台处理中”为由继续召回。

`RecoveryControlLedger` 是删除、同意撤销及插件/外部权限撤权的 deny 控制事实源，使用独立凭据和故障域，不与业务 PostgreSQL 假装共享事务。每个控制操作以确定性 `eventId/idempotencyKey` 先追加并取得 durable ack，再写业务事务和 Outbox；若账本已写而业务事务失败，reconciler 必须按连续 `sequence` 幂等补齐业务 deny/清理状态。账本不可用、签名验证失败、sequence 缺口、账本保留未覆盖最老可恢复备份或业务应用水位未追平时，受影响用途/工作区必须 fail closed，不得确认操作完成或重新开放流量。账本只保留不可逆/假名化引用和最少证明材料，不能包含正文、Embedding 或可逆摘要。

删除单条来源不必删除独立合法事实：若高层记忆仍有其他有效证据，应重新计算并显示证据数量；若无证据，必须失效。删除日记不删除原始会话；删除原始来源则把受影响日记段落标为“来源已删除/不可验证”，并禁止用其生成长期事实。

<a id="privacy-deletion-sla"></a>

### 8.1 删除 SLA 与责任矩阵

| 下游 | 删除动作 | 目标完成时间 | 责任模块 | 验证证据 |
|---|---|---:|---|---|
| PostgreSQL 业务记录 | 标记不可用、级联删除或重建派生记录 | 立即阻断；24 小时内完成 | Domain/Data | `TC-PRIV-DEL-001`、DeletionRequest 状态 |
| Redis 缓存/BullMQ | 取消未执行 Job、清理缓存键、拒绝旧任务 | 立即阻断；1 小时内 | Worker/Platform | 队列扫描、缓存零命中 |
| TurnStreamEvent | 清除事件正文、停止重放并追加不含正文的可见性变更事件 | 立即阻断；24 小时内清除正文 | Conversation/Platform | `TC-PRIV-STREAM-001`、事件正文零读取 |
| FTS/pgvector | 删除或重建索引，更新 embedding 版本 | 24 小时内 | Retrieval/Memory | 删除后零召回测试 |
| S3 原件/OCR/缩略图/导出 | 撤销签名 URL，删除对象和派生物 | 24 小时内 | Content/Ingestion | Object inventory、checksum 清单 |
| 日记/记忆树 | 标记来源失效，重建版本、节点和边 | 24 小时内 | Diary/Memory | 来源链审计、树投影 diff |
| 模型/外部供应商 | 按合同撤回、删除或停止后续处理 | 依供应商 SLA；不得晚于披露期限 | AI/Privacy | 供应商确认、处理日志 |
| RecoveryControlLedger | 先 durable append 假名化 deny/revoke 事件；禁止正文进入账本，按 sequence 对账业务水位 | 请求确认前；持续对账 | Platform/Security/Privacy | `TC-RES-LEDGER-001`、签名/序列/水位证据 |
| 备份/灾备副本 | 不改写历史备份；轮转到期，恢复时校验最老备份覆盖、水位和 sequence 后重放 `RecoveryControlLedger` | 按已批准备份周期 | Platform/Privacy | 恢复演练、账本水位/序列证据和回放 |

每个删除任务必须有 `DeletionRequest`、`idempotencyKey`、状态（`Requested/Blocked/Running/PartiallyCompleted/Completed/Failed`）、重试次数、失败原因、Owner 和最后验证时间。`PartiallyCompleted` 或 `Failed` 状态必须触发告警和用户可见进度；在完成前已删除来源始终不可召回。SLA 变更必须通过 `CR-*` 和隐私/安全批准。

## 9. 导出、更正与迁移

导出至少包括：账户/工作区元数据、目标、会话和消息版本、题目/作答/错题/复习、知识点、四段记忆及来源/事件、记忆树节点/边、日记和版本/来源状态、附件清单、同意和外部集成。格式使用 UTF-8 JSON、CSV 和 Markdown，附件保持原格式并附 manifest/checksum。

用户可纠正消息摘要、长期记忆、知识关系、掌握度推断和日记。纠正不会伪造原始历史，而是创建版本/事件并阻断错误派生结果。服务退出或本地迁移时，导出内容不得要求专有客户端才能读取。

<a id="privacy-security"></a>

## 10. 安全控制

- Web 使用同源 HttpOnly/Secure/SameSite Cookie、CSRF、防重放、CSP 和速率限制；桌面/移动使用 OIDC Authorization Code + PKCE。
- 应用鉴权与 PostgreSQL RLS 双层限制 `(workspaceId, subjectUserId)`；管理员、组织、插件和供应商访问使用独立 `actorId` 并分别审计。
- 静态和传输加密；Restricted 内容和对象使用 KMS envelope encryption；密钥不以明文入库或进入模型。
- 模型、日志、错误监控和分析使用字段级脱敏；`ModelRun` 保存 ContextManifest，不默认复制完整 Prompt。
- 附件限制类型、大小、解压比例和扫描状态；不可信内容不能执行或提升工具权限。
- 供应商上线前完成数据处理、保留、训练、地区、删除、事件通知和子处理者评审。

<a id="privacy-gates"></a>

## 11. 隐私发布门禁

- 所有版本内数据实体有用途、分类、Owner、保留/召回/删除规则；
- 同意界面、撤销路径、历史影响和默认值通过产品/隐私评审；
- 删除 E2E 证明消息、摘要、记忆、日记、索引、缓存、对象和外部处理者均按策略处理；
- 导出在独立工具中可读取，并包含版本、来源和缺失状态；
- 分析事件使用事件专属 schema，不把 `sessionId/goalId/modelVersion` 设为全局必填；
- 跨工作区、组织、管理员、插件和分享越权测试通过；
- 备份恢复后先处于全局 deny，校验独立 `RecoveryControlLedger` 的签名、连续 sequence、最老备份覆盖和业务水位；按序幂等重放后，已删除/撤权数据不会重新可见或可召回。账本不可用、缺口或 reconciliation 未完成时不得开放流量；
- 未成年人、设备捕获、社区、市场或机构能力未完成专项评审前保持禁用。
