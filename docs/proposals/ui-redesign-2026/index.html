Design proposal · 学习域切片

静室 一张安静的书桌，和一个坐在旁边的同伴。

这不是换一套配色，而是重新决定什么该被看见。思隅是主动个人助手， 学习是首批选定的可测量验证场景，不是产品边界。本页是「静室」方案的学习域切片： 把目标、提示层级、记忆和复习放到桌面上，并用一种更克制的方式处理主动帮助。 助手形态的全貌见 「朝夕」demo。

01判断

三端各自成立，合在一起却不成立

现在的桌面、Web 和 Android 分别有一套自洽的界面，但同一个能力在三个地方长成三种样子。 对用户来说这不是"三端适配"，而是"三个产品"。下面三处摩擦，是本方案要解决的起点。

01

同一个「目标」，出现在三个位置

桌面放在左栏卡片，Web 放在右栏侧卡，手机藏在设置里。用户换端之后要重新找一遍。

后果：跨端连续性断在导航上，而这恰好是"连续帮助"承诺的前提。
02

学习闭环被压缩成一次问答

分层提示、错题、复习队列是产品的差异化能力，但界面上只有一个输入框。卡住时用户能做的只有"再问一遍"。

后果：核心机制不可见，用户无法预期"再给一层提示"会发生什么。
03

主动帮助退化成 3 秒 toast

产品承诺"可解释、可暂停、可撤销"，而主动建议以浮层出现、自动消失，既不解释触发原因，也没有地方回看。

后果：打扰大于帮助，用户学会了一律忽略。

界面不该要求用户先学会产品，
也不该把最重要的能力藏进输入框。

02概念

静室：把界面做成一张书桌，而不是一个聊天窗

"思隅"本意是思维的一角。方案把这个名字变成空间隐喻：一张冷灰纸面的书桌，一个安静的同伴坐在旁边， 帮助以纸条的形式递过来，而不是弹出来。四条规则决定了后面所有的取舍。

书页，而不是气泡

对话按阅读顺序排版：时间码退到页边，代码与卡片作为"插图"嵌入正文，而不是缩成一条气泡。

原因：学习内容要回看。气泡流适合短句闲聊，不适合需要重读的解释与代码。

页边，而不是弹窗

主动帮助以"纸条"出现在内容页边：不遮挡正文、不抢焦点、不自动消失，直到你处理或明确说"晚点"。

原因：3 秒浮层无法承载"为什么现在说这句话"。纸条可以停留、可以回溯。

层级，而不是答案

任何"卡住"的地方都给 1→2→3 层提示：观察、条件、结构。第三层之后才出现"看解法"，且被如实记录。

原因：直接给答案会让"掌握度"失真，也会让用户失去一次自己想通的机会。

本机，而不是云端

数据默认只存在这台设备上。界面用"已备份 / 已同步"这类可验证的说法，不使用"云端已保存"。

原因：本地 SQLite 是真源。文案不该暗示一个并不存在的服务端账户。

03结构

五个空间，三种到达顺序

导航不再按"页面"切分，而按用户此刻的意图切分：我在被陪着（此刻）、我在解决一件事（对话）、 我留下了什么（台面）、它记住了什么（记忆）、我能扩展什么（广场）。三端共用这五个空间，只是到达顺序不同。

空间回答的问题桌面Web手机
此刻现在该做什么左栏（角色 + 今日）顶栏胶囊 → 抽屉首屏主视图
对话这件事怎么解决右侧主区中列主视图底部面板（可展开）
台面留下了什么工作台模式一级标签二级页（从对话进入）
记忆它记住了什么侧栏抽屉一级标签设置 → 记忆
广场还能扩展什么侧栏入口侧栏入口设置 → 插件

到达顺序

桌面 此刻→对话→台面→记忆→广场 角色常驻，对话是默认焦点
Web 对话→台面→记忆→此刻→广场 坐下就为完成一件事，先给正文
手机 此刻→对话→台面→记忆→广场 一屏之内先看见"现在做什么"

排列原则

桌面是"陪伴优先"：角色常驻、工作台可选，因为桌面端最长的会话往往发生在旁边有人的时候。 Web 是"工作台优先"：三栏并列、陪伴退为浮层，因为浏览器里的用户通常是坐下来完成一件具体的事。 手机是"此刻优先"：角色占据上半屏，对话叠在下半身，任何时刻都能单手回到输入。

04视觉

一套冷灰纸面，一种钴蓝，两枚状态色

沿用 AVX-DS-001 的色域与禁止项，不引入第二种主色。新增的两枚语义色只表达学习状态， 不参与装饰；层级靠字号、字重与留白建立，而不是靠更多颜色。

颜色

点击色块可复制色值。两枚状态色饱和度均低于 45%，只用于状态点、标签与进度，不用于按钮或大面积背景。

衬线只用在两处：章节标题与角色台词。它们是"人"的部分。所有操作性文字保持系统无衬线， 避免把中文衬线用于小字号（在 Windows 上回退不可控）。等宽只用于时间、路径、代码与计数。

05交互

三条规则决定界面是否可信

视觉决定第一眼，交互决定第三天还用不用。以下三条是本方案里最需要被实现约束的部分， 也是 demo 中可以直接操作验证的部分。

分层提示HINT LEVELS
LEVEL 01观察把问题变成可观察的一步，不出现代码。
LEVEL 02条件指出关键判断或边界，仍不给完整结构。
LEVEL 03结构给出结构与顺序，把最后一步留给用户。
  • 每层之间至少间隔一次用户输入，不允许连点三层。按钮在请求中显示"正在想…"并禁用。
  • 第三层之后按钮变为"看解法"，且这是一个显式动作：点击后记录为「直接看解法」，不计入掌握度。
  • 提示内容不重复用户已经说过的信息；每层最多 2 句，超出部分折叠为"展开更多"。
纸条 · 主动帮助PROACTIVE SLIP
  • 触发：同一处停留 ≥10 分钟、复习到期、连续天数即将中断。三条互斥，不同时出现。
  • 位置：内容页边，最多 3 张；始终不覆盖正文与输入区，窄屏时收进"纸条 (2)"按钮。
  • 动作：接受（写入台面 / 开始复习）、晚点（冷却 30 分钟）、不用（当日同类不再出现）。
  • 消失：只有用户操作才会消失。状态变化后原位替换为一行结果，不弹 toast 二次确认。
  • 可解释：每张纸条都带触发原因（"这里卡了 12 分钟"），不接受无理由的主动建议。
这里卡了 12 分钟

要不要把刚才那句「n == 0 那行」加进递归笔记？下次会先想起来。

这是真实组件：左侧 2px 强调色边界，2px→12px 的圆角过渡，悬停时轻微抬起。它不会自己消失。

工具审批APPROVAL
  • 范围写清：路径、条数、读或写。例如"读取 错题/递归*.md（4 条），仅读取"。
  • 三档授权：允许一次 / 本次会话 / 拒绝。默认焦点在"允许一次"，危险操作默认在"拒绝"。
  • 结果留痕：审批完成后卡片原地变成一行结果，并写入「记忆」，可撤销。
  • 拒绝不解释、不追问、不重复请求；下一次需要时重新提问。

三态与键盘

列表为空、加载中、读取失败必须可区分：加载中显示骨架（≥300ms 才出现，避免闪烁）， 失败显示原因与重试，只有"成功且确实没有数据"才显示空态。空态由图标、标题、一行说明和一个主动作组成， 不接受只有一行灰字。

键盘：⌘K 命令面板，Enter 发送、⇧Enter 换行， Esc 关闭最上层。所有图标按钮提供 26px（桌面）/ 44–48px（移动）命中区与 :focus-visible 外环；输入框的焦点反馈由容器承担，textarea 自身不画轮廓。

06三端

同一套语言，三种坐姿

三个 demo 都是可交互的：切换明暗、发送消息、逐层要提示、处理纸条与审批、在 Web 端切换标签与命令面板、 在手机端展开对话框与打开设置。建议按下面的顺序看。

01 / DESKTOP→

陪伴为主

角色、今日目标、待复习与书页式对话同屏。工作台模式可切换，角色收起为头像。

  • 左栏：角色 + 今日 + 本周节奏
  • 右页边：纸条与审批
  • 底部：多行输入与模式开关
 02 / WEB→

工作台为主

三栏：会话、正文、上下文。台面与记忆升为一级标签，命令面板覆盖全部动作。

  • 中列：对话 / 台面 / 记忆
  • 右栏：目标、记忆命中、复习
  • ⌘K：搜索与命令
 03 / MOBILE→

此刻为主

上半屏是角色与一句话，下半屏是可展开的对话面板；设置是全屏容器，分组条目固定。

  • 底部面板：52% ↔ 88%
  • 全屏设置：分类 + 单列表单
  • 48dp 触控与 M3 形状

08边界

这次只到"可评审"，不到"可发布"

本提案不修改任何现有界面代码，也不代表任何能力已经交付。它提供的是一个可以被讨论、 被拆成实现任务的设计基线。以下三件事需要先定，否则实现会走两次。

「台面」是否升为一级导航

升为一级会让学习产出更可见，但也会让手机端多一个主入口。当前 demo 在 Web 升为标签、手机降为二级页，属于折中。

待定

纸条的每日上限

方案先取 3 张/天、冷却 30 分钟。上限过低会失去"主动"，过高会重新变成噪音，需要真实使用数据。

待定

「直接看解法」是否计入掌握度

不计入更诚实，但会让进度显得慢。建议先不计入，并在复习队列中提高该知识点的优先级。

待定

与现有规范的关系

色域、单主色、动效曲线、圆角阶梯与禁止项均沿用 AVX-DS-001；本方案新增"书页式排版"、 "纸条"与两枚语义色，若采纳需要在 docs/reference/DESIGN.md 增补一节， 而不是在组件里各自定义。Android 仍使用 Material 3 的角色与组件，本方案的品牌层只影响颜色与文案。

如何验证这个方案

一次 5 人可用性测试，三个任务：① 从"看不懂递归"到拿到第 2 层提示，步数 ≤2； ② 说出当前目标和今天要复习的内容；③ 在纸条出现后判断它为什么出现。 记录完成率、步数与"是否忽略纸条"。如果超过一半的人忽略纸条，说明主动帮助的时机错了，而不是样式错了。
