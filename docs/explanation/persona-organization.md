本文回答 Aervox 桌宠 IP（CAP-019）的「角色是谁、长什么样、话怎么说、边界在哪」为何以及如何被文档化、版本化并交由产品负责人维护。它不写具体某一套人设的完整文案，只讲组织方式、字段结构与维护责任；具体契约字段以代码侧 schema 与 AI 质量规范为准。

## 一句话模型

Aervox 的桌宠角色是一等公民资产：每个角色由一份独立文档定义（核心概念、外形、提示词边界、识别边界），再按统一的 personality 字段结构沉淀为模板；多人格模板按人设目录组织、逐页版本化，由产品负责人统一维护，避免角色设定散落、写死或随代码漂移。

## 目标与范围

### 为什么角色设定不能写死在代码里

如果把角色提示词、外形、语气直接硬编码在 API 模块或前端组件中，会带来四类问题：

1. **不可见**：角色内容混在业务逻辑里，审查人设、校验安全边界时无从下手，Prompt 变更也无从追溯。
2. **难版本化**：代码分支承载文案修改，无法独立走评审、回滚和发布节奏；一旦模型升级或某套人设需要下线，只能通过改代码完成。
3. **难以复用**：CAP-019 要求多人格模板可切换，写死的角色无法按文件夹、按模板复用，也无法在人格间显式共享或隔离记忆。
4. **责任悬空**：角色是产品资产而非工程细节，写死等于没有所有者，术语、语气、安全边界缺乏统一把关。

因此把角色设定独立成受控文档，是伴学桌宠 IP 可持续演进的前提。

### 范围

本文覆盖角色文档的目录归属、内容清单、字段化结构与维护流程。运行时解析、多人格切换、记忆隔离的落地规则随 CAP-019 立项（参考 [参考项目能力迁移与借鉴评估 §4.6](reference-design-transfer.md#46-ast-03-人设字段化与解析链)）；AI 生成内容的正确性与安全门槛见 [AI 质量与安全规范](../reference/AI_QUALITY_SAFETY.md)。

## 角色设定文档清单

参考 BaiShou-Next 将桌宠人设独立成文档的做法（`Latte/角色設定.md` 与多语言 profile），每个 Aervox 角色文档固定包含四个部分：

| 部分 | 回答的问题 | 归属与校验 |
|---|---|---|
| 核心概念 | 这个人格是谁、目标与陪伴定位 | 产品负责人定义，评审后冻结 |
| 外形 | 长什么样、形象与视觉设定 | 设计负责人配合，不得进入运行时逻辑 |
| 提示词边界 | 话怎么说、风格与语气、可回应范围 | 产品 + AI 质量负责人联合评审 |
| 识别边界 | 哪些话题该回应、哪些必须回避或转介 | 安全/AI 质量负责人把关，对接安全边界 |

角色文档放在 `docs/explanation/` 之下的人设目录，与代码、前端资产分离；外形资产（图片/模型）的管线在桌面端阶段另行评估（[参考项目能力迁移与借鉴评估 §4.10](reference-design-transfer.md#410-pet-04-表现驱动数据对象与视图接口分离)）。

## 字段化结构

参考 AST-03 的 `Personality` 字段化模型（prompt、开场白、语气模仿对话、工具、技能、错误兜底语），每个 Aervox 角色模板统一为以下字段，缺省由默认模板兜底：

| 字段 | 含义 | 说明 |
|---|---|---|
| prompt | 系统提示词 | 人格的根定义，评审后冻结，变更走版本化 |
| 开场白 | 首见与每日开启的预设对话 | 成对的出现/回应序列，保证偶数条 |
| 语气 | 风格与口吻样例 | 供运行时模仿，不下硬编码语气判断 |
| 技能 | 该人格可用的工具/能力开关 | 与人格切换一致，受共享安全边界约束 |
| 错误兜底语 | 失败或超范围时的固定回话 | 避免模型自由发挥，保证失败如实转述 |

字段与解析链的完整定义、默认兜底语义随 CAP-019 立项时落地（[参考项目能力迁移与借鉴评估 §4.6](reference-design-transfer.md#46-ast-03-人设字段化与解析链)）。

## 多人格模板组织

CAP-019 要求「提供经过审核的教学/陪伴人格，可切换但共享安全边界；人格记忆相互隔离或显式共享」。对应到文档组织：

- **按人设目录组织**：每个模板独立成目录，内含一份 `README.md` 索引 + 上述四部分文档。持久化的人设数据（供产品浏览、校验）作为契约字段随立项定义，与文档双写；文档是事实源，代码 schema 是对照。
- **模板版本化**：每个模板目录带版本与更新日期；对外切换以模板版本为标识，释放旧版本仅作追溯保留，不走静默覆盖。跨人格记忆默认隔离，显式共享前展示范围并取得确认（对齐 [PRD 能力验收 CAP-019](../reference/PRD.md)）。
- **共享安全边界**：所有模板共用同一套安全、事实判断、权限与学习数据规则，人格只影响表达、外观与互动节奏。

## 维护责任

- **产品负责人**：唯一负责角色设定内容（核心概念、外形、提示词边界、识别边界）的评审与发布；人设文档的「责任角色」即产品负责人。
- **AI 质量负责人**：对提示词边界、错误兜底语与 AI 输出质量联动评审（见 [AI 质量与安全规范](../reference/AI_QUALITY_SAFETY.md)）。
- **安全/隐私负责人**：对识别边界、回避/转介话题与未成年人保护把关。
- **设计负责人**：对成形外形与视觉一致性负责。

版本化流程：新增/修改已冻结角色文档需建立 `CR-*` 并登记[生命周期登记表](../DOC_REGISTRY.md)；每次改版更新模板版本、日期与变更摘要，不得只改正文（遵循 [文档写作规范 §5 更新与评审节奏](../README.md#5-更新与评审节奏)）。
