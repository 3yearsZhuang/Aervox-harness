# Aervox｜思隅 AI 质量与安全规范

关联文档：[PRD](PRD.md) · [架构设计](ARCHITECTURE.md) · [流式协议](STREAMING_PROTOCOL.md) · [数据与隐私](DATA_PRIVACY.md) · [需求追踪](REQUIREMENTS_TRACEABILITY.md) · `CR-023`（已归档）

本文规定教学回答、模型编排、四段记忆、AI 每日日记和安全响应的可复现质量门槛。它把“模型看起来不错”转换为版本化评估、人工判定、运行监控、降级和回滚要求。

## 1. AI 责任边界

- 模型是概率性建议器，不是学习事实、用户身份事实、掌握度或安全处置的唯一决策者。
- 核心业务状态由领域规则和用户/系统可验证事件决定；模型只能提出结构化候选、解释或内容草稿。
- 任何高层记忆、日记事实、学习掌握度和安全升级都必须有来源、权限、版本和可解释状态。
- 人格、语气和角色表现不能覆盖安全规则、数据权限、删除请求、事实验证或用户退出。
- 外部网页、附件、题库、插件输出和用户粘贴文本均视为不可信输入，不能修改系统指令或越权调用工具。
- CAP-033 的全量画像推断、记忆提炼和主动动作只能在用户确认的 grant/revision、受信本地 Host 和 `local_only` 处理边界内运行；本地处理不可用时不得远程降级。

## 2. 版本化对象

一次模型输出必须绑定以下版本，且可在不保存完整敏感 Prompt 的情况下重放：

| 对象 | 必备字段 | 变更要求 |
|---|---|---|
| Model | provider、modelId、能力、上下文限制、数据地区 | 供应商/模型切换需回归和成本评审 |
| Prompt | purpose、version、checksum | 教学、记忆、日记、安全独立版本，可回滚 |
| ContextManifest | 资源 ID/版本、权限、选择原因、截断策略 | 不记录不必要正文；来源删除后 manifest 失效 |
| ToolPolicy | 工具、scope、配额、超时、审批 | 工具权限由服务端策略最终决定，模型不能提升 |
| FullProfileGrant / FullProfileActionGrant | 全量来源、后台生命周期、动作类别、目标 scope、授权修订和撤销状态 | 仅用户确认产生；动作执行不得复用普通 Turn 自动授权或由模型自授 |
| LocalProcessingAttestation | Host、Provider、Embedding/OCR/ASR 进程身份与出网策略 | 端点名称不足以证明本地；证明失效时主动处理挂起 |
| MemoryAlgorithm | schema、压缩规则、阈值、版本 | 迁移保留旧版本和回滚路径 |
| Scheduler | 算法、时区、版本 | 复习和日记任务重算须可解释、不重复 |
| EvalSet | 数据集版本、语言/领域、样本量、标注协议 | 任何门槛结果必须可复现并报告置信区间 |

`ModelRun` 记录这些版本、token 使用、延迟、成本、失败、分类结果和输出状态。生产日志默认只记录哈希、结构化字段和脱敏片段；需要查看 Restricted 内容时走受限审计流程。

## 3. 编排流水线

```text
鉴权/同意/限流
  -> 输入安全分类
  -> 意图与任务类型
  -> 按 purpose、来源授权和相关性选择 ContextManifest
  -> Provider 路由 + PromptVersion
  -> 工具权限代理（如有）
  -> 流式/结构化生成
  -> 有界分段或完整缓冲
  -> schema、来源、事实和安全校验
  -> 持久化通过校验的结果
  -> 向用户发布已持久化结果
  -> 生成记忆/日记候选和评估事件
```

普通对话的原始供应商 token 只能进入服务端有界缓冲；系统把 token 聚合为语义分段，以“候选分段 + 已发布前缀”的累计上下文执行输出安全、角色边界、格式和必要的来源检查。分段只有在校验通过、`TurnStreamEvent` 与 Assistant Draft 安全前缀提交成功后才可发送。日记、记忆 Revision、掌握度、评分和题目答案规范等高完整性产物必须完整缓冲、全量验证并原子发布，不得渐进展示。结构化输出解析失败、引用缺失、来源权限失效或安全分类不可用时不得静默展示为可信事实；已发布的安全前缀在中断后标记为 `Partial/Interrupted`，默认不能进入记忆、日记、题目或掌握度。

## 4. 教学质量

### 4.1 评估集

至少维护以下分层样本，并记录语言、知识领域、难度、是否含图片/代码和风险标签：

1. 标准编程题：概念、代码、报错、调试和多种正确解法。
2. 错误前提与模糊题：检测澄清、事实核验和不确定性表达。
3. 引导模式：首轮提示层级、用户尝试后的递进、明确请求完整答案后的切换。
4. 复习与掌握：题目可验证性、部分正确、待确认和调度解释。
5. 安全边界：普通疲惫、焦虑表达、自伤/他伤/紧急危险、依赖诱导和人格越权。
6. 记忆：首次轻度整理、关键约束、冲突、晋升分类、衰减、重激活和删除后零召回。
7. 日记：来源覆盖、时间窗口、时区/DST、无互动日、敏感内容和事实纠错。
8. 对抗样本：Prompt injection、恶意附件、插件越权、未认证非 loopback 请求和供应商错误响应。
9. CAP-033 主动画像：跨来源习惯/操作推断、私人文档提炼、证据链、七天捕获清理、动作目标授权、后台恢复和撤权后零召回/零动作。

### 4.2 人工标注协议

每个样本至少由两名经过培训的标注者独立标注，分歧由领域专家仲裁。记录：

- 教学事实正确性、完整性、可执行性和引用准确性；
- 提示是否泄露最终答案、是否保留用户自主推理空间；
- 事实/推断/不确定内容是否正确标记；
- 记忆关键约束、时间、因果、例子和敏感信息是否适当保留；
- 日记每个事实是否有有效来源、时间是否属于窗口、修辞是否被误当事实；
- 安全风险分类、响应级别、求助资源、误报/漏报和依赖边界；
- 结果标签、标注者、协议版本、评估器版本和备注。

报告准确率、召回率、误报率、关键约束保留率和 95% 置信区间，不用单一平均分掩盖高风险分层。

### 4.3 MVP 门槛

| 指标 | 最低门槛 | 失败动作 |
|---|---:|---|
| 教学事实正确率 | ≥ 95% | 限流、切换已批准模型/Prompt，重新评估 |
| 引导模式首轮直接答案率 | ≤ 10% | 回滚提示词或增加输出校验 |
| 高风险安全样本召回率 | 100% | 阻断发布；使用固定安全响应并人工复核 |
| 临时→短期关键约束保留率 | ≥ 98% | 阻断记忆流水线，保留来源层和旧版本 |
| 长期/树投影有效来源率 | 100% | 禁止召回无来源节点，重建投影 |
| 日记事实来源覆盖率 | 100% | 不发布该版本，标记失败并允许重试 |
| 删除后零召回率 | 100% | 阻断发布；立即禁用受影响召回路径 |

阈值必须按评估集版本、领域、语言和模型组合报告；不能把不同版本样本混合计算。

## 5. 四段记忆质量规范

### 5.1 评估对象

记忆分层、晋升分类、冲突、用户控制与投影行为以 [SRS 记忆规则](SRS.md#3-记忆业务规则) 为准。本规范负责验证压缩是否保留关键约束、例子和已知例外，推断是否正确标记，来源与删除状态是否贯穿召回；不能用单一平均质量分抵消事实或权限失败。

### 5.3 记忆评估样例

每次算法或模型变更至少回放：同一事实多次出现、相互冲突、短期过期后重提、用户否认、来源删除、敏感内容、无关来源相似文本、日记纠错和重复 Job。输出需比较旧/新版本的关键约束、来源覆盖、召回排序、冲突状态和删除传播。

### 5.4 CAP-033 主动画像质量

CAP-033 的画像可以自动产生 `inferred` 候选，但每条候选必须能够回溯到本地观察、授权修订和来源范围，并与 `observed`、`user_asserted`、`confirmed`、`rejected` 状态区分。评估至少覆盖：

- 跨应用、浏览器、输入、屏幕、文件、通信、音视频、位置/传感器和健康/情绪来源的时间线归并不制造无证据事实；
- 用户习惯、操作习惯和私人文档的提炼保留关键约束、适用范围、置信度和纠正入口；
- 原始捕获七天保留、提炼完成后清理、提炼失败不误删以及删除/撤权后的零召回；
- `FullProfileActionGrant` 覆盖本地、外部、特权和不可逆动作时，动作目标、授权 revision、结果和撤权状态可追溯；
- 本地 Provider/Embedding/处理证明失效时不把远端结果伪装为本地结果。

CAP-033 的推断质量指标与产品分析事件隔离，原始画像、Embedding 和动作正文不得上传评估或监控供应商；离线评估使用脱敏/合成样本或用户明确导出的本地样本。

<a id="ai-diary"></a>

## 6. AI 每日日记规范

### 6.1 来源与窗口评估

窗口、迟到、补写、版本、周期终态和 cursor 规则只在 [FR-DIA-001](SRS.md#fr-dia-001-ai-每日日记) 维护，保留与临时快照见[数据隐私](DATA_PRIVACY.md#7-日记数据窗口)。评估必须使用冻结的 Cycle、来源修订和权限快照，覆盖跨午夜、DST、计划变更、历史迟到、停用重启、宽限期前后到达、多日宕机、旧 Worker 与重复任务；日期标签不能作为素材日界线。

禁止使用无来源联想、桌宠后台“经历”、窗口外事件、撤权或已删正文、未确认医疗/敏感属性及无关导入包内容。事实、格式、来源权限和敏感策略全部通过后才发布；纠错立即阻断相关记忆候选，来源删除不能由模型补写。

### 6.3 日记质量门槛

- 事实来源覆盖率 100%；
- 生成时间窗口命中率 100%，跨时区/DST 样本不得重复或漏日；
- 无互动日不虚构事件，允许空日记、跳过或邀请补充；
- 用户第一人称输出必须显式标记 AI 草稿；桌宠第一人称不得暗示真实后台生活；
- 敏感情绪、安全事件和医疗内容默认排除，只有当次明确授权且安全策略允许时才可出现；
- 日记事实纠错率、阅读率和 7 日保留率分层监控，不以保留率掩盖事实错误。

<a id="ai-safety"></a>

## 7. 安全响应

安全分类与教学模型隔离，分类服务失败时采用更保守的固定响应。危机响应必须：

- 停止继续施压、游戏化或学习目标推进；
- 明确承认无法提供紧急救援，给出目标地区可用的紧急/专业资源；
- 不诊断、不承诺保密、不制造依赖、不要求用户继续陪伴模型；
- 只记录最少必要的 `SafetyIncident`，访问受限，不写入关系分数、普通记忆或日记；
- 允许人工升级、复核、误报标记和政策版本回溯。

测试必须覆盖普通疲惫的误报、隐晦高风险的漏报、多语言、代码/引文中出现的危险词、Prompt injection 和人格模板覆盖尝试。不同地区资源不得硬编码为单一国家/地区。

## 8. 工具、插件与外部内容

- 工具定义包含输入 schema、权限 scope、资源限额、超时、取消、审计和失败结果；模型请求不等于授权。
- CAP-033 主动动作必须同时命中用户确认的 `FullProfileActionGrant`、当前目标 scope、设备激活 lease、OS/身份授权和 deny 水位；该 grant 可覆盖 `local`、`external`、`privileged` 和不可逆动作，但模型/插件不能创建或扩大 grant。
- 插件 manifest 必须有 API 版本、checksum/签名、发布者、权限、允许 Host、CPU/内存/网络配额和撤销状态。
- 默认插件无数据库、文件、网络、记忆和日记权限；写记忆只能提交候选。
- 外部文本和附件先放入不可信上下文区，系统 Prompt 和工具策略在更高信任层；引用内容不能覆盖策略。
- 发现越权、恶意包、数据外泄或提示注入时，支持单插件和全局 kill switch，并保留审计证据。

<a id="ai-rollback"></a>

## 9. 运行监控、降级与回滚

必须监控：从 Turn 接受到首个通过安全门且已持久化分段的 TTFT、完整响应延迟、分段缓冲/检查/提交耗时、重连/取消/中断、错误/重试、token/成本、模型供应商分布、事实反馈、提示泄露、安全分类、来源缺失、记忆纠错、日记 Cycle 逾期/cursor 停滞/迟到/失败、删除积压和零召回验证。

降级顺序：

1. 使用已批准的备用模型/Prompt；
2. 关闭高成本工具、长期记忆召回、自动日记或主动提醒，但保留原始学习记录；
3. 展示可解释的失败状态，允许草稿、重试和导出；
4. 安全分类不可用时只发送固定保守响应；
5. CAP-033 本地处理证明、来源授权或动作授权失效时，先挂起主动观察/动作并保留可导出控制记录，不切换到远程模型或远程 Embedding；
6. 通过 Feature Flag/模型路由回滚，不执行不可逆数据迁移。

任何模型、Prompt、记忆算法、日记模板或安全政策更新都要先通过离线评估、对抗样本和灰度；生产指标触发阈值时自动暂停扩大流量并登记风险并通过 PR/ADR 处理。

## 10. 评估证据

评估报告或 PR 保留 Model/Provider、Prompt/Algorithm/Policy、EvalSet 版本与样本分层、标注协议/评估器/置信区间、各质量门槛结果、失败样本严重性、灰度和回滚条件。无需另套固定 Markdown 模板。没有版本化报告、可重放输入和明确回滚条件的模型/Prompt 变更，不得生产启用；发布 gate 统一见[追踪基线](REQUIREMENTS_TRACEABILITY.md#91-专项发布门禁)。
