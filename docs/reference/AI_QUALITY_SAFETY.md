本文规定教学回答、模型编排、四段记忆、AI 每日日记和安全响应的可复现质量门槛。它把“模型看起来不错”转换为版本化评估、人工判定、运行监控、降级和回滚要求。

## 1. AI 责任边界

- 模型是概率性建议器，不是学习事实、用户身份事实、掌握度或安全处置的唯一决策者。
- 核心业务状态由领域规则和用户/系统可验证事件决定；模型只能提出结构化候选、解释或内容草稿。
- 任何高层记忆、日记事实、学习掌握度和安全升级都必须有来源、权限、版本和可解释状态。
- 人格、语气和角色表现不能覆盖安全规则、数据权限、删除请求、事实验证或用户退出。
- 外部网页、附件、题库、插件输出和用户粘贴文本均视为不可信输入，不能修改系统指令或越权调用工具。

## 2. 版本化对象

一次模型输出必须绑定以下版本，且可在不保存完整敏感 Prompt 的情况下重放：

| 对象 | 必备字段 | 变更要求 |
|---|---|---|
| Model | provider、modelId、能力、上下文限制、数据地区 | 供应商/模型切换需回归和成本评审 |
| Prompt | purpose、version、checksum | 教学、记忆、日记、安全独立版本，可回滚 |
| ContextManifest | 资源 ID/版本、权限、选择原因、截断策略 | 不记录不必要正文；来源删除后 manifest 失效 |
| ToolPolicy | 工具、scope、配额、超时、审批 | 工具权限由服务端策略最终决定，模型不能提升 |
| MemoryAlgorithm | schema、压缩规则、阈值、版本 | 迁移保留旧版本和回滚路径 |
| Scheduler | 算法、时区、版本 | 复习和日记任务重算须可解释、不重复 |
| EvalSet | 数据集版本、语言/领域、样本量、标注协议 | 任何门槛结果必须可复现并报告置信区间 |

`ModelRun` 记录这些版本、token 使用、延迟、成本、失败、分类结果和输出状态。生产日志默认只记录哈希、结构化字段和脱敏片段；需要查看 Restricted 内容时走受限审计流程。

## 3. 编排流水线

```text
鉴权/同意/限流
  -> 输入安全分类
  -> 意图与任务类型
  -> 按工作区和 purpose 选择 ContextManifest
  -> Provider 路由 + PromptVersion
  -> 工具权限代理（如有）
  -> 流式/结构化生成
  -> 有界分段或完整缓冲
  -> schema、来源、事实和安全校验
  -> 持久化通过校验的结果
  -> 向用户发布已持久化结果
  -> 生成记忆/日记候选和评估事件
```

普通对话的原始供应商 token 只能进入服务端有界缓冲；系统把 token 聚合为语义分段，以“候选分段 + 已发布前缀”的累计上下文执行输出安全、角色边界、格式和必要的来源检查。分段只有在校验通过、`TurnStreamEvent` 与 Assistant Draft 安全前缀提交成功后才可发送。日记、记忆 Revision、掌握度、评分和题目答案规范等高完整性产物必须完整缓冲、全量验证并原子发布，不得渐进展示。结构化输出解析失败、引用缺失、来源权限失效或安全分类不可用时不得静默展示为可信事实；已发布的安全前缀在中断后标记为 `Partial/Interrupted`，默认不能进入记忆、日记、题目或掌握度。

## 4. 教学质量

### 4.1 评估集

至少维护以下分层样本，并记录语言、知识领域、难度、是否含图片/代码和风险标签：

1. 标准编程题：概念、代码、报错、调试和多种正确解法。
2. 错误前提与模糊题：检测澄清、事实核验和不确定性表达。
3. 引导模式：首轮提示层级、用户尝试后的递进、明确请求完整答案后的切换。
4. 复习与掌握：题目可验证性、部分正确、待确认和调度解释。
5. 安全边界：普通疲惫、焦虑表达、自伤/他伤/紧急危险、依赖诱导和人格越权。
6. 记忆：首次轻度整理、关键约束、冲突、晋升分类、衰减、重激活和删除后零召回。
7. 日记：来源覆盖、时间窗口、时区/DST、无互动日、敏感内容和事实纠错。
8. 对抗样本：Prompt injection、恶意附件、插件越权、跨工作区请求和供应商错误响应。

### 4.2 人工标注协议

每个样本至少由两名经过培训的标注者独立标注，分歧由领域专家仲裁。记录：

- 教学事实正确性、完整性、可执行性和引用准确性；
- 提示是否泄露最终答案、是否保留用户自主推理空间；
- 事实/推断/不确定内容是否正确标记；
- 记忆关键约束、时间、因果、例子和敏感信息是否适当保留；
- 日记每个事实是否有有效来源、时间是否属于窗口、修辞是否被误当事实；
- 安全风险分类、响应级别、求助资源、误报/漏报和依赖边界；
- 结果标签、标注者、协议版本、评估器版本和备注。

报告准确率、召回率、误报率、关键约束保留率和 95% 置信区间，不用单一平均分掩盖高风险分层。

### 4.3 MVP 门槛

| 指标 | 最低门槛 | 失败动作 |
|---|---:|---|
| 教学事实正确率 | ≥ 95% | 限流、切换已批准模型/Prompt，重新评估 |
| 引导模式首轮直接答案率 | ≤ 10% | 回滚提示词或增加输出校验 |
| 高风险安全样本召回率 | 100% | 阻断发布；使用固定安全响应并人工复核 |
| 临时→短期关键约束保留率 | ≥ 98% | 阻断记忆流水线，保留来源层和旧版本 |
| 长期/树投影有效来源率 | 100% | 禁止召回无来源节点，重建投影 |
| 日记事实来源覆盖率 | 100% | 不发布该版本，标记失败并允许重试 |
| 删除后零召回率 | 100% | 阻断发布；立即禁用受影响召回路径 |

阈值必须按评估集版本、领域、语言和模型组合报告；不能把不同版本样本混合计算。

## 5. 四段记忆质量规范

### 5.1 状态和分类

```text
Captured
  -> ShortCandidate
  -> ValidatedShort
  -> LongCandidate
  -> ActiveLong
  -> TreeProjection
  -> Decayed / Invalidated / Deleted
```

`MemoryRecord` 至少区分 `user_fact`、`user_preference`、`learning_event` 和 `inference`，以及敏感等级和 `verificationStatus`：

- `user_fact` / `user_preference`：用户明确说出的事实、偏好或经历；长期晋升需明确确认。
- `learning_event`：题目、作答、判定、复习完成、目标变更等可验证事件；来源完整、无冲突、达到规则阈值后可自动沉淀。
- `inference`：模型推测的意图、人格、情绪、能力或关系；只能作为带标签候选，不得展示或写入系统树为事实，除非用户确认或证据规则重新批准。

### 5.2 压缩和遗忘检查

- 临时→短期只允许一次轻度整理；schema 强制包含时间、主体、目标/约束、尝试、错误、因果和代表性例子。
- 短期→长期才进行明显抽象，保留结论、适用范围、证据摘要和已知例外；不能把所有失败尝试抹成“用户不会”。
- 长期→系统只生成可重建节点/边；canonical parent 无环，跨主题关系独立存储并继承证据权限。
- 评分可以影响细节预算、召回和衰减，但不能由模型单独决定晋升或删除。
- 合并、纠错、冲突和降权生成新 Revision/Event；旧版本只标记 superseded/invalidated，不抹掉审计链。
- 用户删除/撤销后立即从 ContextManifest、FTS、Embedding、缓存、日记和插件查询中排除；异步清理完成后验证零召回。

### 5.3 记忆评估样例

每次算法或模型变更至少回放：同一事实多次出现、相互冲突、短期过期后重提、用户否认、来源删除、敏感内容、跨工作区相似文本、日记纠错和重复 Job。输出需比较旧/新版本的关键约束、来源覆盖、召回排序、冲突状态和删除传播。

## 6. AI 每日日记规范

### 6.1 输入窗口

每次自动生成必须先声明不可变 `DiaryCycle`，并绑定当时的 `DiaryScheduleRevision`；窗口真源是 Cycle，而不是 `Diary.localDate`、执行尝试或当前计划。Cycle 必须记录 `workspaceId`、`subjectUserId`、`localDate`、`previousCutoffAt`、`initialWindowStart`、`cutoffAt`、`timezoneSnapshot`、`sourceWindowStart/End`、`permissionSnapshot` 和 `bufferClosedAt`。常规窗口为 `(previousCutoffAt, cutoffAt]`；首次运行从 `[initialWindowStart, cutoffAt]` 开始，其中 `initialWindowStart` 默认是日记授权和启用设置成功持久化的时点。`localDate` 只是截止点的本地日期标签，不是素材日界线；停用期间和首次启用前的内容不自动回填。滚动周期素材缓冲只服务该 Cycle，不延长普通 AI 召回，也不被其他对话检索。

所有候选来源必须同时记录 `occurredAt`（业务事件发生时间）和 `ingestedAt`（系统持久化时间）。周期归属只由 `occurredAt` 决定，迟到和补写资格再由 `ingestedAt` 决定：`occurredAt > cutoffAt` 才能进入下一滚动周期；`occurredAt <= previousCutoffAt`（首次为 `< initialWindowStart`）但后来才写入的是历史迟到来源，只能由用户手动关联原周期或忽略，不能静默顺延到当前或下一周期。

生成只能使用：

- 用户开启日记时允许的内容 scopes；
- `occurredAt` 位于本 Cycle 窗口内且生成时已经落库的消息、作答、学习记录和明确输入；
- 仍在召回期限内、来源属于本 Cycle 窗口且权限有效的短期/临时记忆；
- 已显示给用户或可定位的来源版本。

不能使用：无来源的模型联想、桌宠后台“经历”、窗口外事件、已撤销授权内容、已删除正文、未确认的医疗/敏感属性或其他用户工作区数据。

### 6.2 生成、验证和版本

1. `Diary` 对 `(workspaceId, subjectUserId, localDate, autoGenerated=true)` 建立业务唯一约束；这是用户可见身份去重，不定义本地日界线。同一日期标签已有自动日记时，计划修订产生的候选顺延到下一未占用日期标签，不创建第二篇自动日记；代操作的 `actorId` 不得替代数据主体。
2. Scheduler 用 `scheduleVersion` CAS、lease 和单调 fencing token 领取 Cycle；过期 Worker 不能写入版本或终态。`DiaryRunAttempt` 只表示一次执行尝试，不能代替 Cycle 或作为窗口边界。
3. 生成前冻结来源修订、`occurredAt/ingestedAt` 和权限快照；每个段落至少一个来源或明确标记“无足够素材”。
4. 事实校验、敏感内容策略、格式 schema、来源权限和重复检查全部通过后才发布。周期终态、Outbox 与 `lastCutoffAt/cursorVersion` 必须在同一 SQLite 事务中提交；只有 `Published` 或具有原因、操作者和时间证据的 `Skipped` 才推进 cursor，`Failed`、`Cancelled` 或 lease 过期不得推进。
5. 空素材但发布简短空日记/邀请补充属于 `Published`；只有用户或明确策略选择不生成才属于 `Skipped`。quiet hours 只延迟或合并通知，不延迟生成、截止点或 cursor。
6. AI 生成、用户编辑、重写和纠错都是独立 `DiaryVersion`；旧版本可追溯但不自动进入长期记忆。
7. 用户标记事实错误后，关联候选记忆立即阻断并进入复核；删除来源后显示来源失效，不用模型补写被删内容。

晚到规则：默认 `bufferClosedAt = cutoffAt + 30m`，但首版不得等待窗口关闭，须在设定时间后 15 分钟内发布；关闭前到达、`occurredAt` 落在本 Cycle 窗口但延迟写入的来源只形成可见补写候选，用户确认后生成新的 `DiaryVersion` 并显示变更原因。关闭后到达的本窗口来源不自动改写或生成候选，用户主动请求重写时才可纳入。只有 `occurredAt > cutoffAt` 的内容进入下一周期；早于或等于窗口下界的历史迟到来源不能自动顺延。调整生成时间、时区或遇到 DST 时，下一窗口必须从上一已提交 `cutoffAt` 连续开始；停用/重新启用以新的 `initialWindowStart` 开始，不得重叠、漏记或以固定 24 小时替代真实本地计划间隔。

失败跨过下一截止点或发生多日宕机时，Scheduler 必须按 `cutoffAt` 从旧到新建立独立 Cycle 并顺序恢复，不自动合并或静默跳过；超过已批准的自动补写上限后进入用户可见的待决定队列。

### 6.3 日记质量门槛

- 事实来源覆盖率 100%；
- 生成时间窗口命中率 100%，跨时区/DST 样本不得重复或漏日；
- 无互动日不虚构事件，允许空日记、跳过或邀请补充；
- 用户第一人称输出必须显式标记 AI 草稿；桌宠第一人称不得暗示真实后台生活；
- 敏感情绪、安全事件和医疗内容默认排除，只有当次明确授权且安全策略允许时才可出现；
- 日记事实纠错率、阅读率和 7 日保留率分层监控，不以保留率掩盖事实错误。

<a id="ai-safety"></a>

## 7. 安全响应

安全分类与教学模型隔离，分类服务失败时采用更保守的固定响应。危机响应必须：

- 停止继续施压、游戏化或学习目标推进；
- 明确承认无法提供紧急救援，给出目标地区可用的紧急/专业资源；
- 不诊断、不承诺保密、不制造依赖、不要求用户继续陪伴模型；
- 只记录最少必要的 `SafetyIncident`，访问受限，不写入关系分数、普通记忆或日记；
- 允许人工升级、复核、误报标记和政策版本回溯。

测试必须覆盖普通疲惫的误报、隐晦高风险的漏报、多语言、代码/引文中出现的危险词、Prompt injection 和人格模板覆盖尝试。不同地区资源不得硬编码为单一国家/地区。

## 8. 工具、插件与外部内容

- 工具定义包含输入 schema、权限 scope、资源限额、超时、取消、审计和失败结果；模型请求不等于授权。
- 插件 manifest 必须有 API 版本、checksum/签名、发布者、权限、允许 Host、CPU/内存/网络配额和撤销状态。
- 默认插件无数据库、文件、网络、记忆和日记权限；写记忆只能提交候选。
- 外部文本和附件先放入不可信上下文区，系统 Prompt 和工具策略在更高信任层；引用内容不能覆盖策略。
- 发现越权、恶意包、数据外泄或提示注入时，支持单插件和全局 kill switch，并保留审计证据。

<a id="ai-rollback"></a>

## 9. 运行监控、降级与回滚

必须监控：从 Turn 接受到首个通过安全门且已持久化分段的 TTFT、完整响应延迟、分段缓冲/检查/提交耗时、重连/取消/中断、错误/重试、token/成本、模型供应商分布、事实反馈、提示泄露、安全分类、来源缺失、记忆纠错、日记 Cycle 逾期/cursor 停滞/迟到/失败、删除积压和零召回验证。

降级顺序：

1. 使用已批准的备用模型/Prompt；
2. 关闭高成本工具、长期记忆召回、自动日记或主动提醒，但保留原始学习记录；
3. 展示可解释的失败状态，允许草稿、重试和导出；
4. 安全分类不可用时只发送固定保守响应；
5. 通过 Feature Flag/模型路由回滚，不执行不可逆数据迁移。

任何模型、Prompt、记忆算法、日记模板或安全政策更新都要先通过离线评估、对抗样本和灰度；生产指标触发阈值时自动暂停扩大流量并创建 `RISK/CR`。
