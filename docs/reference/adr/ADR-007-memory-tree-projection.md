# ADR-007 系统记忆树作为可重建投影

- 提出人：3yearszhuang · 2026-08-26
- 修改人：3yearszhuang · 2026-08-31

- 状态：Proposed
- 日期：2026-08-23
- 关联：`CAP-005/015`、`BR-MEM-003`、`DATA-MEM-001`、`RISK-003/004`

> 更新日期：2026-08-31

## Context

用户希望建立记忆树，但一条记忆可能跨主题，且来源删除、冲突和算法升级必须可传播。把树节点当永久事实副本会造成第二真源和删除漏洞。

## Decision drivers

- 长期记忆 Revision/Evidence 必须是事实真源，树节点不能复制正文；
- 一条记忆可能跨主题，需要独立边表达多主题关系；
- 来源删除、冲突和算法升级必须可传播到投影；
- 投影必须可重建，失败可降级而不丢事实。

## Considered options

1. **长期记忆为真源 + 树状投影**：避免第二真源，支持多主题（选定）。
2. **树节点保存事实副本**：查询直观，但形成第二真源，删除易漏。
3. **仅长期记忆列表、不建图**：最简单，但无法满足记忆树可视化与主题关系需求。

## Decision

长期记忆 Revision/Evidence 是事实来源；系统记忆是按工作区构建的树状投影。每个节点有 canonical parent，层级边无环；跨主题、因果、对比使用独立边，并继承来源权限/失效状态。投影可全量或增量重建，失败时降级为长期记忆列表。

## Positive consequences

- 避免复制事实，删除/纠错可单点传播；
- 支持多主题/因果/对比关系，且无环；
- 投影可重建，算法升级可灰度回滚。

## Negative consequences and risks

- 需要维护投影版本和图一致性检查；
- 重建需要资源，重建期间需降级为列表展示。

## Migration / rollback

树节点只保存引用和结构元数据；算法升级生成新 projectionVersion，旧投影保留至验证结束。删除/纠错从 Evidence 触发受影响子图重建。

## Verification evidence

状态改为 `Accepted` 前至少提供：

- 层级无环、跨主题权限与来源删除传播测试（`TC-INTEG-MEM-001`）；
- 冲突、重复证据与重建一致性测试（`TC-AIEVAL-MEM-001`）；
- 删除后零召回（`TC-PRIV-DEL-001`）。

## 验收差距复核（2026-08-31）

- **未满足**：`TC-INTEG-MEM-001`（无环/跨主题权限/删除传播）与 `TC-AIEVAL-MEM-001`（冲突/重建一致性）自动化缺失。
- **推进路径**：随 CAP-005 规格化（现为 `Specified`/Not Ready）补齐。
