# ADR-029 Bot 平台适配器与外部会话边界

## 1. 背景

维护者于 2026-10-15 明确授权实施微信本人私聊与 QQ 白名单群文字接入。现有客户端经 HTTP 受理会话，插件贡献集中于 UI、工具、Turn Hook 与路由；直接让平台适配器另建模型循环会割裂会话、审批、恢复和删除责任。架构历史来源 `AST-06` 将 IM 群聊判为范围外，本决定只扩展受限文字入口，不引入社区治理、共享数据库账号或租户隔离。

采用范围见 [PRD](../PRD.md#bot-platform-scope)，可观察行为见 [SRS](../SRS.md#fr-plg-005-bot-平台文字接入)。本决定的接受不代表真实账号验收或产品发布完成；实施协调与证据只维护在 [ITER-062](../../../plan.md#iter-062)。

## 2. 备选方案与决定

| 方案 | 取舍 |
|---|---|
| 在各适配器内嵌模型循环与平台数据库 | 拒绝；会话、安全、取消和持久化责任重复，无法继承统一执行策略 |
| 由独立 Bot 框架代理思隅 HTTP 接口 | 暂不采用；新增常驻状态与凭据副本，需要另一套恢复、身份映射与部署合同 |
| API 管理第一方传输插件，共用会话受理与完整执行 | 采用；平台协议可替换，数据与执行策略留在现有宿主 |

第一方 `BotAdapterContribution` 只拥有登录、收发、协议规范化、网络重连和取消。宿主提供按连接绑定的 Secret、checkpoint、状态与持久受理端口；适配器不直接访问数据库或调用模型。类型以 [`@aervox/host-plugin-api`](../../../packages/host-plugin-api/src/bot-adapter.ts) 为准，微信与 OneBot 包通过 API 组合根显式登记，声明式分发包继续只携带声明与资源。

每个连接由一个 API 宿主持有。启停、撤权、重配、卸载和进程关闭必须终止网络请求并拒绝旧实例迟到回调；普通客户端窗口关闭不结束独立运行的 API。API 使用完整执行链路处理 Bot Turn，持久化执行归属，Worker 不得通过简化链路抢跑。

## 3. 会话、权限与数据责任

| 入口 | 固定边界 |
|---|---|
| 微信本人私聊 | 先由管理页发起一次性配对并确认发送者，随后使用普通人格、记忆与独立会话；工具维持 `ask`；不暴露 CAP-033 私密画像与工具 |
| QQ 白名单群 | 仅直接 `@bot` 触发；按连接、平台账号、群、成员分别接续；公开基础身份与本成员历史；无本人人格、记忆、学习事实、工具、Skill、Hook、Inbox、DSH 和 CAP-033 |

会话来源与 Turn 执行策略在受理事务中固定，未知策略拒绝执行。HTTP 入口、重试、恢复和分支继承原边界，消息正文及 metadata 不能提升权限。群聊不能进入本人的个人记忆写入、整理或按需/定时日记素材。平台成员标识用于会话来源与隔离，不成为本地数据库认证主体；群成员无权访问管理 API。

入站以连接、平台账号及平台消息 ID 去重；同成员会话顺序执行，跨会话有界并行。协议游标只在消息持久受理之后前进。出站只发送可见正文，按平台上限分段，保存每段回执；平台接受不代表用户已读。结果未知时不得自动重发，断线前未收到的 OneBot 消息不承诺补齐。

API、平台队列和 Worker 共用 `@aervox/host-runtime` 的会话准入与执行器；Worker 只处理显式委托的本地会话，平台连接只由 API 启动。崩溃恢复以最新 Attempt 为准：终态同步 Turn 并补齐持久终态事件；已领取且租约过期或取消遗留的 Attempt 在同一写者事务内递增 fencing、将未决工具标为结果未知，并提交 Turn 与 `done`。平台队列与 API 恢复共用该协议，取消后被移出队列的工作也须收敛；仅从未领取的输入允许首次派发，不自动重放任何结果未知的副作用。微信重新扫码失败时保留旧有效凭据及接收循环，只有取得有效二维码才暂停旧轮询。

同一数据库客户端的外部操作通过进程内异步队列进入，显式事务持有槽位直到提交、回滚或关闭，事务内操作不重复排队。这样可避免 libSQL 同步等待 SQLite 写锁时阻塞事件循环，使持锁事务无法继续提交。队列仅覆盖短数据库操作与事务，跨成员的模型执行仍可并行；跨进程竞争继续由既有 SQLite 忙等待、重连与重试机制处理。

Bot 凭据使用独立密钥加密，平台令牌、微信上下文凭据与登录轮询令牌不进入管理响应或日志。管理页只展示凭据配置状态和本地渲染所需的扫码内容。业务事实仍在 SQLite；连接、收发队列与会话映射由现有仓储持有，凭据密钥单独备份，不与 CAP-033 Vault 共用。

## 4. 迁移、回退与限制

增量增加 Bot 表和会话执行边界，旧会话保留普通本地语义。回退先停适配器与写入，保留数据库、密钥和投递记录；旧版本不得执行新 Bot 会话。必须回退数据库时按[迁移演练](../../how-to/run-database-migration-drill.md)构建并验证恢复副本，不直接删表、删除新数据或重置未知投递状态。

本机与 Linux 独立机器均可常驻 API，但不自动同步 SQLite、个人资料或登录态。首期不支持微信群、QQ 私聊、媒体处理、主动提醒、平台内工具审批与任意第三方服务端代码动态安装。微信扫码接口与 NapCat 的可用性需分别进行真实账号验证；模拟协议测试不能证明平台长期可用或独立机器部署已验收。

## 5. 验证方式与参考

必须覆盖重复受理、成员隔离、秘密标记不可见、恶意工具调用无副作用、全局完全访问/DSH 不升级策略、API 重启与 Worker 并行、群来源派生隔离、生命周期取消、凭据脱敏及结果未知不重发。真实微信配对与连续对话、真实 QQ 多成员群和重连、本机与独立机器恢复另行留证；完整门禁、真实验收和发布分别陈述。

微信协议参考 AstrBot 固定提交 [`6ca3931925ab60a05c638fd66cb3c977b0d97f39`](https://github.com/AstrBotDevs/AstrBot/blob/6ca3931925ab60a05c638fd66cb3c977b0d97f39/docs/zh/platform/weixin_oc.md)，OneBot 连接方式参考 [NapCat 配置](https://napneko.github.io/config/basic)。适配器依据公开协议独立实现，不引入 AstrBot Python 运行时；许可与参考学习遵循[贡献指南](../../../CONTRIBUTING.md#参考项目与许可)。具体运行步骤见[连接机器人](../../how-to/connect-bots.md)。
