# ADR-027 空间名、陪伴角色名与用户称呼

## 1. 决策与范围

维护者于 2026-10-13 授权命名分层：固定软件名「思隅」表示空间与交互介质，陪伴角色拥有自己的名字，角色对用户的称呼由用户设置。角色名 `companionName` 默认「小隅」，用户称呼 `userAddress` 默认「你」。

原 `feat/companion-identity` 提交 `1c43ddec` 使用 CR-065 / ITER-060；这两个编号已由主线分别用于根界面装配与仓库卫生整改。整合时保留主线编号，命名决定转入 ADR-027，当前交付在 [ITER-061](../../../plan.md#iter-061) 跟踪；旧编号的原始含义由 Git 保留，不重用其权威锚点。

本决定只调整当前设备的对话设置、界面显示与随轮提示词元数据。不改变本地单用户、SQLite 数据所有权、权限、人格 prompt 覆盖优先级或第三方界面信任模型；人格面板与客户端设置统一入册仍留后续。

## 2. 行为差量

- 对话设置提供「TA 的名字」与「TA 怎么称呼你」两个字段；工作台、主动陪伴与素简文档界面的问候语、署名及称呼使用相同身份模型。
- 旧 `assistantName` 自定义值作为角色名读取；旧值恰为「思隅」时回到「小隅」。已有明确 `companionName` 优先，保存时移除旧字段并保留其它设置。
- 三种界面每轮请求携带 `companionName` / `userAddress`，绑定提交时的活跃会话。工作台在插件消息变换之后注入身份，插件不能覆盖显式身份字段。
- 模型提示词区分空间、角色与用户称呼。角色名优先采用当前人格名，否则采用客户端角色名，再回到默认值；人格 prompt 的既有覆盖顺序不变。界面设置不会直接修改服务端人格记录。

## 3. 验证与回滚

验证旧字段迁移、设置保存与重新加载、界面显示、随轮元数据、人格优先级、首次创建会话、请求失败重试、发送期间草稿保留及卸载取消。浏览器回归覆盖四种主界面选择、查询参数退出与窄窗口输入；构建和完整代码/文档门禁验证组合根依赖。

此处只迁移 localStorage 设置，无 SQLite 迁移。回退到只识别 `assistantName` 的旧代码前，需把已保存的 `companionName` 映射回该旧字段；旧代码没有 `userAddress` 字段。备份当前设置后再回退，不能宣称删除旧字段后的设置无条件向后兼容。真实模型、移动实机和发布验收单独记录。
