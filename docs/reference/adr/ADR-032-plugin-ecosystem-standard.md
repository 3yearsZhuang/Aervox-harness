# ADR-032 插件生态标识、分类与发布合同

维护者已确认按集合仓原 [PR #2](https://github.com/Aervox-agent/Aervox-plugins/pull/2) 的设计完成宿主和插件集合配套实现。上轮把目标规范改成现状说明的修改不能替代该决定。本决定接续 [ADR-031](ADR-031-first-party-plugin-repositories.md)，实施与证据统一登记 [ITER-075](../../../plan.md#iter-075)。

## 决定

新生态标识为 `ap-<category>-<slug>`，分类为 `tool`、`bot`、`ui`、`proactive`、`sync`、`workflow`、`theme`。主分类在创建身份时确定；后续能力扩展使用 tags，不因分类展示或版本升级重命名持久身份。集合源码位于 `plugins/<category>/<slug>`，宿主通过现有集合子模块在 `plugins/plugins/<category>/<slug>` 消费。包名、公共 exports 和宿主数据所有权保持现行合同。受信根界面仍位于集合 `surfaces/`，不冒充可动态执行的声明包。

Manifest 的 category、tags、breaking 与 Registry 元数据由 Contracts 定义，旧格式仍可读取。集合作者门禁执行新命名和 SemVer 标准。Tag 为 `<id>@v<version>`，附件为 `<id>-v<version>.aervox-plugin`，预发布通道已经包含在 SemVer 中，不再重复附加。目录分类统一使用上述单数形式。

Registry 只收录实际发布、下载并验证过的声明包，记录版本、兼容范围、大小与 SHA-256；空索引准确表示尚无发布。发布流程复用宿主打包器及根锁，不建立第二份 Schema 或 ZIP 实现。宿主通过公开索引读取市场元数据，下载后重验内容、身份、版本、权限和安装合同，客户端沿公共 API 浏览与确认。SHA-256 证明内容一致，不等于发布者签名。

作者门禁比较上一发布的 Manifest、Config 与工具声明，拦截可机器识别的破坏变化未递增 MAJOR；源码语义、数据结构或外部服务变化仍须作者显式标记 breaking，并经评审验证。单个版本号不自动授予数据迁移或扩大权限。声明资源支持图标和必须的许可材料，保留现有 AGPL 及第三方许可，不批量改许可。

## 现有身份迁移

维护者选择统一现有九个插件的新标识，通过显式离线工具迁移，**本次只实现及测试工具，不操作用户业务库**。不恢复通用 alias，避免相同插件多身份装配和授权判断分叉。

旧格式仍可预检，但这九个已退役的第一方 ID 不接受新的安装写入，避免生成新旧两份配置和授权。已有旧数据须先迁移，新安装使用新标识的发布包；其他历史第三方标识的兼容读取保持。

工具要求停写、备份、选择完整数据目录、建立 staging 副本、校验、原子换目录、保留回滚包。配置、Secret、启停、撤权、当前工具和技能、Bot 与主动规则关联应保持。遇到目标身份冲突、未知引用、外置未纳入资源或校验失败必须拒绝，不能合并记录、丢弃数据或猜测新旧权威。

不可变历史、审批版本及恢复账本保持原证据；迁移清单关联新旧身份，不重写签名链或令旧 Attempt 获得新身份权限。旧授权回执不能跨新身份复用。已安装归档、generation 所有者及目录在 staging 中保持一致更新，原始包由备份与回滚目录保留。启动在任何插件同步之前检查未迁移身份和迁移锁。

主动规则派生 ID 与加密关联数据也随身份变化。显式纳入所需 Vault 密钥后，只在 staging 重加密当前规则并保持触发/冷却状态；缺密钥、未知引用或解密失败均拒绝切换。历史收据和不可变账本继续保留原身份。

## 后果与验证

分类源码布局替代 ADR-031 第一阶段的平铺布局和保留旧 ID 的迁仓限制，其余宿主责任和两仓配对交付继续有效。新布局需要同步工作区、准入扫描、根锁、冷安装、实际消费者与移除演练。

验收须分别覆盖新旧协议、资源允许清单、可重现打包、Registry 下载校验、发布及 breaking 门禁、真实 SQLite 迁移与失败恢复、宿主和集合精确提交。代码验证、首次真实发布、用户数据迁移和正式产品发布分别记录，不将空 Registry 或临时夹具计为真实生态发布。
