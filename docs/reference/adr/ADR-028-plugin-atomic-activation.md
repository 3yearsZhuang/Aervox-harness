# ADR-028 声明式插件资源准备与原子激活

## 背景

覆盖安装曾先卸载旧插件再登记新版；配置、Secret 和授权会随卸载丢失，后续资源写入失败无法恢复完整旧版。需要在本地 SQLite 与文件系统之间保持可恢复性，同时避免数据库事务内解压和复制文件。

## 备选方案

- 卸载重装并在异常时重建旧记录：跨存储补偿可能再次失败，也容易恢复已经撤销的授权，不采用。
- 在数据库事务内覆盖文件：事务不能回滚文件，且长时间占用写者，不采用。
- 独立资源代际准备加数据库激活指针：文件先完整写入，短事务只选择已准备的资源及其元数据，采用。

## 决策

1. 分发预检使用共享 Manifest、配置和资源校验，解压受现有配额约束。验证全部声明入口后，将原始包、Page 与 Skill 内容写入唯一 generation 目录并刷写文件。
2. `plugins.bundle_generation` 是可空的内部指针；空值兼容旧路径，无需搬移已有目录。新目录在激活前不可被正常插件入口选中。
3. 一个 SQLite 写事务同时更新插件版本、指针、工具、技能和页面记录。保留原插件主记录以及用户启停意图，不删除配置、Secret 或授权，不把撤权记录恢复为有效授权。
4. 准备阶段读取的插件版本/代际、配置 Schema 与 revision 在事务内复验。配置并发变化拒绝本次激活，保留并发用户操作；调用方重新预检后再试。
5. 已保存配置支持新增默认值和移除顶层字段的 orphan 保留；类型改变或约束不兼容需要明确迁移，当前拒绝自动解释。Secret 不进入文件副本或导出包。
6. 准备/事务失败时旧指针仍生效；新安装失败不留下部分注册。进程在提交后退出时，新指针对应已准备文件。只在确认不是当前指针时清理失败代际，提交结果不确定时保留文件。
7. 已安装包导出返回原始归档字节，完整保留元数据、宿主要求与声明；它不导出用户配置/Secret。generation 包禁止通过旧 Schema/Page/资源接口原地修改，更新必须重新打包。带宿主归属标记的旧代际保留至显式卸载，未知旧目录和文件不自动删除，可从保存的原始包发起经验证的重装；不自动恢复旧授权。

## 后果与回退

安装需要额外磁盘空间；完成前的进程退出可能留下不可见代际，当前不自动回收，以免误删恢复材料。旧版本运行失败后的自动回退、配置更名/复杂迁移及跨版本业务数据转换不在此合同中。断电后的文件系统持久性仍取决于平台和 SQLite 配置；进程退出验证不能替代硬件断电演练。

该变化增加可空资源指针；关联 Hook 合同另增加执行代次并为旧记录生成初值，不删除既有业务数据。回退应用代码之前，应先用新版导出并恢复所需声明包到支持的存储布局；旧程序不理解 generation 路径，不能直接保证读取新版安装的 Page。原配置和授权不通过卸载恢复。

第一方实现与第三方执行的信任边界保持 [ADR-009](ADR-009-electron-plugin-sandbox.md) 和 [ADR-016](ADR-016-base-boundaries.md)；本决定不开放 Bundle 内服务端代码执行。

## 验证与证据

[升级集成测试](../../../apps/api/test/plugin-upgrade.test.ts)覆盖配置/Secret/撤权/停用保留、文件准备失败、事务中途失败、并发配置写入及原始包导出。[进程退出测试](../../../packages/repositories/test/plugin-installation.test.ts)在独立进程内于提交中和提交后退出，再重新打开文件数据库验证旧版或新版完整记录。发布与实机验收另行记录。
