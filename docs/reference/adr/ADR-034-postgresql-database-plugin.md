# ADR-034 PostgreSQL 主库配置插件与 SQLite 数据迁移

## 背景

维护者要求新增插件能力：将整个应用实例的业务主库切换为 PostgreSQL，包含现有 SQLite 数据迁移，连接地址由用户自管，可指向本机或远程服务。该需求已明确，本文记录可审查的实现边界；PostgreSQL 后端与迁移器尚未实现，隐私数据的去向仍需裁定。实施只由 [ITER-078](../../../plan.md#iter-078) 协调。

[ADR-003](ADR-003-postgres-retrieval.md) 与[数据库契约](../DATABASE.md#1-适用范围与不变量)原先取消 PostgreSQL 演进；本次拟修订数据库方言与部署限制，保留单用户、宿主数据所有权、来源、撤权、删除、幂等与恢复责任，不恢复租户列、RLS 或共享多用户服务。

当前 Schema、连接与仓储实际绑定 SQLite。`createInjectedDatabase` 使用 LibSQL 方言，并非 PostgreSQL 适配器；API Host 与 Worker 在读取插件配置前创建数据库，不能通过 Manifest 字段或修改 `DATABASE_URL` 兑现本能力。[ADR-031](ADR-031-first-party-plugin-repositories.md#分发生命周期与数据)规定宿主持有数据库与连接凭据，插件继续经窄端口提交意图。

## 备选方案

| 方案 | 判断 |
|---|---|
| 维持 SQLite 或仅新增连接配置 | 不能满足真实主库切换与数据迁移 |
| 插件直接持有数据库、业务仓储与迁移 | 将数据服务依赖于插件安装状态，破坏宿主授权、卸载与恢复责任，不采用 |
| 第一方插件提供配置入口，宿主提供完整数据库适配与迁移 | 拟采用；SQLite 保持出厂默认，用户显式选择 PostgreSQL |

## 拟决定

### 插件与宿主所有权

第一方受信插件拟使用 `ap-tool-postgresql`，在集合仓提供连接设置、检查结果、迁移预检与切换状态界面；主仓在 `@aervox/host-plugin-api` 增加宿主配置窄端口。驱动、Schema、Repository Port、事务、检索、迁移与恢复继续归主仓，不向插件开放裸 SQL 或连接对象。声明包安装本身不取得代码执行、迁移或网络权限。

应用实例的 API、Worker、调度和其他后台消费者统一使用数据库装配入口；Web、桌面及 CLI 通过原宿主服务访问同一主库。Android 独立实例现有固定 SQLite 合同由 [ADR-022](ADR-022-mobile-runtime-access.md)维护，不能因服务器切换宣称手机原生 PostgreSQL 已支持；移动客户端接入已配置宿主与独立设备换库分别验收。

插件停用、卸载或源码缺席不改变已经生效的数据库，不删除数据或宿主连接配置。宿主保留状态查看、凭据修复、迁移回执和显式切换入口；选择 PostgreSQL 后，数据服务不能依赖该插件继续安装。

### 独立启动配置与连接检查

宿主在主库之外保存版本化启动配置，区分当前生效与待生效目标，绑定实例身份、目标数据库身份、Schema 版本、配置代际、迁移回执和凭据引用。插件配置表不能承担其自身数据库的首次选择。含密码的连接串保存在宿主专用保护存储中，不进入普通插件配置、模型、日志、导出、Page 或 API 响应；界面只显示脱敏目标和配置状态。

PostgreSQL 连接检查必须验证用户指定的端点、认证、目标身份、访问权限、版本与业务能力。远程服务使用证书验证的加密连接；拒绝不受信重定向和静默关闭验证，错误回执不包含凭据。探活成功不等于结构或业务兼容。

主库切换在协调停止全部写者并排空执行后完成，通过持久配置原子激活和重启生效，不在活动事务中替换连接。API 与 Worker 必须绑定同一目标和代际；过期进程、独立手改环境变量及旧任务不能继续向旧库写入。所选目标不可用、身份变化或结构不匹配时拒绝业务准入，不静默改回 SQLite、不创建空库替代数据、不自动重放结果未知的事务。

### PostgreSQL 业务兼容

仓储适配吸收方言差异，业务调用方只消费同一领域 Port。必须实现 PostgreSQL 的物理 Schema 校验和版本身份，覆盖约束、索引、外键、JSON、事务回执、CAS/fencing、Outbox、历史分页、来源删除与撤权；不能把 SQLite 类型断言成 PostgreSQL，也不能依赖字符串替换假装完整方言兼容。

FTS5、SQLite JSON 函数、`rowid` 排序、PRAGMA 和文件备份分别提供实际后端实现。派生索引可以按后端重建；事实、稳定 ID、幂等键、历史顺序、引用关系与删除资格必须保留。类型映射须覆盖精度、BLOB、Unicode/NUL、NULL、时间和 JSON 内容；不可无损表达或语义不等价的数据输出阻断报告，不清洗、截短或选择冲突胜者。

### 现有 SQLite 数据迁移

用户已将迁移现有数据纳入功能范围。实现与演练使用隔离夹具；操作某一真实业务库前，须具备具体源库、目标、可复核预检、备份与数据范围，不从默认地址推断待迁移数据库。

迁移遵循以下持久阶段，重启只能从有证据的阶段接续：

1. **预检**：绑定源实例与版本，核对目标身份、权限、可用空间和所有消费者；显式列出事实、派生索引、凭据、附件、Vault 与独立账本的处理范围。未知表或不支持类型阻断；无可靠隐私分类的历史在保留本地保护的方案下阻断迁出，若批准新的受保护数据存储用途，则按最严格分类、明确范围和新授权处理，不能默认放行。
2. **停写与备份**：暂停新接单、Worker、调度与全部写者，排空或报告未决执行，创建并验证一致性备份，保存本机回滚集合；停写不等于把已受理任务记为完成。
3. **独立 staging**：在已证明为空且为本实例专用的 PostgreSQL staging 目标建库，在有界批次中保持原身份与引用导入。批次回执绑定源备份、目标与内容，重试按实际提交回执核对，不盲重放未知提交。
4. **校验**：核对逐表行数、规范内容校验值、主外键、唯一性、类型、来源与撤权关系、待执行任务以及必要业务查询；重建检索投影并验证删除后零召回。未知数据、冲突或内容损失拒绝激活，保留源库和证据。
5. **激活与重开**：目标验证通过后，原子激活外部启动配置，再以同一代际重开全部消费者。激活与首写前重新校验目标、迁移回执、独立 deny 账本完整性、连续水位及目标应用水位；备份后新增的删除/撤权须先重放并失效对应来源，缺口或未知回执保持拒绝。后续准入沿用实时撤权门禁，不把一次水位检查当永久许可；源库保持封存，禁止两个主库同时受写。
6. **回退**：首个目标业务写入前可恢复原启动配置和封存源库；目标已产生新事实后，必须停写并对账，执行经验证的反向迁移或修复目标，不能直接选择旧 SQLite 丢弃新数据。保留原备份、账本、密钥及回滚材料，期限至少沿用[现行迁移保留规则](../DATABASE.md#9-cr-030-破坏性迁移)。

PostgreSQL 集群无法与本地配置实现跨库原子提交；协议必须承认并恢复激活、重开与提交回执未知的窗口。源数据未删除、目标失败与活动配置未切换分别报告。数据库备份不得覆盖独立 deny 账本，不解除历史安装的安全恢复拒绝。

### 待裁定的隐私数据去向

[SRS 的 BR-PRO-003](../SRS.md#br-pro-003-本地处理边界)要求 `local_only` 从来源传播到画像、记忆、提醒和 ContextManifest；[PRIV-PRO-002](../SRS.md#priv-pro-002-本地持久化与不出云)明确禁止远程数据库接收主动数据。[隐私规范](../DATA_PRIVACY.md#2-数据角色与范围)还将普通业务库与备份归属用户私有目录。本次允许自管远端 PostgreSQL 的需求需要明确修订普通存储的运营方、地区、备份、删除和访问责任；自管、TLS 或 loopback 地址都不证明存储仍在同设备。

仅保留本地 Vault 不足以满足该合同：主动提醒正文会写入主库通知，画像会影响普通对话回复；旧会话未持久绑定完整数据边界。新的 ContextManifest 已由仓储投影为不含正文的请求元数据，但历史正文没有自动清理，不能假定旧快照和派生历史可安全整体迁出。

以下三种方案需要维护者选择；未选择前不放宽现行本地保护，也不迁移真实业务数据：

| 方案 | 行为与代价 |
|---|---|
| 保留受保护的本机独立事实域（建议） | 普通业务采用 PostgreSQL，主动画像及其对话、提醒和混合来源派生数据继续在可证明同机的持久域；需完整路由、来源标记及跨域事务/删除协调。无法可靠分类的历史保留并阻断整体迁出 |
| 允许受保护数据进入用户自管 PostgreSQL | 明确修订“不出云”用途与承诺，定义用户告知、地区、权限、密钥、备份与删除责任；原有授权不能自动视为覆盖新存储用途 |
| PostgreSQL 实例关闭主动模式 | 普通业务可换库；启用主动模式拒绝。既有主动数据仍须留在本机，无可靠分类的旧库拒绝远程迁移，关闭能力本身不能使旧数据获得迁出资格 |

Vault、附件、设备身份和独立恢复控制账本的本机保护及故障域保持，改变这些范围须另行明确。远程主库启用或迁移必须在批准方案的真实存储路径上验证，不通过清空历史或默认放行满足检查。

## 后果与回退

本能力增加第二种数据库适配及迁移维护成本，不能只交付配置开关。现有 SQLite 安装保持原行为，插件安装不自动启用 PostgreSQL。源码与根锁通过 [ADR-031](ADR-031-first-party-plugin-repositories.md#两仓开发与兼容验证)的配对 PR 交付；源码回退不回滚用户数据库。

本提案接受后，同步修订 ADR-003、PRD、SRS、DATABASE、ARCHITECTURE、DATA_PRIVACY 与相关能力合同；保留旧决定和编号，不把 PostgreSQL 等同于多租户或云服务产品。能力状态仍以实际后端、迁移及目标环境证据为准。

## 验证与证据

先在真实 PostgreSQL 验证结构漂移拒绝、完整领域仓储合同、并发与提交结果未知、API/Worker 同代际、连接故障重开、凭据不披露及插件缺席的数据管理。连接 mock 和设置保存不算主库支持。

SQLite 到 PostgreSQL 的隔离演练覆盖 Unicode/NUL、BLOB、JSON、引用、历史分页、Outbox、来源删除、备份后新增 deny 而目标回放未完成的激活拒绝、迁移各阶段中断与目标新写后的回退拒绝；校验失败保持源库与现行配置。受保护数据分别验证本地路由或经批准的新存储用途；混合来源与未知历史按批准方案验证拒绝或最严格分类及新授权，不自动降低保护。

新实例、存量迁移、本机部署、远程部署、移动宿主接入、独立移动后端与正式发布分别取证。当前只有需求与提案，未提供 PostgreSQL 业务运行、数据迁移或发布证据。
