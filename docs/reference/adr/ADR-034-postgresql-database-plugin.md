# ADR-034 可选 PostgreSQL 主库插件与 SQLite 离线迁移

## 背景

维护者要求通过用户自主安装的插件，将整个应用实例的业务主库改为自管本机或远端 PostgreSQL，并迁移已有 SQLite 数据。SQLite 保持出厂默认。本决定修订 [ADR-003](ADR-003-postgres-retrieval.md) 的后端选择限制，保留单用户、宿主数据所有权、来源、撤权、删除、幂等与恢复责任；不恢复租户列、RLS 或共享多用户服务。实施与验证由 [ITER-078](../../../plan.md#iter-078) 协调。

插件安装状态不能放在尚未打开的目标库中决定首次连接；[ADR-031](ADR-031-first-party-plugin-repositories.md#分发生命周期与数据)仍要求宿主持有数据库和连接凭据。既有 `local_only` 与主动数据不出云合同继续适用，用户选择远端 PostgreSQL 不构成放宽该用途的授权。

## 备选方案

| 方案 | 判断 |
|---|---|
| 仅保存 PostgreSQL 地址 | 无法兑现真实业务仓储与已有数据迁移 |
| 插件直接持有业务库、裸 SQL 和迁移 | 数据与恢复责任越过宿主边界，不采用 |
| 可选插件提供 Provider 身份，宿主完成原生适配与离线切换 | 采用；默认 SQLite，用户显式安装、启用并迁移 |

## 决策

### 插件和宿主

第一方插件为 `ap-tool-postgresql`，安装策略为 `optional`。市场可以展示，首次启动不创建其安装、配置或授权记录；安装和启用不自动连接或迁移。声明包提供受信 Provider 身份，宿主拥有连接、Schema、领域仓储、启动配置、迁移、凭据和恢复，插件不取得裸数据库对象或任意 SQL 权限。

首次迁移和激活前，`ap-tool-postgresql` 必须已安装并启用，宿主按源库/已验证备份中的安装记录检查该资格。激活后，生效主库、连接凭据和数据管理归宿主所有；停用、卸载或移除可选声明包不解除主库选择，宿主继续通过原生后端访问 PostgreSQL，保留数据管理与修复入口。实际连接、凭据或目标身份/结构失败仍拒绝业务，不静默选择旧 SQLite，也不创建空数据库替代已有事实。声明包的生命周期不成为已选业务主库的持续可用性依赖。

API、Worker 和 CLI 共用宿主的生效数据库配置；业务调用方继续消费领域 Port。Web/桌面通过既有宿主接口访问。Android 独立端继续固定 SQLite，见 [ADR-022](ADR-022-mobile-runtime-access.md)，本决定不宣称原生手机换库已支持。

### 原生 PostgreSQL 和启动配置

支持 PostgreSQL 16 及以上、UTF8 编码。物理结构从同一 `@aervox/schema` 声明编译，独立 PostgreSQL release fingerprint 绑定列、约束、索引、搜索投影和实例标记。使用真实 `pg` 连接与 PostgreSQL Session/方言编译查询；复用领域仓储和查询 AST，不将 SQLite SQL 通过字符串替换当成 PostgreSQL 后端。

普通启动只校验已准备的专用 Schema、实例与版本，不自动修补漂移或初始化未知库。共享/系统 Schema、未知对象、外键/索引/列语义变化、触发器及可覆盖查询语义的额外函数等均拒绝。JSON 保持序列化文本，插入顺序有独立位置列；FTS5 和 PostgreSQL 文本检索分别作为可重建投影，相关性分数不承诺相同。

宿主在主库之外保存版本化启动配置和加密连接凭据，避免依赖目标库中的插件配置完成首次开库。密钥、状态与回执保存在用户私有目录；不宣称文件密钥等同 OS Keychain。连接串不进入普通插件配置、Page、API 响应、模型、导出或日志。`AERVOX_POSTGRESQL_URL` 是离线命令的输入，不能单独改变生效后端；已生效配置由受控激活流程读取。

远端连接使用证书和主机名验证的 TLS；连接、语句、锁等待及闲置事务有界。地址参数不能关闭验证或覆盖连接策略。探活成功不代表结构、业务或隐私兼容。连接池建立新物理连接时，在业务事务前重新核验目标结构、实例与本机存储资格；不能沿用旧连接的证明接入变化后的目标。目标不可用、身份/结构变化或提交回执丢失均拒绝；未知提交不因后续 rollback 成功而被当作未提交，也不自动重放。

### 整个业务主库的离线迁移

迁移覆盖 canonical 主库全部业务表，包括配置与已保存事实；独立 Vault、恢复控制账本、附件文件和 P2P 设备身份保持原故障域，不随数据库行迁往 PostgreSQL。旧源库必须先达到当前 canonical 结构和版本；未知表、视图、触发器、类型或范围阻断，不通过丢弃对象满足校验。

迁移器按具体源路径、目标 Schema/实例与新备份目录操作，先停止 API、Worker、调度和全部数据库连接。持久独占锁阻止源库重新开写；未 checkpoint 的 WAL/journal、活动句柄或无法证明停写的状态均拒绝。源库从不由迁移器直接重写：先建立一致、带 SHA-256 的已验证备份，只打开其检查副本进行导出和检索重建。

仅在独立、已证明为空的目标 Schema 中初始化并导入。稳定 ID、全列内容、引用、幂等键和四类原 SQLite 插入位置保留；逐表行数、规范内容哈希、外键/索引、来源结构、搜索投影与下一插入位置验证后才生成 durable receipt。NUL、非法 UTF8、不安全整数、非有限数、错误 affinity 或无法解析的 JSON 拒绝，不能清洗、截短或选冲突胜者。

准备完成不激活配置。激活前再次核对源库身份/字节、备份、Vault/独立账本证据、目标身份/结构/内容和回执；任一变化保留拒绝。备份后的源事实、删除或撤权变化必须重新准备或进入经验证的修复流程，不自动覆盖独立 deny 账本，也不解除原安全恢复门禁。

持久阶段包括认领、备份、预检、目标初始化、导入、提交待确认、已验证、失败和结果未知。失败保留源、备份、staging 与锁。导入提交回执未知需要依据保留证据核对真实目标，当前 CLI 不自动裁定或重发原导入。原子激活主库外配置后源库继续封存，旧进程不能继续写入；本地配置与 PostgreSQL 没有跨介质原子事务，恢复必须承认该窗口。

### 远端隐私边界

[BR-PRO-003](../SRS.md#br-pro-003-本地处理边界) 与 [PRIV-PRO-002](../SRS.md#priv-pro-002-本地持久化与不出云)保持：主动原始数据、画像、授权、动作及其派生记忆、提醒、对话和 ContextManifest 不进入远端数据库。仅留住本地 Vault 不能证明安全，画像可能已影响普通会话；新 ContextManifest 是无正文请求元数据，历史快照并未自动清理。

迁移与运行时共用保守的本机存储证明：当前 OS 用户私有 UNIX socket、同用户私有 PostgreSQL 数据目录与受支持本机存储结构。自管、TLS、TCP loopback、转发或缺乏证明的地址不取得 `local_only` 资格。无法证明时，整体迁移拒绝受保护或来源无法分类的历史；不通过关闭画像、清空历史或重标分类放行。

纯配置和插件、工具、技能注册元数据可通过远端预检，覆盖空业务库的实际宿主首次启动产物。人格及其修订正文、技能载荷/候选/发布历史和导入工作区技能不是出厂注册元数据；原始会话已经不存在或 `source=builtin` 均不提供迁出豁免，不能据此证明文本的来源或隐私分类。

远端或未证明本机的主库实例必须关闭主动激活、画像处理及可能把 `local_only` 派生结果写入主库的运行路径。无法维持该拒绝时，相关用途继续 fail closed。普通远端存储由用户负责服务运营方、地区、访问、备份、保留和删除；Aervox 的在线来源/删除规则仍适用，TLS 不代替静态加密或数据库备份删除责任，详见 [DATA_PRIVACY](../DATA_PRIVACY.md#2-数据角色与范围)。

### 状态、恢复和回退

宿主离线命令合同为 `./aervox database status|migrate|activate|recover|abort`。`status` 报告脱敏状态；`migrate` 准备和验证目标；`activate` 切换已验证目标；`recover` 复验原操作进程退出后的启动配置发布中断，保留源锁，不处理未知导入 COMMIT；`abort` 仅放弃未激活尝试，拒绝活动 owner 和已生效 PostgreSQL，归档源锁并保留全部目标、备份和回执。参数与操作流程见[数据库契约](../DATABASE.md#postgresql-operations)，CLI 接线及端到端验证仍由 ITER-078 保存证据。

没有自动反向迁移或目标已产生新事实后的旧库回退。该情况下停止写入并修复/对账目标，不能选回封存 SQLite 丢弃新数据。保留备份、账本、密钥、回执与失败 staging；清理遵守[现行保留规则](../DATABASE.md#9-cr-030-破坏性迁移)。

## 后果与回退

增加原生 PostgreSQL 适配、双物理编译与离线恢复维护成本，既有 SQLite 安装保持原默认。第一方声明与宿主通过 [ADR-031](ADR-031-first-party-plugin-repositories.md#两仓开发与兼容验证)配对提交验证；源码回退不回滚用户数据库。SQLite 专用原生向量缓存和 P2P/文件备份路径不能在 PostgreSQL 下假装可用，须使用适合当前后端的路径或明确拒绝。

## 验证与证据

原生适配、物理结构和隔离迁移已有真实 PostgreSQL 18.6 测试，覆盖结构漂移、内容/引用、JSON/Unicode、脏数据、插入位置、检索投影与 COMMIT 回执丢失。组合根、CLI、首次安装/启用资格、声明移除后主库保持、远端主动拒绝、密钥不披露及全量门禁继续在 ITER-078 记录，不将连接 mock 或声明包当作业务支持证据。

未迁移或修改用户业务数据库。真实用户库、远端部署、API/Worker 重开、移动宿主接入及正式发布分别验收；本决定被接受不代表这些验收已经完成。
