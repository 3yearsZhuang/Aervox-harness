# ADR-035 本机回环端点的唯一判定

## 背景

`isLiteralLoopbackUrl` 用于回答一个跨模块的同一问题：某个模型或服务端点是否指向本机。它决定主动智能能否把处理留在本地、模型路由能否把预设归入本地候选项，以及 `LocalOnlyStorageRequiredError` 是否抛出。这一判定曾被实现两次，且结论相反：

| 位置 | `localhost` | 协议校验 |
|---|---|---|
| `packages/contracts/src/model-routing-schemas.ts` | 接受 | 无（`file:`、`ftp:` 也会被判为本机） |
| `packages/host-runtime/src/modules/proactive/proactive/profile-context.ts` | 拒绝 | 仅 `http:`/`https:` |

两处各自有测试锁定相反结论，因此同一份 LLM 配置在一个模块里是「本地」、在另一个模块里是「不可本地」。这既让 `localhost:11434` 这类常见本地模型端点无法通过主动智能的本地准入，也让非 HTTP 协议的 URL 被误判为本机。它构成静默漂移与安全面扩大，不是偏好差异。

本决定细化 [ADR-018](ADR-018-proactive-local-privacy-host.md#decision) 中「仅接受字面 loopback 请求」的实现语义，不改变该 ADR 的任何数据边界、授权或删除责任。

## 决定

`isLiteralLoopbackUrl` 只在 `@aervox/contracts` 中实现一份，其余模块只消费。判定同时满足：

1. URL 可被 WHATWG `URL` 解析；
2. 协议为 `http:` 或 `https:`；其他协议一律拒绝，即使主机名是回环地址；
3. 主机名为 `localhost`、`127.0.0.1`、`::1` 或 `[::1]` 之一，比较前统一小写。

无法解析或任一条件不满足时返回 `false`（fail-closed）。函数不发起 DNS 解析、不限端口、不读取环境变量，因此结果是纯函数，可被两侧模块共用。

`localhost` 属于被接受的写法：它是本地模型服务的常规入口，拒绝它会让现有本地配置全部失效，而不是阻止任何真实的外部访问。协议校验才是本次实际修补的安全缺口。

## 备选方案

| 方案 | 判断 |
|---|---|
| 保留两份实现，只在文档说明差异 | 不采用。结论相反，调用方无法预期结果 |
| 统一到 host-runtime 版（拒绝 `localhost`） | 不采用。收窄真实可用的本地端点，且与用户既有配置冲突 |
| 统一到 contracts 版（不校验协议） | 不采用。`file://127.0.0.1/...` 这类输入会被判为本地，扩大而非缩小安全面 |
| 统一到 contracts 并补协议校验，接受 `localhost` | 采用 |
| 追加 `127.0.0.0/8` 全段判定 | 暂不采用。会把大量非本机回环别名纳入准入，属独立决定；如需要应另行修订 |

## 后果

- 两侧调用方得到一致结论，主动智能的本地准入与模型路由的本地候选来自同一判据。
- 非 HTTP(S) 端点不再被误判为本机，这是可观察的收紧；依赖旧行为的输入现在被拒绝。
- 断言 `localhost` 为 `false` 的既有测试与本决定冲突，必须按本决定修正；断言 `localhost` 为 `true` 的测试保持成立，并补充协议拒绝用例。
- 判定仍不覆盖 DNS 重绑定、代理与转发。它回答的是「该 URL 字面是否指向本机」，不是「该请求实际是否只到达本机」；后者仍由 ADR-018 的本地边界与出网阻断验收负责，不因本决定提前关闭。
