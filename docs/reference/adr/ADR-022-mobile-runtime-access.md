# ADR-022 移动端运行与跨设备访问边界

<a id="cr-055"></a>

## 状态与背景

本记录承接原 CR-055，维护者已接受下述 **Android 隔离原型 M0 技术方案**；接受范围不包含正式平台支持、签名发布或其它备选路线。维护者已明确选择**手机独立运行，电脑关闭后仍可使用**，不再以配套端作为首个交付目标。Vue + Capacitor 沿用已接受的 [ADR-015](ADR-015-vue-full-stack.md)；维护者已进一步确认 **Android 先行**；M0 的本地运行时、首个范围与原生持钥方案已裁定；Android 正式版本范围仍待设备矩阵，iOS 留作后续平台验收。已有移动平台标记、单列布局、安全区、键盘与会话草稿切片，不能据此认定独立运行、原生工程、真机网络或发布已经验收。

手机优先解决继续对话、作答、反馈和今日复习。Capacitor 只封装前端，不能直接承载现有 Node.js API、Worker、SQLite 原生依赖或桌面子进程。当前顺序与责任维护在 [plan.md](../../../plan.md)，本 ADR 不承诺工期或 CAP 完成状态。

## 备选方案与建议

| 路线 | 运行与数据责任 | 取舍 |
|---|---|---|
| 移动 Web 配套端 | 电脑运行 API/Worker，电脑 SQLite 为业务真源 | 最快验证手机交互，但电脑必须在线且可达 |
| Capacitor 配套端 | 复用 Web 与主机 API；手机仅存获准草稿、设置和恢复标识 | 可安装及受限原生桥接，增加签名、权限和生命周期成本 |
| 独立手机端 | 手机领域运行时、数据库、模型连接和可补偿调度 | 电脑关闭后可用，但必须实测依赖与系统限制 |
| 桌面与手机双向同步 | 两个可写副本与复制协议 | 新增冲突、墓碑、删除、撤权和密钥责任，不纳入首版 |

已选择独立手机端，因此先在 Android 验证本地执行与存储适配，再确定版本范围和交付范围；移动 Web 可用于界面验证，但不算完成独立端。手机作为本安装的业务真源，不依赖桌面 API/Worker，跨设备双向同步仍由 ITER-028 单独验收。独立运行不等于无网络推理，模型可按用户配置连接获准服务；`local_only` 仍不能外发。手机 USB/BLE 外设网关、手机常驻 Agent、任意插件安装、公共中继、健康来源与多主同步均需另行决定。

## 已接受的 M0：Android 独立隔离原型

维护者在审阅具体方案后，选择复用 TypeScript Core 与现有仓储规则，以固定内置 SQLite 作为本安装唯一持久真源，原生侧保存模型凭据并执行模型请求。首版只处理新建手机测试会话的前台发送、流式结果、重启读取、取消、一次问答与删除闭环；使用隔离测试库，不操作桌面业务库，不自动导入活动 SQLite/WAL。产品目标和本技术范围均已获授权，无需重复确认普通实现步骤。

- **引擎与 Schema：** 首个候选为 [SQLite 官方 Android 3.54.1 AAR](https://sqlite.org/download.html)，固定版本及官方 SHA3-256 `3afb0568a107d753b640e4d65cdb1d9a2247e9833c25e72ca7d1086b78365de1`；显式恢复并验证依赖，构建不接受缺失或篡改制品。项目承担引擎/ABI/安全修复更新责任。[系统 SQLite 随 Android 版本与厂商变化](https://developer.android.com/reference/android/database/sqlite/package-summary)，不能由 minSdk24 推定 RETURNING、JSON 和 FTS5 均存在。唯一 Schema 来自仓储 manifest 的版本、发布指纹和 DDL 构建制品，不在 Java/Kotlin 重写表结构；不匹配时拒绝写入，不清库猜测迁移。
- **业务权威：** 原生连接提供参数绑定、串行写者、受限事务和资源边界；接单、审批、fencing、删除与幂等仍由复用的领域命令负责，不拆成多次桥写模拟原子命令。中性执行适配只委托持久仓储，不把内存 Store 或 Preferences 快照作为提交成功回执。主库、Vault、恢复账本和密钥的故障域继续遵循原合同；未实现的主动、Vault、插件等能力在准入处关闭，不能用空实现放行。
- **凭据与模型：** 使用 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) 的不可导出包装密钥保护原生私有密文；Keystore 不直接存任意 API Token 字符串。WebView 只取得配置摘要与 ModelChunk，不接收模型密钥。原生请求按保存的受限端点/预设执行，提供取消、截止、字节预算、请求代际与 HTTPS 校验，不作为任意 URL/header 代理。无有效凭据或 local_only 遇远程模型时拒绝；密钥失效时不自动重建覆盖旧密文。
- **桥与数据范围：** 首版只装受信捆绑脚本，SQLite 桥不向插件 Page 或外部页面公开，不接受外部数据库路径、ATTACH、动态扩展或远程数据库 URL。模块私有性不能抵抗同一受信 WebView 脚本被攻陷；需要不受信 UI 隔离时另定独立执行环境。数据库保存在应用私有存储；系统自动备份和明文网络保持关闭；依赖 AAR 的 `allowBackup=true` 必须在合并 Manifest 中被明确覆盖。
- **验收边界：** minSdk24 仅保留为原型构建下限；候选尚须真实 JSON/NUL、FTS5、RETURNING、FK、回滚、ABI/16 KiB 页面和设备验证。先用确定性 Provider 完成持久命令合同，再显式接真实获准模型；电脑关闭仍能完成闭环才可称独立端。后台终止保留已提交数据并在重启补偿，不承诺常驻 Worker。同步、本机推理、第三方代码插件、后台主动运行及正式发布继续由各自前置约束。

按依赖先交付中性执行边界与唯一 Schema 制品，再验证原生 SQLite、装配内部 Transport 与持钥模型桥，最后做实际进程重启和删除/迟到写矩阵；构建、原生测试编译、Android 测试执行及真实 Provider 分别记录。候选版本批准进入隔离原型，不代表原生制品或平台已经验收。

## 当前前台文本接线

当前分支由 `MainActivity → NativeRuntimeActivity` 装配固定资产 WebView、私有 SQLite actor、原生模型服务与 UI 偏好适配。共享界面经内部 Transport 调用中性仓储和 Core，普通浏览器预览继续使用 API Transport。受信组合模块只能导入已声明的中性公开出口，普通 Web 视图和第三方 Page 不因本接线获得仓储或 SQL 权限。

固定业务库只在独占新建文件时初始化唯一 Schema、FTS 和版本回执；已有库须通过本方完成标记、文件身份、版本及完整物理结构验证。不自动导入、迁移或重建未知库。所有权锁仅在原生 SQL 确认 drain 后释放；有效本方归属内的 rollback journal 交 SQLite 恢复，外来 WAL/SHM 和不匹配证据保留并拒绝。外部标记用于应用私有目录内的生命周期归属，不能证明对抗 root 或任意同 UID 篡改。

原生模型配置一次保存端点、模型与密钥，不拆成可能错配的多次提交；配置输入不经过 WebView。网络只使用该保存配置，固定 OpenAI 兼容文本 SSE，拒绝重定向、任意 header、IP 字面量和 localhost 端点。原生控制与网络线程有队列、字节、事件和截止限制，前台退出请求取消；JavaScript 读完分页终态后才提交完成，不能用“生产者已结束”替代“所有分片已消费”。密钥摘要只能表示配置已保存，真实服务成功须由实际请求证明。

当前文本输入限于 32 KiB UTF-8 和 120 KiB JSON 字符串正文编码，回复正文限于累计 48 KiB JSON 编码（不含两端引号）。原生生产者和 JavaScript 消费者均在超限分片发布前以 `length` 结束，Core 按原有安全、取消和 fencing 规则冲刷尾段并提交 `Interrupted(model_length)`，不把截断回复记为完成。控制字符的 JSON 膨胀计入预算，接单 Outbox、全文终态绑定和单轮历史回执保留原生限额；历史页按字节缩页，模型历史在同一快照逐轮读取，保留完整对话对的字符预算。具体使用限制见[移动工程说明](../../../apps/mobile/README.md#首次独立对话)。

未发送草稿与当前会话选择可通过原生 UI 偏好缓存恢复；缓存不保存凭据或业务提交回执。模型缺配不接单，未知提交不重放模型；过期执行由共享仓储退休，不能把草稿恢复称作执行断点。当前切片只提供普通权限的前台文本、新建/改名/删除、分页历史和停止；工具问答、设备工具、后台常驻及完整 M0 故障矩阵仍未接入或未验收，获批的 M0 目标继续保留。

受信文档从首次原生就绪回执前开始观察退休；退休后关闭请求准入、释放生命周期监听器，不向旧界面返回迟到结果。等待模型配置回执时若观察到进入后台，即使随后返回前台，也拒绝尚未接单的发送；接单已经提交而回执跨过后台切换时，复用共享取消事务收尾并保留真实受理回执，不启动模型。恢复仍按持久租约裁定：有效租约不抢占，到期后退休为 Interrupted 或 Cancelled，保留已提交安全前缀，旧 fencing 写入拒绝。

## 能力交付与授权分级

维护者已允许按具体功能使用系统授权、Shizuku 或 root；基础对话、存储、凭据和模型网络必须先在普通应用权限内可用。提高权限不能替代缺失处理器，也不让普通功能依赖已安装 Shizuku 或设备存在 `su`。界面分别表达“代码未接入／前台原型／已验证可用／失败”等交付状态与实际授权状态；未接入不展示假授权或假启停按钮。

| 范围 | 授权边界 | 当前接线与后续验收 |
|---|---|---|
| P0：本地对话、会话与历史、密钥、HTTPS 模型、停止和删除 | 普通应用权限与应用私有目录 | 当前前台文本原型；真实模型、重启和删除故障分别验收，不依赖提权 |
| P1：语音、通知、用户文件、屏幕采集等 | 各自 Android 系统 API 与具体用途授权 | 未接入；实现时按功能请求，不以一次总授权替代系统逐次/作用域规则 |
| P2：明确类型的系统诊断或受限系统操作 | Shizuku 实际 UID、Binder 和应用授权 | 未接入；按类型固定操作、目标、输入与结果边界，服务撤权/死亡后停止准入，未知副作用回执不重放 |
| P3：普通 API 与 Shizuku 无法满足的特定实验 | 明确目标及可撤销 root 执行边界 | 未接入；不提供任意 shell、提权文件浏览或绕过主仓业务账本的第二执行器 |

[Shizuku API](https://github.com/RikkaApps/Shizuku-API) 的 ADB 启动通常是 shell UID，不是 root；调用者必须查询实际 UID 和授权，不能推定可访问其它应用私有数据。未来辅助服务只承接有界、类型化的具体操作；工具准入、审批、fencing、取消与删除仍由现有 Core/仓储命令裁定。服务连接或权限状态不是功能健康证明，也不构成第二份业务真源。

## 手机应用参考与取舍

本轮参考维护者设备上实装的 [FlClash](https://github.com/chen08209/FlClash) 0.9.2 仪表盘，以及 [AstrBot 运行管理器](https://github.com/JunWan666/astrbot-for-android)（`io.astrbot.android`，JunWan666，1.0.0）的首页和设置。设备截图是界面证据，主分支源码可能包含未发布功能；只看过仪表盘不能据此宣称工具页已验证。参考期间不启动其代理/服务，也不修改现有配置；可能含订阅、网络或设备信息的原始截图不提交仓库。

- **已用于本轮：** 沿用 Material 3，把标题、说明、右侧状态/操作与 tonal 分组统一；本机存储、前台运行、模型保存状态分别显示。无处理器的桌面入口关闭，保留原有角色、圆角输入、返回和键盘操作。
- **值得后续接入：** AstrBot 的环境预检、修复入口、版本/运行/健康分离，按需启停，以及有界日志、脱敏诊断和显式备份恢复。Aervox 应先有真实处理器和持久生命周期再展示入口，不复制一套不受主仓规则管理的服务控制面。
- **不直接对齐：** FlClash 的流量/VPN 仪表盘与悬浮导航不属于对话产品需求；AstrBot 的 PRoot Ubuntu/NapCat 是其部署方案，官方项目声明无需 root，不能由其存在推导 Aervox 必须提权或搬入完整 Linux 运行环境。本轮不复制第三方代码、素材或个人配置。

## 可选配套访问的备选边界

以下仅适用于未来显式启用的桌面访问模式，不替代已选择的独立端目标，也不自动复制手机或桌面的业务数据库。

共享 Vue UI 只消费平台 Port，不直接导入 Capacitor/Electron；API Client 统一连接、鉴权、游标、取消和恢复；移动壳提供生命周期、安全存储及按需系统权限。平台功能按能力声明判定，避免以移动标记复制业务逻辑。手机无直接 SQLite 或主机私密控制面入口。

推荐首版使用单列工作台，支持消息身份、持久化历史、引用/删除、作答与复习；日记只读且必须证明来源可跨设备，完整编辑与资料管理另列。人格和界面偏好不提升权限，主机进程、模型下载、路径与桌面权限仍由主机管理。角色动画按设备能力启用，资源失败不能阻断核心操作。

### 认证与网络

- 首版建议显式连接同一局域网主机，仍须加密和对端验证。手机 `localhost` 不代表电脑；连接界面必须显示主机身份。
- 比较受信 HTTPS、原生证书绑定与配对闭环；不能把浏览器证书警告或跳过校验作为生产步骤。
- 主机显式启用受限访问，短时一次性配对材料换取可撤销设备凭据；设备 ID 用于认证/审计，不成为业务分区键。二维码、URL、构建配置和日志不得含长期 Token 或模型密钥。
- 原生凭据走 Keychain/Keystore 等受限 Adapter；Web 会话方案与服务端共同裁定，长期凭据不写 `localStorage`。请求、SSE、附件、取消共用鉴权，CORS 不代替认证。
- 入口仅暴露获准能力；主机配置、模型进程、插件安装、文件路径和私密控制面默认关闭，工具调用也须后端准入。

现行隐私规范的 Web Cookie / 移动 OIDC + PKCE 与本机 API Token 存在差异。该可选配套访问路线启用前必须另行裁定并同步认证和威胁模型，不能把当前本机 Token 或独立原型的原生持钥认定为远程移动发布方案。

### 数据与恢复

配套端以主机为业务真源，草稿按主机和会话隔离并可清除。未确认写入先查询权威结果或复用同一幂等标识，不自动创建新 Turn。SSE 复用[流式协议](../STREAMING_PROTOCOL.md)，按最后已应用事件恢复、去重；后台恢复重新核对认证、Turn 与终态。退出订阅不等于取消，停止生成必须发送服务端取消命令。

断网只允许已加载页面或内置壳编辑草稿，不默认建立业务离线写队列，也不承诺移动 Web 离线冷启动。增加历史缓存前须定义分类、期限、加密、删除和撤权传播。

手机是另一设备。`local_only` 来源及其派生输出不得因同一用户或同一 Wi-Fi 而外发；检查普通上下文、SSE、历史、日记、附件、检索和插件输出。未知来源旧记录默认拒绝，混合来源整体拒绝或走已评审的安全投影。清洁会话仍须由服务端逐 Turn/工具阻止私密上下文进入并持久化来源判断，不能信任客户端标记；跨会话汇集材料的既有日记不能因此自动开放。拒绝回归须覆盖“画像→普通回复→日记/工具结果→SSE/历史”及撤权后重连。

## 独立端验证与退出条件

独立原型须用测试库证明不依赖电脑的新会话、落盘、获准模型调用、流式展示、重启恢复和一次作答；实测移动 SQLite/FTS、文件、密钥、备份及迁移，保留 Schema/Repository 边界。后台调度必须持久化且可补偿，不能承诺桌面常驻 Worker 的时效。

Android 工程现已纳入版本控制，Web 构建和原生编译使用显式分开的命令；环境预检检查仓库 JDK、SDK platform、Build Tools 及可选设备，不安装工具或接受许可。Gradle 自动 SDK 下载关闭，默认拒绝明文网络和系统自动备份；模板资源、依赖、许可证和调试包构建边界见[移动工程说明](../../../apps/mobile/README.md)。默认原生入口已按上节装配内部 Transport，普通浏览器预览仍使用 API Transport；工程可生成或 APK 可安装都不能替代独立端闭环。

首个代码前置提供 `@aervox/core/browser` 中性出口，排除终端审批的 Node 静态依赖，保留现有 `.` 与 `./core` 终端兼容。整包浏览器构建、无 Node 全局的 VM Turn 和不带 ambient Node 类型的声明闭包有[回归证明](../../../packages/core/test/browser-entry.test.ts)；原有轻量出口的全部中性运行时符号另作兼容基线。这只证明内核入口可用于后续移动 Host，不包含本机持久化、原生密钥/模型桥、实际 WebView 或手机验收；现有 Fetch Provider 不能直接承载需要保留在原生侧的密钥。

现执行适配接续提供 `@aervox/host-agent/browser`：中性 `ConversationExecutionStore` 依赖明确的仓储 Port，原 `SqliteExecutionStore` 以兼容包装复用同一方法和真实错误身份。新入口的整包 VM 与构建声明闭包不依赖 Node、libsql、Drizzle 或 Vue；持久命令仍由宿主仓储实现。该边界只移除装配耦合，不能作为手机持久化、接单、问答或删除能力的替代证据。

独立运行不等于离线推理。模型调用仍经 Provider、安全检查和持久化，不由 WebView 持有模型密钥；本机推理另验内存、许可、温升、耗电和中断，`local_only` 不降级给远程模型。导入桌面资料显式选范围、备份和校验；同步不得复制活动 SQLite/WAL 或直接最后写入覆盖，另定冲突、墓碑、撤权与密钥协议。安装成功不能替代运行闭环证据。

## 验收、后果与回退

M0 的独立运行目标、Android 先行和隔离原型技术方案已接受。接续验证 Android 版本范围、实际设备/SDK/性能预算及凭据/普通内容合同，将原 `M-AC-01～09` 建议映射为正式验收。未获接受的其它备选路线仍不实施；技术方案接受不等于实现、设备或发布验收通过。

- 核心闭环覆盖消息身份与跨会话隔离、作答幂等、320 CSS px 回流、IME、键盘、安全区、放大字体、VoiceOver/TalkBack；已有 API E2E 不代替手机交互验收。
- 真机覆盖切网、锁屏、后台终止、重启、过期游标、主机休眠、取消与恢复；不得重复消息、计分或工具副作用。拒绝错误主机、失效证书、重放配对、过期/撤销凭据及混合来源泄漏。
- 主机删除后手机刷新失效；解绑清除本机内容和凭据，切换主机不串数据。原生权限拒绝不丢草稿，锁屏通知不显示正文；APNs/FCM 或中继需另行裁决。
