# ADR-024 原生计算、活动采集与进程边界

## 背景与方案

本记录合并原 CR-062/063 的已接受决策。维护者于 2026-10-12 批准先做有界代码搜索与合成向量对照，再扩展只读向量 Port、三平台活动 Provider 和声明进程主管；2026-10-13 批准原生源码与 IPC 结构收敛。

| 方案 | 决定与理由 |
|---|---|
| TypeScript 业务配合有界原生组件 | 采用；计算和进程资源可隔离，保留已有数据、授权和恢复责任 |
| 立即替换生产索引、SQLite、Electron 或 Core | 不采用；缺少端到端收益和迁移证据 |
| 为性能自行实现持久索引或压缩格式 | 不采用；优先与成熟扩展/库比较，无收益则保留 TypeScript |

## 数据与授权所有权

TypeScript 负责业务、授权、写事务、删除与最终召回资格；SQLite 保持业务真源。`@aervox/native-runtime` 负责有界异步 IPC、可信制品校验和可关闭生命周期；Rust 承接只读计算、应用活动元数据与声明进程树管理。默认检出不依赖预存二进制。原生进程、缓存和租约均不能成为授权或删除真源。

<a id="cr-062"></a>

## 有界搜索与测量

代码搜索采用锁定 npm 平台包分发的 `ripgrep`，不从用户 PATH 选程序，不运行期下载、不经过 Shell；保留字面匹配与原有过滤边界。调用者取消贯穿 MCP/HTTP 到子进程，截止、输出、文件和并发均受限，失败不得伪装为空结果。具体接口、限额与回归见[代码搜索合同](../agent-harness-loop.md#bounded-code-search)。

合成试点仅处理固定种子的 1 千、1 万、10 万条向量，不接入业务库。生产向量 Port 的采纳另比较真实 SQLite 读入、JSON 解码、TypeScript 全排序/有界 top-K、连续数组 Worker、Rust 冷/热 IPC 与成熟扩展，报告精度/候选一致性、内存边界、设备、样本和延迟分位数。纯计算加速不等于端到端收益；收益不足时保留负结果和 TypeScript 路径，不迁移生产 Schema。

<a id="cr-063"></a>

## 原生运行合同

- **向量**：仅显式本地库的只读连接，按模型缓存连续浮点数据，不复制业务正文；SQLite 提交、模型或文件变化使缓存失效，重启不复用旧缓存。宿主返回上下文前从真源复核来源资格；不一致时有界重试或失败，禁止返回旧缓存。详细数据合同见[数据库 §7.1](../DATABASE.md#71-只读向量缓存)。
- **活动**：仅当前应用标识、名称、PID；不采窗口标题、网址、命令行、按键或任意文件。macOS 使用 AppKit/真实 Accessibility 状态，Windows 使用前台窗口及受限进程查询，Linux 使用 X11/EWMH；Wayland 不支持时明确不可用，不以全进程列表冒充。
- **租约**：宿主每次采集核对设备、授权修订、来源 Grant、激活 epoch、期限、暂停/撤权；Helper 只持有内存短租约，到期、宿主退出或通道中断即停止，重启不恢复旧授权。窗口关闭后的运行必须已有后台授权，数据仍走 CAP-033 入库与删除链。
- **制品**：生产校验发行制品摘要与签名；开发测试豁免只能由宿主显式配置且不得用于打包态。OS 权限不能由开发豁免获得。
- **主管**：按版本化清单与参数数组启动 API/Worker/模型，同一数据目录只允许一个持锁主管；仅回收自己创建的 Unix 进程组或 Windows Job。端口冲突、就绪超时、异常退出及关闭均可见。模型角色不能同时由 API Driver 启动；升级、卸载或失败不删除业务目录。
- **其他计算**：音频仅可选预处理，识别仍用 `sherpa-onnx`；插件压缩无实测 Rust 优势则保留成熟库与有界 Worker。输入、格式、路径、配额、超时和取消约束不能因性能优化放宽。

<a id="cr-063-layout"></a>

## 原生源码与 IPC 结构

顶层 `native/` 使用共用锁文件的 Cargo 工作区，包含生产 runtime 与合成向量试点两个成员；保留依赖版本，TypeScript 与原生构建任务分离。TypeScript 公共出口及发行制品路径保持兼容。

`native/protocol/runtime.json` 是内部 IPC 唯一机读定义，包含方法、输入输出、错误码、版本和帧限额；只使用生成器支持的 JSON Schema 子集。Rust 嵌入同一文件，TypeScript 类型从中生成，双端执行共享正反夹具。公共 HTTP/OpenAPI 继续由 `packages/contracts` 管理。

协议维持 v1；宿主每个进程代际首次业务调用前验证握手，非法消息、错误结果形状、未知错误码明确失败。活动租约或采集请求验证失败即失效该实例授权；合法请求仍须授权及租约复核。生成漂移、协议不匹配、冷构建制品缺失和包外源码未触发验证均由门禁覆盖。

当前继续单一生产可执行文件，各宿主分别拥有进程实例。独立 Helper/主管发行仅在独立权限、签名身份或部署生命周期确有需要时另行决定，不把 CR-062 的早期候选当成无限扩展授权。

## 验证、发布与回退

验证覆盖外连接更新/删除、模型切换、资格过滤、错误 IPC/崩溃/超时，活动的无租约/错设备/修订/撤权/到期/重启，以及主管的重复归属、端口冲突、就绪失败和后代清理。三平台构建及可执行合同进入 CI；真实性能、OS 能力探测、桌面权限、签名/公证、安装升级与实机发行分别取证。实现和测量证据见 [PR #272](https://github.com/3yearsZhuang/Aervox-harness/pull/272) 与[运行指南](../../how-to/run-native-components.md)。

已实现组件不代表 Released；本决策不包括生产索引/数据库迁移、OS 系统服务注册或公开发布。关闭原生选项或移除制品后走 TypeScript/权威 SQLite 路径，停用 Helper 不恢复授权，主管仅停止自有进程。源码回退同时回退构建路径、增量输入与协议生成物，保留数据及旧制品，不涉及业务数据转换。
