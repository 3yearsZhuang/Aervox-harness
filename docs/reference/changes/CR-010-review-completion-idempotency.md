## 变更

- **原因**：复习完成事务能够避免重复调度，但客户端在网络超时后重试只能得到 404，无法确认第一次是否成功。
- **关联能力与需求**：`CAP-006`、`FR-REV-001`、`NFR-REL-001`。
- **目标行为**：首次完成在同一事务中保存判定、更新知识点、完成当前项并创建下一项；相同判定的重复请求返回首次结算结果，不重复写入；相反判定返回 409；用户可以查看租户隔离的最近完成记录及其下一复习项。
- **范围外**：IANA 时区日界线、DST、调度算法升级和历史重算。

## 验证与回滚

- **数据**：已完成复习项记录 `completionIsCorrect` 与 `nextReviewId`，用于精确重放。
- **API/UX**：完成响应显示下一项及 `schedulerVersion`；工作台提供“记得/忘了”，失败时提示使用相同结果重试，并展示最近五条完成记录。
- **验证**：API 集成测试覆盖首次完成、同结果重放、冲突重试、历史租户隔离、数量限制和下一项唯一性；数据库/API/UI 类型检查。
- **回滚**：停止写入并忽略新增可空列，恢复旧的非重放响应；不删除已产生的复习项。
