## 1. 变更背景与驱动因素

CR-032 已落地「插件声明、内核裁决、多端联动」的开放生态：触发规则可由插件声明、感知源两级授权、全局防打扰裁决器、主动回合调度与桌宠多端直推，并以出厂插件 `health-guard` 跑通全链路。然而在落地与实测过程中，暴露出当前架构在**终局形态**上的四类结构性天花板，以及一个产品级机会方向：

1. **感知是轮询快照，不是事件流**：剪贴板 3 秒、广域源 5 分钟、空闲状态 60 秒的拉式采样，经 captures→蒸馏→observations 管线后，规则引擎消费的是滞后数分钟的过期快照，且产生大量冗余观测（实测一次验证灌入 22 条空闲观测）。「时机型主动」（事件发生后秒级响应）在轮询架构下不可能实现；
2. **态势数据 N×M 耦合**：情报 Worker 派生十二类数据（时间线、项目、注意力、漂移、场景等）各自成表，规则引擎求值器必须逐表认知；每新增一类态势数据都要改一次求值器代码，插件生态的「零内核改动接入」承诺在态势维度不成立；
3. **规则即枚举**：五种 `triggerType` 各配一段硬编码求值逻辑，条件为松散记录。插件只能选用内核认识的类型，无法表达组合条件（如「在座超过 50 分钟且正在全屏演示则不提醒」）；
4. **防打扰是静态水位**：冷却 + 静音时段 + 每小时固定次数，不随用户反馈涨落，长期必然走向「要么打扰、要么失聪」的两极；
5. **人格分裂风险**：主动话术由独立组合器生成（仅装配插件 SKILL.md），与对话侧的人格管线（persona revision + 记忆召回）不同源，主动时的思隅和对话时的思隅可能不是同一个「人」。

同时，产品侧存在一个与主动智能天然契合的终局机会：**结构化操作域**（业界所称 computer use 的可靠子集）。感知侧已具备屏幕、应用、浏览器、剪贴板信号；授权体系已预建 `action.local/privileged/irreversible` 分级；Agent Loop 已有写工具审批通道；MCP 桥已落地。主动智能的终局不应止于「提醒你」，而是「看到机会 → 主动提议 → 人点头 → 执行 → 汇报」。

本 CR 作为**北极星基线文档**：确立主动智能的终局架构原则、分层设计与演进路线，供后续各批次 CR 拆片引用。本文不绑定具体交付批次，不携带实现级契约（那将由各演进切片的 CR 承接）。

## 2. 终局设计主张（北极星）

> **主动智能 = 态势感知内核 + 预算化干预通道。感知事件化，态势统一化，规则数据化，干预预算化，全程可解释。插件只提供数据（声明），内核只做引擎。**

分层视角：

| 层 | 职责 | 形态 | 谁可以扩展 |
|---|---|---|---|
| 感知层 | 把设备/应用/外部信号归一化为感知事件 | 桌面适配器 + MCP 事件源 | 平台适配器（内核）+ MCP 事件桥（生态） |
| 态势层 | 把事件流归约为统一态势投影 | 只读 SituationModel（白名单 schema） | 内核（schema 受治演进） |
| 规则层 | 对态势投影求值，产出触发候选 | 纯数据声明（受限表达式） | 插件与内置规则包，零内核改动 |
| 裁决层 | 授权闸、冷却、静音、预算执行 | 内核裁决器 | 仅内核 |
| 干预层 | 话术/动作生成与多端表现 | 人格化组合器 + 表现声明 + 操作提议 | 插件声明人格叠加与表现 |
| 账本层 | 不可篡改的决策与干预留痕 | 追加式事件账本 | 仅内核写入 |

## 3. 五大设计支柱

### 3.1 P1 感知事件化

- **现状**：适配器按固定周期采样并整批落 captures，蒸馏 Worker 周期扫描，信号到规则可见的延迟以分钟计；
- **应然**：适配器与 MCP 事件桥作为**事件源**，把信号归一化为带类型、主体与置信度的感知事件（如 `presence.continuous_active`、`app.frontmost_changed`），写入感知事件流；蒸馏、态势归约、规则引擎成为事件流的订阅者；
- **关键设计**：事件 schema 是本层的治权边界——新增事件类型走 schema 演进而非内核代码；原始快照仍按 CAP-0033 七天留存策略落 vault，事件流只携带派生事实；高节拍事件（空闲秒数）在源端做**边沿聚合**（状态变化才发事件），从源头消灭观测洪水；
- **收益**：时机型主动从不可能变为默认能力；观测噪声在源头消失；桌面采集与 Worker 解耦后各自独立演进。

### 3.2 P2 统一态势投影（SituationModel）

- **现状**：十二类派生数据各自成表，规则求值器逐表认知，耦合为 N×M；
- **应然**：每周期（或每事件批）把全部信号归约为**一个只读态势投影**——在场状态、专注/疲劳水位、近期承诺、漂移概况、当前场景、外部连接状态等——以版本化白名单 schema（`situation_model_v1`）暴露；
- **关键设计**：投影是**规则与 LLM 的唯一视野**：规则表达式只能引用投影字段，主动回合的提示词也只装配投影快照；投影 schema 的演进走受治流程，即 fail-closed 边界从「求值器枚举」上移到「投影 schema」；投影是纯派生物，可随时从事件流重建，不承担真源职责（真源仍是 vault 各表）；
- **收益**：N×M 耦合收敛为 N→1；「内置 4 规则」与插件规则在同一投影上等价表达，为内置规则数据化铺平道路。

> [!NOTE] F0 语义澄清（2026-09-14）
> 「SituationModel 是唯一视野」仅指**主动信号视图**：规则表达式与主动回合提示词只装配投影快照。
> persona revision、safety policy 与获准记忆引用走**独立的 `ContextManifest`**（见 ADR-017），
> 不并入投影白名单；投影只承载感知/态势信号，不承载人格、安全与记忆引用，避免 P2 与 P5 的语义冲突。

### 3.3 P3 规则数据化（受限表达式语言）

- **现状**：五种 `triggerType` 枚举 + 硬编码求值分支，条件为松散 record；
- **应然**：规则本体是一门**极小的确定性表达式语言**——只能引用态势投影白名单字段、纯函数、无 IO、无循环，形如受限 JSONLogic/CEL 的子集；内置规则与插件规则统一为数据声明；
- **关键设计**：fail-closed 从「类型枚举校验」升级为「表达式静态检查」——安装期做字段白名单与类型检查，运行期求值器对未知节点一律不命中；表达式语言冻结在极小集合（比较、逻辑、算术、时间窗函数），刻意不提供图灵完备性；
- **收益**：插件场景创新零内核改动；「在座超 50 分钟且全屏演示则抑制」这类组合条件可表达；规则可 diff、可解释、可导出。

### 3.4 P4 预算化干预（注意力预算）

- **现状**：冷却 + 静音时段 + 每小时固定水位，静态配置，不随反馈变化；
- **应然**：每个插件与全局各持有**注意力预算**——干预消耗预算，用户回应（点开、回复、执行提议）使预算回升，连续忽略使预算收缩直至该插件自然静默；预算模型输入包括回应率、时段敏感度、干预类型权重；
- **关键设计**：**预算的执行权永远在内核**——插件可以建议预算参数，扣不扣只能裁决器说了算；每次干预附带「回执」（为什么现在提醒、引用了哪些证据、消耗多少预算），落决策账本供用户随时查阅；静态水位与静音时段作为预算模型的兜底硬约束保留；
- **收益**：防打扰从「用户手动调配置」升级为「系统学习信任边界」，这是主动类产品长期不被关掉的关键；回执让 CAP-030 的「可解释」成为每个干预的内建属性而非事后补丁。

### 3.5 P5 人格同源

- **现状**：主动话术由独立组合器生成，提示词仅装配插件 SKILL.md 与证据快照，与对话侧人格管线割裂；
- **应然**：主动回合复用对话侧的**人格管线**（persona revision、记忆召回、安全门禁），插件的 SKILL.md 作为人格**叠加层**（场景指令）而非替代；主动话术与对话话术出自同一个「人」；
- **关键设计**：主动回合复用既有安全分类器前置门禁（危机内容一律走安全通道，主动场景同样适用）；主动回合的生成预算独立于对话回合计量，纳入 P4 干预预算；
- **收益**：桌宠的主动性是「角色性格在场景中的延伸」而非提醒机器人；安全语义全域一致。

## 4. 内核不变量（永不让渡）

以下四项是主动智能信任边界的基石，任何演进阶段、任何插件生态繁荣程度下都不得让渡给插件或外部代码：

1. **授权闸**：CAP-033 源授权 + 插件感知源授权的两层模型，未授权即切断事件输入（fail-closed）；
2. **预算执行权**：预算参数可被建议，预算的扣减与拦截只能由内核裁决器执行；
3. **决策账本**：触发、裁决、派发、干预、回执的留痕只能由内核追加写入，插件只读；
4. **local_only 处理边界**：感知与态势数据不出本机（CR-023 语义不变），导出权与撤销权语义不变。

## 5. 操作域方向（结构化操作域与 computer use 的关系）

定位一句话：**computer use 对 Aervox 不是要不要的问题，而是「手」长在哪的问题——手长在结构化 MCP 工具上，由主动智能提议、人点头执行。**

### 5.1 分级路径

| 级别 | 内容 | 信任等级 | 前置条件 |
|---|---|---|---|
| O1 结构化操作域 | 操作能力以 MCP 工具包提供：日历/提醒事项/备忘录/信息走系统脚本原语，浏览器走受控受管 profile，快捷指令作 runner；沿用 Home Assistant 集成的「服务白名单 + 实体默认禁用 + 逐项授权」模式 | `action.local` | 操作域工具包 CR 立项 |
| O2 操作目录进态势投影 | 「此刻可执行的操作清单」成为态势投影字段；主动智能从「提醒你」升级为「看到重复性机械操作 → 提议代劳」 | `action.local` | P2 落地 |
| O3 主动提议闭环 | 提议走既有 proactive_actions 账本 + 写工具审批通道；桌宠点头/摇头 + 气泡确认作为审批界面；执行结果回执入账本 | `action.local`（不可逆类逐项确认） | O1 + O2 + P4 |
| O4 像素级自主操作（远期，可选） | 仅当结构化原语覆盖不到时评估；前置条件：屏面内容注入防御专项设计（感知内容一律按数据对待）、`action.privileged` 显式签署、操作沙箱与逐步确认 | `action.privileged/irreversible` | 专项 CR + 安全评审 |

### 5.2 设计红线

- 感知内容（屏幕、网页、消息）**永远是数据，永远不是指令**——注入防御在 O1 起就按最高标准执行，而非留到 O4；
- 不可逆操作（删除、发送、支付类）无论哪一级都强制逐项人工确认，永不进入「自动执行」；
- 操作能力由插件贡献时（清单 `spec.mcpServers` 已预留），工具清单走与感知源同构的两级授权；
- 桌宠审批界面（CAP-019）是操作域的默认确认面，但确认语义与弹窗确认等价，不做「免确认」的便利模式。

## 6. 当前行为 vs 目标行为

| 维度 | 当前行为（CR-032 落地后基线） | 目标行为（本 CR 终局形态） |
|---|---|---|
| 感知 | 周期轮询采样，批式蒸馏，分钟级延迟 | 事件流驱动，边沿聚合，秒级可见 |
| 态势 | 十二类派生表各自为政，求值器逐表认知 | 统一只读态势投影，白名单 schema 单点治权 |
| 规则 | 五类枚举 + 内核硬编码求值 + 内置 4 规则硬编码 | 数据化规则（受限表达式），内置与插件规则同构 |
| 防打扰 | 静态冷却/静音/水位 | 学习型注意力预算 + 回执，静态约束兜底 |
| 话术人格 | 独立组合器，SKILL.md 即全部人格 | 对话人格管线同源，SKILL.md 为场景叠加 |
| 执行体 | 仅话术与表现（无动作） | 结构化操作域：提议 → 确认 → 执行 → 回执 |
| 可解释性 | 触发事件与抑制原因留痕 | 全链路回执：证据、预算、替代方案可随时查阅 |

## 7. 演进路线（各片独立立项、独立验收）

| 阶段 | 内容 | 性质 | 验收要点 |
|---|---|---|---|
| E1 | 态势投影抽取 + 内置 4 规则数据化：Worker 先产出 `situation_model_v1` 投影，内置规则改写为对投影的数据声明（行为不变），CR-032 规则引擎改为消费投影 | 纯重构，无行为变化 | 既有全部测试不修改即通过；投影 schema 契约测试；影子对比（新旧求值结果一致） |
| E2 | 规则表达式语言 + 注意力预算：受限表达式解析与静态检查替换类型枚举；预算模型替换静态水位（静态约束降级为兜底） | 行为增量 | 表达式 fail-closed 测试（未知字段/节点拒绝）；预算涨落的可复现测试；回执字段落账本 |
| E3 | 感知事件化：桌面适配器与 MCP 事件桥产出归一化事件流，蒸馏与态势归约改为订阅者；源端边沿聚合 | 架构迁移 | 事件延迟预算（信号到规则可见 ≤ 数秒）；观测数量对比（洪水消失）；旧管线保留至双跑验证后移除 |
| O1 | 操作域 MCP 工具包：第一组系统操作原语 + 白名单授权面 | 新能力 | 白名单外操作拒绝；不可逆操作强制确认；授权面走 CAP-033 同构模型 |
| O2 | 主动提议闭环：操作目录进投影 + 提议/确认/执行/回执链路 | 新能力 | 提议消耗预算且可被静默；确认语义与弹窗等价；全链路回执可查 |

排序原则：E1 → E2 → E3 为主干（每步建立在前一步之上）；O1 可与 E2 并行启动（不依赖事件化）；O4 永远不在本 CR 范围内承诺。

## 8. 受影响模块与契约面（终态视图）

- `@aervox/contracts`：态势投影 schema、感知事件 schema、规则表达式 DSL、预算与回执类型、操作目录与提议类型；
- `packages/schema` + `packages/repositories`：感知事件流存储、态势投影快照、预算状态、回执账本（vault 侧；均遵循追加式与加密约定）；
- `apps/worker`：态势归约器、表达式求值器、预算裁决器、蒸馏器订阅化改造；
- `apps/desktop`：适配器事件化改造、边沿聚合、操作域 MCP 桥、桌宠审批界面；
- `apps/api`：主动回合人格管线复用（对话模块 persona 管线开放给主动调度）、SSE 直推通道扩展；
- 插件面：清单 `spec.proactive` 的规则字段升级为表达式；`spec.mcpServers` 转正为操作/事件贡献通道。

## 9. 范围外

- O4 像素级自主操作的任何实现承诺（本 CR 仅登记其前置条件与红线）；
- 云端感知、多设备态势同步、多用户共享画像（与 CR-023 local_only 边界冲突，方向性排除）；
- 主动智能设置 UI 的插件化（当前保留为工作台内置分区，未来可另行评估用 CR-006 Page 机制承载）；
- 任何 LLM 供应商侧的功能依赖（一切以本地/自备端点为前提）。

## 10. 安全、隐私与信任影响

- **注入防御前移**：操作域从 O1 起即执行「感知内容一律为数据」的最高标准，不留到 O4；
- **预算即隐私**：预算模型输入仅为本地行为统计（回应率、时段），不引入任何外部信号；预算与回执数据落 vault，随导出权与撤销权一并交还用户；
- **人格同源的安全一致性**：主动回合复用对话侧安全分类器门禁，杜绝「对话侧有安全门禁、主动侧没有」的旁路；
- **账本不可篡改**：回执与预算变更加入决策账本，用户可完整追溯「它为什么做这个决定」——这是 CAP-030 可解释性验收的终局形态；
- **操作域信任梯度**：结构化原语（可枚举、可白名单、可回滚）先于像素原语（不可枚举、不可回滚），信任升级与能力升级同向。

## 11. 风险、成本、灰度与回滚

| 风险 | 缓解 |
|---|---|
| 事件化改造动桌面采集与蒸馏管线，动静最大 | E3 放在主干最后；旧管线双跑对比后才切换；事件 schema 先行冻结 |
| 表达式语言设计过度（走向图灵完备） | 语言集合冻结在最小子集；任何扩充走本 CR 的修订而非顺手加 |
| 预算模型误学（好插件被静默、劣插件骚扰依旧） | 静态兜底约束永不移除；预算对用户可见可手动锁定；学习速率保守起步 |
| 人格同源引入对话管线的延迟与失败面 | 主动话术保留模板降级通道（CR-032 语义不变）；生成预算超时即降级 |
| 操作域误操作 | 白名单 + 默认禁用 + 不可逆逐项确认；全部操作过账本与审计 |
| 各阶段周期长、跨多批次 | 每片独立立项独立验收，任何一片停滞不影响已落地片的价值 |

回滚原则：E1 为纯重构可整体回退；E2/E3 各引入 Feature Flag（表达式引擎与事件流管线可开关回退到 CR-032 基线行为）；O1/O2 的操作能力以授权面为总开关，撤销授权即全域停用。

## 12. 与既有基线的关系（差量单声明）

- 对 **CR-023**：local_only 边界、两层授权、七天留存、导出/撤销权**全部继承不变**；本 CR 是其上的形态演进；
- 对 **CR-032**：插件声明、两级感知源授权、裁决器骨架、账本、SSE 直推**全部继承**；差异仅在于裁决器输入（投影与预算）、规则形态（数据）与话术来源（人格管线）；
- 对 **AVX-SRS-002**：FR-PRO 系列与 SEC-PRO/PRIV-PRO 语义不变；FR-PRO-013 派生能力将成为态势投影的输入而非独立终点；
- 对 **CAP-030**：本 CR 的 P4 即其「频控、免打扰、可解释」验收的终局实现路径；
- 对 **CAP-034/035**：外部连接事件在 P1 中成为一等事件源，集成模式不变。

后续各演进切片立项时，以本 CR 为引用基线，各自携带实现级契约与验收细节。
