# CR-061 内核执行合同与五阶段审核整改

## 1. 决策与范围

维护者于 2026-10-08 授权按本次代码审核落地五个迭代。取号已核对归档仓库，归档最大编号为 CR-059，主仓已有 CR-060。本提案承载恢复与模型合同差量；当前执行顺序与移交状态只维护在[根计划](../../../plan.md)。

维持 ADR-021 的零运行时依赖、库与宿主分离、本地单用户及现有部署。数据库 Schema、持久化终态枚举、公开 SSE 事件形状不变。公开软件包发布与生产数据库操作另行决策。

## 2. 行为差量

- 工具派发在审批后重新核对取消与租约。工具超时保留明确分类。API 复用内核工具运行时，插件禁用和调用者信号在执行边界重新验证。
- 模型截断、过滤、不完整工具参数与异常结束均拒绝工具批次；完整文本前缀可显示，终态为未完成。模型能力、窗口与用量由 Provider 合同表达，本地进程生命周期由宿主管理。
- 下一步指令进入实际模型请求。动态工具使用受权声明快照，执行时复验。最终模型输入与预留输出共同校验窗口；无法容纳时明确拒绝。
- 规则压缩按完整工具组选择，保留系统约束并明确说明历史被省略，不声称生成了摘要。真实摘要仍通过压缩 Port 注入。
- 正文以有界窗口提交，取消和租约丢失能终止静默源等待；重试不得重复已提交正文。
- 恢复裁决检查完整账本、最新意图及持久事件上界，逐执行标识关联结果。仅确定结果可进入宿主续跑；未知结果、审批待决和撤权均拒绝自动续跑。
- 基准记录首段可见、取消、资源上限及 SQLite 写竞争。稳定包入口与内部实现分开，提供兼容说明，不触发公开发布。

## 3. 验证与回滚

自动化用例覆盖 core、API 和 SQLite 适配，检查实际副作用与模型请求，包含取消/丢租约、截断、门控缺失、父子控制、收件箱、工具配对、事件高水位与慢源。运行完整代码和文档门禁、headless 冒烟及可重复负载基准。

失败时回退本分支代码；恢复接线以 `AERVOX_LOOP_RESUME=local-results` 显式启用，只由本机模型补完已知工具结果的正文，禁止新工具和回合插件钩子；停用后保持既有失败收敛。没有历史数据转换，无需换库。截断输出和未知副作用不得在降级时自动重试。
