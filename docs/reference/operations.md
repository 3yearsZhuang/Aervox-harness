# Aervox｜思隅 本地运行与演练手册

- 提出人：3yearszhuang · 2026-08-26
- 修改人：3yearszhuang · 2026-10-04

关联：[架构设计](ARCHITECTURE.md) · [数据与隐私](DATA_PRIVACY.md) · [威胁模型](THREAT_MODEL.md) · [换库与回滚演练](../how-to/run-database-migration-drill.md)

本文覆盖 Aervox 纯本地单用户部署形态（CR-030 后）的故障止损/恢复/验证、模型与侧车运维和演练留证。原 SaaS 值班/灰度章节（多用户升级矩阵、按比例灰度、云灾备 RPO/RTO 目标）已随本地化转型移除，历史文本可从 Git 历史回溯。日记与删除的语义规则分别以 [SRS](SRS.md) 与 [数据库契约 §8](DATABASE.md#8-删除撤权与恢复) 为真源，本文只保留运维处置动作。

## 1. 运行服务与观测口径

| 服务 | 职责 | 关键观测 |
|---|---|---|
| API（Fastify 5，默认 loopback:3000） | 会话/Turn/SSE、领域路由、插件与工具运行时 | `GET /v1/metrics`（Prometheus 文本/JSON）、`http.request.completed/error` 日志、审计落库 |
| Worker（独立进程） | outbox/review/diary/deletion/embedding/attempt-recovery/proactive 等 10 个任务 | 任务完成日志、outbox 积压、DLQ 计数、退避状态 |
| model-runtime 侧车（llama.cpp） | 本地模型推理（OpenAI 兼容端点） | `/health` 就绪、`/metrics` 采样、下载与启动状态 |
| SQLite 主库（WAL） | 业务真源 + Outbox + FTS5/向量 | 文件大小、WAL 增长、busy/换连接自愈计数 |
| proactive Vault / RecoveryControlLedger | 加密画像库 / 独立控制账本 | Vault 可用性、账本 sequence 连续性 |
| 桌面端（Electron）/ Web / CLI | 客户端形态 | 连接诊断（`siyu doctor`）、SSE 心跳 |

## 2. 事件处置流程

当前为单维护者运行，无值班轮换；处置纪律不变：

1. 确认影响范围、开始时间、版本和最近变更（`git log`）；
2. 优先止损：关闭非核心任务、熔断受影响模型/供应商、停用插件、进入只读；
3. 保留最小审计证据，不把完整用户内容复制到工单或聊天；
4. 恢复后验证业务事实、来源链、删除状态和监控；72 小时内完成复盘并登记 `CR/RISK`。

严重度：`SEV-0` 数据不可逆损坏/泄露/危机响应失效；`SEV-1` 核心闭环不可用或删除链失效；`SEV-2` 局部功能/供应商降级；`SEV-3` 低影响缺陷。涉及用户数据外泄风险一律按 `SEV-0/1` 处置并通知数据主体。

## 3. 模型 Provider 故障

- 触发：远程供应商超时/5xx/限流超过路由阈值、质量门槛回归或供应商安全事件；本地侧车 `/health` 探活失败。
- 远程动作：按既有降级阶梯（CR-034/CR-042，已归档）切换已评估备用模型；无备用时保留输入并提供重试/历史只读。
- 本地侧车动作：`GET /v1/model-runtime/state` 查看状态；异常时 `POST /v1/model-runtime/stop` 后重新 `start`；启动失败先检查模型文件完整性与磁盘空间，再查端口占用。模型下载中断依赖 `.part` 原子落盘恢复，不产出损坏制品。
- 不得：跳过输入/输出安全分类、使用未评估模型、把失败输出写入记忆/日记/掌握度。
- 验证：ModelRun、路由比例、TTFT、事实/安全抽检、成本；恢复需渐进放量。

## 4. Outbox 积压与 Worker 异常

- 暂停非核心生产者和重复重放；保留 API 核心写入及 SQLite Outbox。
- Worker 与 API 通过本地 Domain Socket IPC（`wake`/`pressure`）协同；IPC 失联时轮询兜底，重启 Worker 即恢复注册。
- 恢复后按 Outbox 水位重建任务；使用幂等键，检查每个 `localDate` 标签最多一个自动日记身份、复习活动项唯一和删除任务状态。
- DLQ 重放前检查权限/删除状态/版本，过期或撤销任务标记取消，不再次调用供应商。
- 验证 outbox 未消费数、重复业务结果和退避日志（长时间 `SQLITE_BUSY` 或持续换连接说明超出单写者负载边界，见 ITER-027 压测口径）。

## 5. SQLite 故障与备份恢复

- 进入只读/维护状态，停止 Worker 写入；保护当前 WAL/备份证据。
- 按备份清单（manifest + SHA-256 + 逐表行数）选择恢复点，在隔离环境恢复并运行完整性/迁移检查。
- `RecoveryControlLedger` 是独立故障域的 deny 控制事实源。先在全局 deny/维护状态校验签名、序列连续性、最老备份覆盖范围和业务应用水位；水位缺口、账本不可用或 reconciliation 未完成时保持 fail closed，不开放流量。按 `sequence` 幂等重放删除、撤销的 ConsentGrant、插件权限和外部授权，再重建 Outbox 派生状态、FTS 索引和派生投影。
- 破坏性迁移与原子换库按[换库与回滚演练](../how-to/run-database-migration-drill.md)执行：停写、备份、staging 校验、原子换库、保留回滚包。
- 冒烟验证 loopback/认证与数据目录权限、`actorId`/Grant、学习记录、日记唯一性、记忆来源、导出和删除后零召回。

## 6. 本地附件/导出文件事件

- 立即暂停读取/解析；检查文件版本、扫描状态和来源范围。
- 从可信副本恢复时校验 checksum，重新运行病毒/OCR/来源处理；已删除对象不能恢复为可见状态。
- 对外泄风险按 `SEV-0/1` 处置，并触发安全/隐私通知流程。

## 7. 删除传播失败

- DeletionRequest 一旦接受，来源保持 deny，无论后台状态如何。
- 定位失败的 DeletionTarget（DB、Outbox、FTS、向量、本地文件目录、Diary/Memory、供应商、备份）；重试不得恢复访问。
- 超过删除 SLA 按 `SEV-1` 处置并同步用户可见状态；外部供应商按合同升级。
- 完成后运行零召回、对象清单、树投影 diff 和导出缺失状态检查，证据回填请求。

## 8. 日记/记忆流水线异常

规则语义以 [SRS `FR-DIA-001`](SRS.md) 与 [ADR-011](adr/ADR-011-diary-cycle-schedule-revision.md) 为准，本节只列处置动作：

- 日记重复：以 `(localDate, autoGenerated)` 唯一身份核对，保留合法版本并标记异常运行，不删除用户编辑；
- 日记迟到/未生成：核对 `DiaryCycle` 窗口与 cursor 是否推进，检查 Worker diary 任务日志；失败进入可见状态与 DLQ，不静默跳过；
- 记忆过度压缩/虚假事实：关闭高层晋升和树召回，保留临时/短期来源，回滚算法/Prompt，重建受影响投影；
- 来源不可追溯：立即隐藏相应日记段落/记忆节点并阻断发布/召回。

## 9. 发布与回滚

- 发布前：备份/迁移验证、Eval、OpenAPI diff、许可证/安全扫描和回滚命令确认。
- 本地分发通过 tag 触发桌面打包流水线（`electron-builder`，Release 附件）；无灰度概念，发布即全量，回滚靠用户重装上一版本安装包。
- 应用回滚不能把数据库回滚到丢失新数据的状态；使用 expand/contract 与兼容开关。不可逆迁移为发布阻断。
- 桌面端当前无签名/公证/自动更新通道（CAP-018 发布门禁未闭合），分发范围限开发者自装，不得对外承诺升级能力。

## 10. 演练与证据

每季度演练：SQLite 备份恢复与完整性校验、`RecoveryControlLedger` 账本不可用/缺口/重复/乱序及 reconciler、Outbox 队列重放、本地附件恢复、CR-030 换库与回滚（步骤见[换库演练指南](../how-to/run-database-migration-drill.md)）、模型供应商中断与侧车重启、磁盘满与端口占用、删除传播、插件 kill switch 和日记跨 DST。记录日期、环境、版本、账本水位、fail-closed 结果、偏差和改进项；没有演练证据不能通过 G5，证据记录用 [§12 演练证据模板](#12-季度恢复演练证据模板)。

## 11. 事件分级与升级

单维护者运行下无多角色升级矩阵；保留分级用于自评与留痕：

| 级别 | 定义 | 典型示例 | 处置时限（自评） |
|---|---|---|---|
| `SEV-0` | 数据不可逆损坏/泄露/危机响应失效 | 删除后数据复活、凭据泄露 | 立即止损，当日复盘 |
| `SEV-1` | 核心闭环不可用或删除链失效 | API 不可启动、删除传播超 SLA | 当日 |
| `SEV-2` | 局部功能或供应商降级 | 单模型降级、队列积压 | 计划内修复 |
| `SEV-3` | 低影响缺陷 | 可计划修复的缺陷 | 下个迭代 |

涉及用户数据的工单/记录不得复制完整正文（见[数据与隐私](DATA_PRIVACY.md)）。
