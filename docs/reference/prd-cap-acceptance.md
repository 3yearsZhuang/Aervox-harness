# Aervox｜思隅 产品能力验收标准附录（P1/P2/P3 与专项能力）

- 提出人：3yearszhuang · 2026-08-26
- 修改人：3yearszhuang · 2026-09-13

关联文档：[PRD 主文档](PRD.md) · [需求追踪与交付基线](REQUIREMENTS_TRACEABILITY.md) · [软件需求规格（SRS）](SRS.md) · [文档索引](../README.md)

本文件从 [PRD 主文档 §6.9](PRD.md#69-能力验收标准附录索引p1p2p3-与专项能力) 拆分而来，归档 P1、P2、P3 及专项能力（CAP-033 全域感知、CAP-034 Home Assistant、CAP-035 运动健康）的最低可验收结果与原则。所有能力进入开发批次前，必须在[需求追踪基线](REQUIREMENTS_TRACEABILITY.md)中从 `Mapped` 推进至 `Ready`，补齐原子需求与可执行测试。

<a id="prd-cap-014-019"></a>

## 1. P1 差异化能力的验收原则

P1 需求不得只增加“更聪明的回答”，必须形成用户可感知、可回溯的学习收益：

| 能力 | 最低可验收结果 |
|---|---|
| CAP-014 层级对话与会话地图 | 每个术语、追问和分支定位到真实来源消息或学习尝试；分支创建、合并、返回主线和删除影响均可操作；布局数据丢失不会丢失会话内容 |
| CAP-015 思维宇宙 | 每条知识关系显示来源、关系类型和置信状态；用户可合并、拆分、纠正或删除；被纠正的关系立即停止用于讲解和推荐 |
| CAP-016 自适应刷题与报告 | 难度调整可解释为正确率、耗时、提示次数和复习结果；报告区分观测与推断；用户可重置推断但保留原始作答记录 |
| CAP-017 考试日计划 | 可修改日期、范围、休息日和可用时间；滚动调整不删除已完成记录；预测无法完成时展示取舍和降级计划，不制造情绪压力 |
| CAP-018 桌面化与 Live2D | Windows/macOS 核心闭环与 Web 数据一致；通知、置顶、开机启动、麦克风/屏幕等权限逐项授权；退出后不保留未经同意的后台进程 |
| CAP-019 多人格模板 | 人格切换仅影响表达、外观和互动节奏；安全、事实判断、权限与学习数据不变；跨人格记忆默认隔离，共享前显示范围并取得确认 |

## 2. P2 连接与智能化的验收原则

| 能力 | 最低可验收结果 |
|---|---|
| CAP-020 技能与插件系统 | 安装前展示发布者、版本、签名、所需权限和数据范围；默认无网络/文件/记忆权限；可逐项撤销、一键禁用/卸载；插件失败或越权不阻断核心流程；插件配置可在设置中按声明式 Schema 可视化编辑（secret 不回显），插件 Page 通过受限 iframe 打开（[CR-006](changes/CR-006-plugin-config-and-pages.md)） |
| CAP-021 学习路线与视频推荐 | 每项推荐显示来源、适用目标、更新时间和推荐理由；失效内容可报告；用户可关闭个性化并删除推荐历史 |
| CAP-022 兴趣分析与跨域推荐 | 仅使用已授权行为；每个推断可查看依据、纠正和关闭；敏感属性、危机内容和脆弱状态不得用于商业推荐或定向 |
| CAP-023 第三方刷题接入 | 授权范围、同步方向、最近同步和冲突状态可见；重复导入幂等；撤销授权后立即停止同步，并允许删除或保留已导入副本 |
| CAP-024 文献阅读与发散 | 结论和引文可定位到页码/段落；解析不确定时明确标记；导入内容不能通过 Prompt injection 获得工具或用户数据权限 |
| CAP-025 线下试卷扫描 | 用户可检查和修正分题、OCR、答案与批改痕迹；低置信识别不自动进入错题/掌握度；原图和派生数据可分别删除 |
| CAP-026 收藏空间与知识库 | 对话、网页、文件和笔记统一检索且保留来源、许可和更新时间；删除来源后索引、摘要和向量按规则失效；支持标准格式导出 |
| CAP-027 本地数据主权与可移植性 | SQLite 本地单用户真源；提供可读导出、一致性备份、恢复演练、版本兼容和显式破坏性迁移；多范围旧库必须选择保留范围且未选数据留在备份/导出包 |

## 3. P3 生态与规模化的验收原则

| 能力 | 最低可验收结果 |
|---|---|
| CAP-028 社区互助 | 发布、编辑、举报、屏蔽、审核、申诉和下架状态完整；公开前预览脱敏结果；未成年人进入前必须启用独立年龄、私信和监护策略 |
| CAP-029 名词解释网页 | 仅发布用户逐项确认的内容；页面显示作者、来源、更新时间、版本和 AI 参与程度；撤回后链接失效，搜索缓存按 SLA 清除 |
| CAP-030 主动提醒深化 | 每条提醒显示触发原因；提供频率上限、免打扰、暂停和一键关闭；危机、脆弱状态或长期未使用不得用于内疚、焦虑或排他式召回 |
| CAP-031 内容与技能市场 | 上架前完成身份、版权、权限、安全和质量审核；版本、价格、退款、分成、下架和已购用户兼容策略可执行；恶意技能可全局停用 |
| CAP-032 机构与监护模式 | 组织角色和字段级可见范围可配置且默认最小；完整私人对话、情绪和日记默认不可见；成员可查看授权记录、退出组织并导出个人数据 |
| CAP-033 全域感知与个人画像（主动智能模式） | 用户先开启完全访问，再明确确认版本化全量画像授权包；当前平台所有可用来源和主动动作均显示授权范围、OS 回执和运行状态；支持开机自启、应用退出后常驻、休眠/重启恢复并告知用户；原始副本按 7 天窗口保留，完成记忆提炼后才清理；画像、记忆、授权、动作和审计均在本地持久化且可导出、纠正、暂停、撤权和删除 |
| CAP-034 Home Assistant 家庭环境连接 | 用户可连接私网/回环/`.local` HA 实例；实体默认禁用，逐项授权读取与允许的 service；状态变化可进入本地时间线，写操作同时校验当前主动动作授权、实体和服务白名单；撤销删除 Token 与实体缓存 |
| CAP-035 运动健康信号连接 | 用户以自有且获准的官方开放平台配置同步按日步数、睡眠和静息心率；Token 不回显、不导出、不进模型；健康指标按敏感级别本地保存，支持只读工具、同步状态和连接级撤销删除 |

所有 P1-P3 能力进入开发前，必须在需求追踪文档中由 `Mapped` 提升为 `Ready`，补齐功能需求、异常路径、权限、数据生命周期、验收条件、测试和负责人。能力地图中的存在不等于已经完成需求规格。

## 4. 其他 P0 能力的最低验收

| 能力 | 最低可验收结果 |
|---|---|
| CAP-001 桌宠入口 | 首屏可在一个操作内进入继续学习、今日复习或新对话；角色资源加载失败时展示可操作降级界面；状态和提醒不遮挡学习内容或无障碍焦点 |
| CAP-010 人格问卷与基础偏好 | 用户可跳过问卷并使用中性默认值；每项偏好可单独修改/重置；修改只影响后续表达和提醒，不更改历史事实、安全策略或数据权限 |
| CAP-011 学习资料整理 | 生成资料区分模型生成内容与外部引用；引用可定位来源；无法验证的事实明确标记；用户可编辑、导出、删除且删除会传播到检索索引 |
| CAP-012 多模态答疑 | 上传前展示允许格式、大小和用途；解析结果可预览/裁剪/纠正；低置信或失败时不臆测题目，并提供重传或转文字路径；附件可独立删除 |
| CAP-013 消息编辑、删除与引用 | 编辑产生版本并保持引用可解释；删除前展示对摘要、错题、日记和记忆的影响；删除后立即停止召回，异步完成派生数据重建 |

CAP-005 的完整验收见 [PRD §7](PRD.md#prd-cap-005)；CAP-009 除本节外还必须满足 [PRD §6.7 与 §7.6](PRD.md#prd-cap-009) 和 AI 质量规范。任何 P0 能力进入发布范围时，同样须在追踪矩阵达到 `Ready` 并关联测试证据。

## 5. 全域感知与个人画像（CAP-033）

**用户故事**：作为希望获得持续主动帮助的用户，我可以单独授权 Aervox 使用设备上全部可用的个人来源并执行授权动作，以便系统在本地理解我的使用/操作习惯、整理私人资料并主动协助我。

**最低可验收结果**：

- 用户必须先开启 `full_access`，再在独立向导中确认版本化 `full_profile_v1`；向导列出当前平台全部可用来源、动作范围、后台生命周期、七天原始副本策略和本地处理承诺，取消或失败不得产生生效授权；
- 授权包覆盖当前平台可提供的应用/窗口/进程、浏览器、键鼠/输入、剪贴板、屏幕、可读文件/目录、通信、音视频、位置/传感器及用户选择的健康/情绪等私人资料，并保留每项 OS 授权回执、版本和撤销状态；
- 授权后允许开机自启、应用退出后常驻、休眠恢复和重启自动恢复；启用前、恢复时、状态变化和异常必须向用户告知并在界面显示；
- 允许用户授权本地文件修改、浏览器/家居控制、外部消息和其他声明动作；动作必须绑定当前授权修订、目标范围和执行结果，用户可撤销，系统不能由模型自行扩大范围；
- 原始屏幕、音频、输入、剪贴板和文件副本按每个捕获时间保留七天，只有成功提炼为用户记忆后才可物理清理；用户主动删除可以提前触发删除，记忆仍保留来源和授权溯源；
- 画像推断区分观测、推断、用户陈述、已确认和拒绝状态，展示证据并允许纠正；确认后的记忆、画像、授权、动作、触发和审计历史全部在本地持久化；
- 用户可以随时暂停、撤销单个来源/动作或关闭整个能力，立即停止后续读取、召回和动作，查看清理进度，并导出原始副本、画像、记忆、授权和动作历史。

CAP-033 依赖并关联 `CAP-002/005/007/008/009/010/012/013/018/020/022/023/024/026/027/030`；它是独立生命周期能力，不把上述能力的状态或权限静默扩大。完整画像仍受操作系统访问控制、本机 API 边界、来源授权、删除权和导出权约束。

CAP-033 的本地派生层必须提供十二项能力：统一个人时间线、项目与意图图谱、操作流程学习、情境主动触发、计划/执行/验证、画像冲突纠正、主动准备包、注意力与疲劳模型、行为漂移检测、关系与沟通上下文、本地场景模型、每日与每周回顾。每项结果保留来源修订并可在本地仪表盘查看和导出；无证据时显示空状态，不伪造画像。

<a id="prd-cap-034"></a>

## 6. Home Assistant 家庭环境连接（CAP-034）

**用户故事**：作为主动智能用户，我可以连接自己的 Home Assistant，并精确选择 Aervox 可读取和控制的实体，以便系统理解家庭环境并执行获准的家居操作。

**最低可验收结果**：连接仅接受私网、回环或 `.local` 端点并拒绝重定向；Token 加密存储且不回显；实体同步后默认禁用，用户逐项启用并配置 service 白名单；状态事件仅对授权实体进入本地时间线；写操作必须通过 `action.external`、实体与 service 三重校验并记录结果；撤销后停止订阅并删除凭据与缓存。

<a id="prd-cap-035"></a>

## 7. 运动健康信号连接（CAP-035）

**用户故事**：作为主动智能用户，我可以连接自己有权使用的小米运动健康开放平台配置，以便系统在本地结合活动与睡眠信号调整提醒、准备和回顾。

**最低可验收结果**：只使用用户提供且有权使用的官方开放平台 API，不使用逆向私有协议；支持 Access Token/Refresh Token；只保存每日步数、睡眠分钟和静息心率及最小元数据，不保存完整供应商响应；步数为低敏，睡眠与心率按 Restricted 处理；提供按日只读工具；撤销连接删除凭据与健康样本。厂商审批、账号资格和 API 可用性由用户配置决定，产品不得显示为 Aervox 已获厂商授权。
