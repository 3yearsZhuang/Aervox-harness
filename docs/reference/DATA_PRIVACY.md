# Aervox｜思隅 数据与隐私规范

关联文档：[PRD](PRD.md) · [架构设计](ARCHITECTURE.md) · [AI 质量与安全](AI_QUALITY_SAFETY.md) · `CR-023`（已归档） · `CR-030`（已归档）

本文定义数据用途、分类、授权、AI 召回期限、用户可见保留期限、删除传播、导出和审计基线。目标地区和正式保留期限须在上线前经安全/隐私与法务评审批准；下表中的默认值是工程设计基线，不替代地区法律意见。

## 1. 核心原则

1. **用途限定**：为回答、学习记录、复习、记忆、日记、分析或安全分别取得必要权限，不以“一次同意”覆盖未来用途。
2. **最少数据**：模型上下文只包含完成当前任务必要的信息；日志、分析和审计不复制完整私人内容。
3. **召回与保留分离**：AI 何时不能再使用某条内容，与用户何时不能再查看历史是两套期限。
4. **事实与派生分离**：消息/作答是来源；摘要、掌握度、记忆树、Embedding 和日记是派生数据，必须保留来源和失效关系。
5. **即时禁用、异步清除**：撤销或删除后立即禁止模型、检索和插件继续使用；物理清除可异步，但有 SLA、重试和审计。
6. **用户拥有控制权**：查看、纠错、导出、锁定、忘记、删除和退出不能依赖客服或模型判断。
7. **默认私人**：学习数据、记忆和日记默认不公开、不出售、不训练；分享必须逐项发起并预览。
8. **全量画像需独立确认**：CAP-033 可以由用户一次确认当前版本的全量来源、后台生命周期和主动动作，但每项 source/purpose/action 仍保留独立授权、用途、审计和撤销记录；「完全访问」不是该同意的替代物。
9. **外部连接凭据与内容分离**：CAP-034/035 的 Token、Refresh Token 和 Client Secret 只存本地加密 Vault；模型、日志、分析、导出和普通 API 响应只能看到脱敏连接状态与已授权的规范化结果。

## 2. 数据角色与范围

- **本地用户**：产品数据归属于当前操作系统用户的数据目录；同一数据库不服务多个不互信用户。
- **数据目录**：业务数据库、Vault、恢复账本、迁移状态和备份使用用户私有目录；多操作系统用户必须使用不同目录和 ACL。
- **处理者/供应商**：身份、模型、通知、分析和错误监控供应商须建立清单，记录用途、数据地区、保存策略、子处理者、删除能力和合同状态；当前部署形态为本地单用户，除用户显式配置的模型/语音/外部连接供应商外不存在其他处理者。
- **远程访问者**：默认不存在；非 loopback 访问必须由用户显式启用并使用 token 认证，不提供组织管理员浏览入口。
- **插件/外部集成**：是独立权限主体。安装不代表获得数据，必须按 scope 授权，可撤销、过期和审计。
- **插件配置**：普通配置值按本地插件 ID 保存；`secret` 字段属于 Restricted，不进入普通配置 JSON、日志、API 响应或 iframe HTML，生产环境使用加密 SecretStore Port；卸载按删除规则清理配置、secret 与 Page。

当前 SQLite 插件 Secret 实现保证同库配置提交与 API 不回显，仍保存原值，不具备默认静态加密或 OS Keychain 保证；不能把上述生产要求当作已交付能力。配置/Secret 原子性、外部 Store 和审计边界见[插件配置合同](plugin-config-and-pages.md#2-配置存储与-api)，发布缺口仍受隐私门禁约束。

## 3. 数据分类

| 等级 | 示例 | 默认控制 |
|---|---|---|
| Public | 用户主动发布并确认的知识网页、公开题包 | 公开前脱敏预览、来源/版本/AI 标识、撤回和缓存清理 |
| Internal | 系统配置、聚合容量指标、无用户内容的运行元数据 | 员工最小权限、变更审计 |
| Confidential | 本地用户档案、目标、会话、作答、知识点、记忆、日记、附件、模型上下文 | 用户目录 ACL、本机 API 边界、用途同意、导出/删除 |
| Restricted | 安全事件、健康/情绪表达、未成年人数据、设备捕获、凭据、支付/法务资料 | 默认不进入普通记忆/日记/分析；CAP-033 仅在 `restricted.profile` 独立授权下本地处理；专门权限、访问审计和专项评审 |

“情绪内容”不自动等同于需要永久保存的健康信息。普通陪伴响应可在会话中发生，但安全危机原文、医疗推断和未经确认的敏感属性不得进入长期/系统记忆。

## 4. 同意与偏好

`ConsentGrant` 至少按以下 purpose 分开：

- `core_learning`：保存目标、会话、作答、错题和复习；核心功能所需。
- `model_processing`：把必要上下文发送到已披露的模型供应商；必须显示供应商类别和跨境/地区情况。
- `memory_short`、`memory_long`：短期整理与长期个性化分开控制；关闭长期记忆不能阻断基础问答。
- `daily_diary`：日记开关，并在 `contentScopes` 中分别允许学习、互动片段、情绪表达和附件摘要。
- `analytics_optional`：非必要产品分析；拒绝后核心功能可用，使用伪匿名 `subjectId`。
- `external_sync:{provider}`、`plugin:{id}:{permission}`：第三方和插件逐项授权。
- 未来的 `screen`、`microphone`、`camera`、`notifications`：逐设备、逐能力授权，不由应用总开关替代系统权限。
- `profile_observation:{source}`：CAP-033 全量画像来源（应用/窗口/进程、浏览器、键鼠/输入、剪贴板、屏幕、文件/目录、通信、音视频、位置/传感器和 Restricted 私人资料）；每项带 manifest revision 和 OS 回执。
- `profile_action:{scope}`：CAP-033 主动动作（本地文件、浏览器/家居、外部消息、`privileged` 和不可逆动作）；用户确认 `FullProfileActionGrant` 后可执行，动作目标和撤销记录独立保存。
- `profile_background`：CAP-033 开机自启、应用退出后常驻、休眠恢复和重启自动恢复；启用和恢复必须通知用户。
- `external_sync:home_assistant`：CAP-034 连接实例、读取实体目录和订阅状态；每个实体和允许的 service 另有本地白名单，写操作还需 `profile_action:action.external`。
- `external_sync:xiaomi_health`：CAP-035 使用用户自己有权使用的官方开放平台配置同步每日指标；不代表 Aervox 已获厂商审批，不允许逆向私有协议。

同意记录包含政策版本、范围、授予/撤销时间、来源界面和证据。撤销只影响后续处理时，界面必须说明历史数据会保留还是删除，并提供相应操作。

同意与质量反馈 API 的审计操作者只取宿主认证上下文，旧请求体 `actorId` 和身份 Header 不得覆盖它；这维护本地单用户审计完整性，不建立新的数据隔离或权限主体。接口与回归入口见[API 约定](API_CONVENTIONS.md)。

### 分析事件最小字段

所有分析事件的通用必填字段为 `eventId`、`eventName`、`eventSchemaVersion`、`occurredAt`、本地生成且不可反推身份的 `analyticsSubjectId`、客户端版本和平台。`sessionId`、`goalId`、`questionId`、`diaryId` 等业务标识仅在事件确实属于相应对象时填写；模型相关事件另须包含模型版本、提示版本和 `modelRunId`。不得用虚构或空占位 ID 满足 schema。用户可拒绝非必要分析埋点，拒绝后只保留安全和可靠性所必需且已最小化的事件。

## 5. 召回、保留与删除基线

| 数据/层级 | AI 自动召回期限 | 用户可见/业务保留 | 删除/失效规则 |
|---|---|---|---|
| 原始会话与 MessageVersion | 当前会话及临时记忆窗口；默认最后活动后 6 小时自动进入上下文，之后需用户主动打开或按明确检索规则选取 | 默认保留至用户删除、卸载清理或期限到期；用户可配置历史保留 | 删除后立即禁止召回；在线副本/索引/缓存 24 小时内清除，引用和派生数据重建 |
| 临时记忆 | 数小时，默认 6 小时，可按活跃会话延长 | 仅作为 AI 召回层；精确内容由来源消息承载，不另造永久副本 | TTL 到期停止自动召回并删除临时投影，不等于删除用户历史消息 |
| 短期记忆 | 默认 7～30 天滚动；再次验证可延长 | 过期后可归档为用户可见版本或删除，按产品设置和必要性批准 | 衰减/过期停止召回；删除来源后重新验证，证据不足即失效 |
| 长期记忆 | 默认无普通 TTL；受相关性、置信度、用户控制和目的限制 | 用户删除、卸载清理或目的终止前 | 用户事实和敏感偏好需确认；纠错、撤销或证据删除后降权/失效/删除 |
| 系统记忆树投影 | 从有效长期记忆动态召回 | 可重建结构，不作为独立永久内容真源 | 来源失效后立即停止使用并重建节点/边；全部本地数据删除时清除 |
| 日记及版本 | 默认不自动作为模型事实召回；只有用户在当前任务中选择或明确确认片段时使用 | 用户逐篇/批量删除、卸载清理或期限到期；历史版本可导出 | 删除日记不删除来源；删除来源会把相关段落标为不可验证并停止后续使用 |
| 附件/OCR/Embedding | 仅在用户当前任务、收藏或有效记忆授权范围内 | 原件和派生物分别显示；默认随来源保留 | 删除原件时显示派生物影响；对象、OCR、缩略图、向量和缓存 24 小时内清除 |
| CAP-033 原始捕获副本 | 仅在有效主动画像处理和记忆提炼任务内使用 | 从 `observedAt` 起保留 7 天；达到期限且完成记忆提炼后才允许物理删除 | `retentionUntil = observedAt + 7d`；`pending/failed` 不因定时任务删除；用户主动删除可提前触发，来源哈希/授权修订保留在记忆证据中 |
| CAP-033 画像/动作/控制面 | 仅在有效本地授权、激活租约和当前目标范围内召回或执行 | 本地加密存储至用户删除、撤权清理或目的终止 | 只在本地处理；撤权立即零召回/零动作，派生记录按来源传播；导出权不因暂停/撤权失效 |
| CAP-034 HA 连接与实体状态 | 仅在主动模式、`device.sensors` 和实体白名单有效时读取/触发 | 凭据存至连接撤销；实体缓存存至连接删除或重新同步失效 | 撤销先停 WebSocket/工具，再删除 Token 和实体缓存；普通导出不含凭据 |
| CAP-035 健康每日指标 | 仅在主动模式和 `restricted.profile` 有效时用于注意力、触发、回顾和用户请求的只读工具 | 规范化样本存至连接撤销、用户删除或目的终止 | 步数为低敏；睡眠/心率为 Restricted；撤销删除 Token 和样本，不保留完整供应商响应 |
| 可选分析事件 | 不进入模型上下文 | 原始事件建议不超过 90 天，聚合数据不超过 13 个月；上线前审批 | 撤销后停止新事件；支持 subjectId 断联/删除；不以真实 userId 为必填 |
| 安全事件 | 只供安全处置，不进入普通教学/日记召回 | 按严重性、调查和地区规则最小化；上线前形成专项表 | 访问受限；期满清除内容，可保留去标识统计和必要审计 |
| 审计/tombstone | 不进入模型和产品推荐 | 为证明权限/删除操作保留的最小元数据；期限上线前审批 | 不含原文、Embedding 或可逆摘要；不能用来恢复被删除内容 |
| Turn/TurnStreamEvent | 仅在有效会话、同意和在线重放窗口内使用；事件正文不得成为独立记忆来源 | `MessageVersion` 是会话历史真源；MVP 正文事件默认仅保留 24 小时在线重放，最小事件元数据/tombstone 按审计期限 | 来源删除、撤权或重放窗口结束后清除事件正文；可追加不含正文的 `redacted`，不得通过事件副本恢复已删内容 |
| RecoveryControlLedger | 不进入模型、检索、分析或产品推荐 | 仅保留假名化控制引用、eventId、幂等键、sequence、时间与防篡改证据；保留期必须覆盖最老可恢复备份及审批的法定/审计期限 | 独立故障域；不是用户内容副本。到期清除/轮转前必须确保所有可恢复备份已过期或已具备等效控制覆盖 |
| 备份 | 不可在线召回 | 加密备份按已公示周期轮转；建议最长 35 天，需法务/灾备批准 | 删除内容不从旧备份单项修改；恢复时先校验并重放独立 `RecoveryControlLedger`，防止复活 |

长期记忆和系统记忆中的“永久”仅表示不按时间自然过期，不表示不可删除、不可纠正或可超出原目的使用。

## 6. 四段记忆的隐私规则

分层、晋升与投影行为见 [SRS](SRS.md#3-记忆业务规则)，质量阈值见 [AI 质量](AI_QUALITY_SAFETY.md#ai-memory)。隐私约束是：临时层精确内容不能无限复制到日志/分析/向量；摘要在保留学习关键约束时去掉无必要敏感细节；CAP-033 提炼继承来源、grant revision 和 `local_only`；锁定只阻止自动衰减，不能阻止用户删除、安全纠错或法定清理。

## 7. 日记数据窗口

不可变 Cycle 和时间归属规则见 [FR-DIA-001](SRS.md#fr-dia-001-ai-每日日记)。素材缓冲只为该 Cycle 保存来源引用、修订、权限快照和必要结构化事实，不是第五层记忆，不延长普通召回或原始业务保留；来源正文不复制到 DiarySource。时区快照保留 IANA 时区与适用 UTC 偏移/DST 规则，供重放解释。

若历史保留策略会在生成前清理来源，只有用户另行授权才可保存最小加密临时快照；生成成功后 24 小时内、最终失败后 72 小时内清除。一般缓冲在生成/补写用途结束后清理，撤销日记授权后未执行任务和缓冲立即失效。手动选择历史补写不改变自动 cursor，停用期间素材不自动回填。

## 8. 删除传播

```text
用户请求删除/撤销
  -> 对 RecoveryControlLedger durable append deny/revoke event
  -> 幂等提交主事务：标记来源不可用 + 写 DeletionRequest/Outbox
  -> 同步阻断 AI 召回、搜索、插件和外部同步
  -> 异步清除/重建：摘要、短/长期记忆、树边、日记来源状态、
     错题/复习派生、FTS、Embedding、缓存、对象、通知和供应商副本
     CAP-033 原始捕获、画像声明、动作队列和本地投影
  -> 验证无召回 + 回填审计证据
  -> 备份到期；恢复时校验 ledger 水位并按序重放
```

删除 SLA：立即停止在线使用；24 小时内完成 Aervox 控制的在线存储清除/重建；外部处理者按合同 SLA，若不能满足则不得承载相应数据。失败进入队列重试和告警，用户可查看进度。删除失败不能以“后台处理中”为由继续召回。

PR #324 的会话切片在受理参数恢复时拒绝缺失、软删或脱敏的首版用户输入；准备和模型/工具检查点重新检查首输入存在且未软删。SSE 在建流、空闲轮询和逐帧读取时复验 Session/Turn、首输入存在及同 Turn 现存消息身份软删状态，并重新读取持久事件，阻止旧缓存页继续披露。固定危机求助回复的记忆用途脱敏仍保持现有语义，不能把该标记等同撤权。本切片不清洗历史正文、Outbox 或派生副本，不证明全部写者、授权修订和已物理删除的非首输入来源传播；检查至后续网络/写入仍有并发窗口，完整责任仍按本节和[流式差量](STREAMING_PROTOCOL.md#5-重连保留与断点恢复)验收。

画像的旧独立 claim 写入口在同一写者事务内复验声明的来源：带 capture 或 source 引用时，revision 必须为 active/enabled/local_only，每个来源必须为 granted/local_only，capture 未删除且实际来源、revision 相符。每条 capture 的来源须显式包含于 `sourceGrantIds`，缺失或不符不猜测补造；删除、撤权、过期或暂停先提交后，迟到写入返回 `409 CONFLICT`，不新增正文或操作审计。完全不带来源引用的直接输入保持既有行为，不能用来证明来源已被验证。此切片只检查当前资格，未绑定来源授权修订，不自动清洗历史错误关联；撤权再授权及完整来源传播仍须独立验收。

capture 与 observation 新建入口同样先固定输入，再在一个写者事务内核对当前 revision、来源身份、授权状态及本地处理边界，连同正文和既有元数据审计一起提交。审计失败回滚本次写入；正常同 ID、同来源身份及 checksum 重试复用原行，不重复审计。重试也检查当前资格，不能以命中已有 ID 绕过暂停、撤权或过期；capture 已删除的墓碑即使在来源重新授权后也不作为成功重试。历史缺失审计不自动补造，历史查看和导出继续使用独立读取入口。

这些事务门禁不证明从 SQL 提交到响应交付的原子撤权。observation 物理删除后缺少授权修订回执，来源重新授权时仍无法区分旧草稿；capture 提交后的感知事件副写也未与本事务合并，尤其可选来源撤权时整体激活状态可能仍有效。感知事件、其他持久写者、grant 修订及独立 deny 账本继续按完整来源传播责任验收，不以这三个入口的局部修复宣称全链删除完成。

`RecoveryControlLedger` 是删除、同意撤销及插件/外部权限撤权的 deny 控制事实源，使用独立凭据和故障域，不与业务数据库假装共享事务。每个控制操作以确定性 `eventId/idempotencyKey` 先追加并取得 durable ack，再写业务事务和 Outbox；若账本已写而业务事务失败，reconciler 必须按连续 `sequence` 幂等补齐业务 deny/清理状态。账本不可用、签名验证失败、sequence 缺口、账本保留未覆盖最老可恢复备份或业务应用水位未追平时，受影响用途或来源必须 fail closed，不得确认操作完成或重新开放本地流量。账本只保留不可逆/假名化引用和最少证明材料，不能包含正文、Embedding 或可逆摘要。

删除单条来源不必删除独立合法事实：若高层记忆仍有其他有效证据，应重新计算并显示证据数量；若无证据，必须失效。删除日记不删除原始会话；删除原始来源则把受影响日记段落标为“来源已删除/不可验证”，并禁止用其生成长期事实。

### 8.2 显式 Memory 清理与召回准入

`POST /v1/deletions` 可按[请求模式](../../packages/contracts/src/privacy-schemas.ts)提交显式 targets，并与请求同事务落库。Worker 仅完成 `scope=memory`、请求与目标 `ownerModule=memory`、`targetType=memory` 的既存记录；清理正文、修订正文、摘要、FTS/向量后独立验证，索引、压缩摘要及压缩事件写入端在写者事务内拒绝向已删除记录回填迟到结果；同一清理事务清除压缩 Outbox 的载荷与错误正文，保留不含正文的已消费标记，并独立验证该副本。已取出的旧事件同样受墓碑检查约束。存在共享树、时态事实、技能或子记忆投影时，保留数据并报告需要 owner 清理；空目标、未知范围和失败不解闸，旧 completed 占位记录及未覆盖队列副本的旧版证明也保持阻断，并与失败请求共用重试判据。

自动召回仅接受已确认的长期记忆，并排除已删除、召回期限到期/非法及敏感或未知分级的数据；主对话召回与主动回合上下文共用同一资格谓词，候选按过采样读取后逐条判定，防止不合格命中挤占注入名额，见[召回资格测试](../../apps/api/test/memory-recall-eligibility.test.ts)。自动召回另受 `memory_long` 用途闸门约束：宿主接线后无有效授权（或授权读取失败）即不召回，撤权立即生效；历史查看与导出不受该闸门影响。召回到期不删除仍在用户保留期内的历史。

创建面按 `(targetType, targetId)` 去重并拒绝同目标不同 ownerModule；重复幂等键返回原请求。行为回归见[删除 Worker 测试](../../apps/worker/test/deletion-worker.test.ts)，现行实现范围与尚未闭合的全链删除/恢复限制只在[追踪基线](REQUIREMENTS_TRACEABILITY.md#42-证据与适用限制)维护。

## 9. 导出、更正与迁移

导出至少包括：本地用户档案、目标、会话和消息版本、题目/作答/错题/复习、知识点、四段记忆及来源/事件、记忆树节点/边、日记和版本/来源状态、附件清单、同意和外部集成。格式使用 UTF-8 JSON、CSV 和 Markdown，附件保持原格式并附 manifest/checksum。

CAP-033 的本地导出还必须能够按用户选择包含原始捕获副本、观察、画像 claim、记忆提炼证据、设备/OS 授权回执、后台生命周期设置、主动动作和触发历史；导出不受主动模式暂停或撤权影响，不自动写入云同步目录。导出不得包含密钥、Token、密码、Secure Input 原文或可恢复已删内容的 tombstone。

用户可纠正消息摘要、长期记忆、知识关系、掌握度推断和日记。纠正不会伪造原始历史，而是创建版本/事件并阻断错误派生结果。服务退出或本地迁移时，导出内容不得要求专有客户端才能读取。

## 10. 安全控制

- 认证、loopback、文件 ACL、插件与 Electron 攻击面见[威胁模型](THREAT_MODEL.md)和 [SEC-LOC-001](SRS.md#srs-sec-local)；Web Cookie/移动认证的部署选择须经相应架构决定。
- 静态与传输加密，Restricted 内容采用 envelope encryption；密钥由受控密钥存储管理，不以明文进入业务库、模型或导出。实际本地密钥与备份边界按 [ADR-018](adr/ADR-018-proactive-local-privacy-host.md)冻结。
- 日志、错误监控与分析按字段脱敏，ModelRun 使用 ContextManifest，不默认复制完整 Prompt。供应商须评审用途、保留、训练、地区、删除、通知与子处理者。
- ContextManifest 的新写入由仓储白名单投影为请求元数据：消息数量及角色计数、工具数量和合法生成参数。消息、推理、工具参数/结果、工具描述/Schema、额外字段及正文 hash 均不持久化；未知快照写为 null。Core 的调用边界快照仅供进程内执行诊断，此投影不自动清洗历史正文，也不代替来源删除传播或授权账本。
- CAP-033 的独立来源/动作授权、本地存储与控制面凭据限制以 [SRS §8](SRS.md#8-cap-033-全域感知与个人画像主动智能模式) 为准；确认推断不解除 `local_only`。
