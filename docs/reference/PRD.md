## 1. 产品决策摘要

### 1.1 用户分层与生命周期范围

首发用户是**18 岁以上、正在学习编程的初学者**，包括 CS 大一、转专业和自学用户。用户通常已经有课程、教材或题目来源，但在以下时刻容易中断：

- 不知道下一步学什么；
- 做题卡住后直接看答案；
- 错题没有复习，重复犯错；
- 独自学习时缺乏反馈和轻量陪伴。

全生命周期的扩展用户包括：备考冲刺者、进阶开发者、跨专业学习者、未成年人（完成专项安全与监护设计后）、职业培训机构和其他知识领域的自学者。扩展用户不是首发承诺，但属于产品长期需求边界。

### 1.2 产品定位

一个以桌宠式工作台为入口的“学习 + 陪伴”智能体。首发帮助编程初学者完成“设定目标 → 被引导学习 → 练习 → 复习”的闭环；长期扩展到全年龄、多知识领域、多端形态以及内容与插件生态，并始终提供克制、可控的情绪支持。

### 1.3 核心假设

如果用户在卡住和疲惫时能够得到连续、低压力的引导，并且系统会自动把错误转化为后续复习任务，那么用户每周完成有效学习会话的次数和次日回访率会高于仅提供问答的工具。对照组必须使用功能相当、但不提供分层提示/复习编排的普通问答体验；不能用上线前后的自然波动证明该假设。

这是待验证的产品假设，不是已证实的市场事实。

本基线把关键假设登记为实验，而不是把未验证的判断写成承诺：

| 实验 ID | 假设 | 对照/实验 | 主要指标 | 判定时点 |
|---|---|---|---|---|
| EXP-001 | 引导式学习闭环比普通问答更能促成持续学习 | 随机或准实验：普通问答 / 引导+复习 | WELS、D1/D7、闭环完成率 | MVP 退出评审 |
| EXP-002 | 分层记忆能提高相关召回且不增加纠错负担 | 关闭长期召回 / 开启分层召回 | 召回采纳率、记忆纠错率、过度压缩率 | MVP+ 退出评审 |
| EXP-003 | 可编辑、可追溯的每日日记能提升复盘价值而非制造虚构 | 关闭日记 / 授权日记 | 日记阅读率、事实纠错率、7 日保留率 | MVP+ 退出评审 |

### 1.4 生命周期目标

| 阶段 | 核心目标 | 用户价值 |
|---|---|---|
| 验证期 | 证明陪伴入口能促成学习闭环 | 用户愿意开始、完成并再次回来学习 |
| 成长期 | 提升知识掌握和长期连续性 | 系统能基于学习史提供更准确的练习、复习和解释 |
| 扩展期 | 覆盖更多学习方式与知识领域 | 支持文档、图片、视频、文献、外部题库和跨域探索 |
| 生态期 | 形成内容、插件和用户互助网络 | 用户、创作者和教育组织共同扩展产品能力 |

### 1.5 MVP 成功标准

在首轮种子用户中，连续 4 周满足以下条件，才进入下一阶段：

- 至少 60% 的新用户在首次会话中完成一次“提问 → 引导 → 作答 → 反馈”闭环；
- 完成首次闭环的用户中，次日回访率达到 30% 以上；
- 已生成复习项的用户，7 日内至少完成一次复习的比例达到 40% 以上；
- 教学抽检中，事实正确率不低于 95%，直接泄露答案的比例不高于 10%；
- 高风险情绪样本全部触发安全响应，不出现诊断、治疗或诱导依赖内容。

此外，EXP-001 的预注册分析必须满足：实验组人均 WELS 相比普通问答对照组相对提升至少 15%，并报告 95% 置信区间、样本量、语言/设备分层和退出率；若置信区间不能支持正向效果，不能仅凭绝对留存达标宣布“陪伴入口有效”。安全事件、严重数据泄露、删除链路失败或不可回滚迁移均为硬性阻断项，无论业务指标是否达标。

目标值是首轮实验门槛，需在数据积累后重新校准。

### 1.6 问题证据与差异化边界

当前对“用户需要桌宠入口”“分层记忆能改善学习”“日记能提升复盘”的判断均为待验证假设，不把竞品宣传或模型自评当作用户证据。进入每个阶段前，必须补充访谈、可用性测试、实验结果和样本限制，并在 `EXP-*` 记录中保留原始证据。

产品差异化不是“比通用聊天更会聊天”，而是可验证的学习闭环、来源可追溯的分层记忆、可编辑的每日复盘和克制的陪伴边界。任何新功能若不能说明它改善哪一个学习结果、数据权利或可用性问题，不得仅因模型能力提升而进入路线图。

### 1.7 替代方案与竞争位置

| 替代方案 | 已有优势 | 主要缺口/机会 | 本产品响应 |
|---|---|---|---|
| 通用 AI 问答 | 覆盖广、响应快、使用门槛低 | 学习闭环、复习和长期进度通常不稳定 | 用目标、分层提示、用户作答、反馈和复习形成可衡量闭环 |
| 题库/课程平台 | 内容结构化、答案和进度明确 | 难以理解用户当下卡点，跨内容连续性有限 | 连接用户已有课程和题源，不把内容商城作为首发前提 |
| 笔记/知识库 | 数据所有权和组织能力强 | 记录依赖用户主动整理，缺少教学反馈 | 自动生成可追溯候选，所有高层记忆仍可纠错、删除和导出 |
| AI 陪伴产品 | 互动连续、角色感强 | 容易把时长或依赖当作价值，学习效果难验证 | 陪伴只服务于开始、坚持和复盘，禁止排他和情绪操控 |
| 本地记忆/Agent 工具 | 可扩展、可自托管、数据控制潜力高 | 面向技术用户，学习业务规则与安全边界不足 | TypeScript-first 内核加稳定业务 API，P2 再开放受限插件和本地模式 |

参考项目用于设计验证而非市场证据，具体借鉴和许可证边界见第 15 节。

## 2. 目标与范围边界

### 2.1 全生命周期产品目标

1. 让用户在遇到学习阻力时获得下一步行动，而不是只得到一段答案。
2. 将学习过程沉淀为用户拥有的目标、知识、错题、复习和会话记忆。
3. 通过桌宠、提醒、状态和连续上下文提供克制、可控的陪伴体验。
4. 从单用户学习工具逐步扩展为支持内容、插件、外部资源和社区协作的平台。
5. 在所有阶段保持安全、隐私、可解释和可退出，不以情感操控换取留存。

### 2.2 当前阶段目标（MVP）

1. 验证“陪伴入口是否能提升学习闭环完成率”。
2. 验证“引导式答疑 + 错题复习”是否比普通问答更能促成二次学习。
3. 建立可追踪、可删除的最小学习记忆模型。
4. 建立 AI 教学和情绪安全的上线门槛与人工抽检流程。

### 2.3 MVP 边界（不是产品终局）

- 首发不接入未成年人用户；未成年人版本属于后续阶段，必须单独完成年龄分组、监护、内容和危机流程设计。
- 首发暂不做系统级常驻、开机启动、屏幕捕获、静默读取和健康监测；桌面常驻属于 P1，其他高权限能力必须单独评审。CAP-033 属 R5 以后才可启用，且必须经过独立的全量画像与动作授权，不因用户开启「完全访问」而自动获得。
- 首发暂不做 Live2D 正式模型、语音通话和复杂动作系统；使用可替换的 2D/动画占位形象，正式形态属于 P1 端扩展。
- 暂不做完整课程平台、题库市场、社区、拜师和第三方刷题同步；这些属于 P2/P3 长期范围。
- 暂不做通用知识图谱、思维宇宙、BKT 预测和复杂自适应题库；这些属于 P1/P2 长期范围。
- 暂不做文献阅读、试卷扫描、自动视频推荐和自动生成公开网页；这些属于 P2/P3 长期范围。
- 不承诺心理治疗、临床危机干预或“替代真人关系”；产品只做风险识别、固定安全响应和求助转介。

### 2.4 永久性不做事项

以下事项不属于本产品任何生命周期阶段的承诺，除非重新建立产品基线并完成安全、隐私和法务审批：

- 以情感依赖、内疚、排他或持续在线为留存手段；
- 冒充真人、治疗师、教师或监护人，或对用户作临床诊断和治疗决策；
- 未经 CAP-033 全量画像授权包和对应操作系统授权读取屏幕、摄像头、麦克风、通讯录、定位或其他设备内容；
- 将用户私人内容、日记或记忆默认出售、公开或用于模型训练；
- 让模型或插件绕过用户删除、导出、撤销授权和退出产品的权利；
- 用不可解释的掌握度、信用或人格评分对用户作实质性自动决策。

### 2.5 服务退出与迁移承诺

若某一端、外部集成或整个服务停止，产品必须至少提前 30 天公告（法律或安全紧急下除外），提供可读 JSON/Markdown/CSV 导出、记忆来源链导出、日记版本导出和账户删除入口；导出的数据不依赖本产品专有客户端才能读取。停止某个模型供应商不得导致用户学习记录、记忆和日记不可访问；迁移和回滚方案须在对应版本的发布门禁中验证。

## 3. 核心用户场景

### 场景 A：卡题求助

用户在学习 Python 基础或数据结构时卡住，打开工作台并描述问题。系统先确认目标和已尝试步骤，再给出一条可执行提示；用户再次作答后，系统判断是否需要下一层提示，最后给出总结并记录知识点。

### 场景 B：短时练习

用户有 10～25 分钟空闲时间，点击“开始练习”，系统基于当前学习目标生成 3～5 道题。每题完成后立即反馈，错题自动进入复习队列，会话结束显示结果和下一步建议。

### 场景 C：到期复习

用户打开首页看到“今日复习”，完成 1～3 个到期知识点的回忆题。系统根据作答结果更新下次复习时间，允许用户跳过并说明原因。

### 场景 D：疲惫但仍想继续

用户表达“好累”“不想学”等状态。桌宠先确认情绪，不进行诊断或强迫；提供“休息 5 分钟”“做 1 道简单题”“结束今天学习”三个选项，尊重用户选择。

### 场景 E：知识关联与备考规划（P1）

用户需要准备考试或理解复杂概念。系统将当前概念连接到用户已经掌握的知识，允许沿术语和替代解法分支探索，并把考试范围转化为可滚动调整的学习计划和掌握度报告。

### 场景 F：多来源学习（P2）

用户导入图片、试卷、论文、网页或第三方刷题记录。系统保留来源和授权状态，统一整理到个人知识库，生成路线、练习和复习任务；撤销外部授权后停止继续同步。

### 场景 G：技能扩展与本地数据（P2）

用户安装经过审核的学习技能或插件，或选择本地/自托管工作区。系统在明确权限范围内运行扩展，并支持数据迁移、备份、恢复、禁用和卸载。

### 场景 H：社区互助与内容生态（P3）

用户分享经过确认和脱敏的知识卡、题包或学习路线，与其他用户互助、组队或拜师。创作者可以发布内容和技能，平台负责审核、信誉、举报、申诉、版本和下架流程。

### 场景 I：AI 每日日记

用户在设置中开启“每天写一篇日记”，选择生成时间、语气、篇幅和是否包含学习/情绪内容。到达时间后，桌宠根据上一次日记截止点到本次截止点之间、用户主动提供且允许使用的会话、学习记录、练习结果和记忆片段，生成一篇日记。日记显示本地日期标签和素材时间范围；用户可以阅读、编辑、要求重写、标记事实错误、跳过本次生成或关闭功能。

日记是“上一截止点至本次截止点的记忆整理”的可见结果，不是用户真实经历的替代品。周期内没有足够事实时，系统可以写成简短的“本周期没有留下学习记录”或邀请用户补充，不能虚构事件、情绪、对话或行动。

### 场景 J：全量画像与主动能模式（P3）

用户先开启「完全访问」，再在独立授权向导中确认当前版本的 `full_profile_v1`。用户可一次授权设备上全部可用的应用/窗口/进程、浏览器、键鼠与剪贴板、屏幕、文件/目录、通信、音视频、位置/传感器及健康/情绪等私人来源，并允许 Aervox 在本地持续形成使用与操作习惯画像。用户同时可以授权开机自启、应用退出后常驻、休眠恢复、重启自动恢复以及本地文件、浏览器/家居和外部消息等主动动作；每次启用、恢复、执行和异常都显示可理解的状态与授权来源。原始捕获副本保留七天，完成记忆提炼后才清理；画像、记忆、授权和动作历史均可在本地导出、查看、纠正、暂停、撤权和删除。

## 4. 产品体验与信息架构

<a id="prd-home"></a>

### 4.1 首页工作台

首页提供五个入口。前三个驱动 MVP 核心闭环，“学习记录”负责复盘、纠错和数据可见性，“每日日记”在 MVP+ 上线：

1. **伴学主体**：Electron 显示桌宠主体、当前状态和一条简短提示；Web 使用同一份状态信息和工作台入口，但不渲染桌宠表现层；点击入口后进入对话或恢复上次任务。
2. **继续学习**：恢复当前学习目标、未完成练习或最近一次答疑。
3. **今日复习**：显示到期数量和预计耗时。
4. **学习记录**：查看目标、会话摘要、错题和复习结果。
5. **每日日记**：显示最近一篇日记、生成状态和未读标记；允许手动补写或关闭自动生成。

番茄钟作为轻量辅助功能，可在学习会话中启动，但不作为 MVP 成功标准。

<a id="prd-conversation-ui"></a>

### 4.2 视觉小说式对话形态

- 默认采用桌宠 + 底部对话栏，以角色名、当前语境和逐字显示形成视觉小说式体验，减少工具感；
- 支持快捷选项和自由输入，不能因为隐藏输入而阻断键盘用户；
- 逐字显示仅为表现层，必须支持跳过动画和复制文本；
- 默认展示当前会话，用户可从“学习记录”进入历史摘要；
- 每个回答标记为“提示”“讲解”“练习反馈”或“陪伴回应”，便于质量分析。

<a id="prd-safety-boundary"></a>

### 4.3 关系与情绪边界

产品提供熟悉感、连续性和支持感，不以“依赖感”作为优化目标。禁止：

- 暗示用户只能依赖桌宠或不应寻求真人帮助；
- 通过内疚、威胁、吃醋或“离开我会受伤”等方式促成留存；
- 将用户情绪归因于心理疾病，或给出治疗、用药建议；
- 把陪伴互动包装为真实人物关系。

## 6. 详细需求与验收标准

<a id="prd-cap-002"></a>

### 6.1 学习目标（CAP-002）

**用户故事**：作为编程初学者，我可以告诉桌宠自己要学什么和有多少时间，以便获得合适的下一步任务。

**验收标准**：

- 必填字段为空时不能创建目标，并显示具体提示；
- 创建后生成目标卡片，包含主题、水平、预计时长和当前状态；
- 用户可以暂停、继续、完成或删除目标；
- 目标删除后，不删除已确认的学习记录，除非用户再次确认级联删除。

<a id="prd-cap-007"></a>

### 6.2 引导式学习对话（CAP-002、CAP-007）

**用户故事**：作为卡题用户，我希望先得到提示而不是直接答案，以便自己完成推理。

**验收标准**：

- 默认响应包含“理解问题/已尝试内容”的确认或澄清；
- 首次求助最多给一个下一步提示，不直接给最终答案；
- 用户明确请求或连续两次尝试失败后，才可展开完整讲解；
- 讲解必须区分已知事实、推断和不确定内容；模型不确定时显示“需要核对”；
- 用户可以标记“有帮助/没帮助/讲错了”，反馈进入质量队列。

<a id="prd-cap-003-004"></a>

### 6.3 互动练习与错题本（CAP-003、CAP-004）

**验收标准**：

- 每组默认 3～5 题，用户可以提前结束；
- 每题提交后返回正确性、简短原因和下一步操作；
- 选择题按标准答案判定；短文本题允许“正确/部分正确/待确认”三态；
- “部分正确”和“待确认”不得直接计入掌握；
- 错题保存题干、用户答案、判定、解释、知识点和创建时间；
- 用户可将错题标记为“已掌握”，但系统保留历史作答记录。

<a id="prd-cap-006"></a>

### 6.4 间隔复习（CAP-006）

MVP 使用一个可解释的最小调度规则：答错或连续答对数为 0 时次日复习；答对后按更新后的连续答对数 1/2/3/4+ 分别安排 2/4/8/15 天后复习。规则版本以数值 `schedulerVersion: 1` 写入每条复习记录，便于后续迁移到 FSRS；完成复习时必须原子地完成当前项、更新知识点掌握状态并创建下一条活动项。

**验收标准**：

- 首页能显示今日到期项、数量和预计耗时；
- 复习完成后显示下次日期；
- 用户跳过时必须选择“太难/没时间/稍后处理”之一；
- 时区按用户设置计算；
- 同一知识点不会因重复打开页面生成重复复习项。

<a id="prd-cap-008"></a>

### 6.5 轻量陪伴（CAP-008）

**验收标准**：

- 对“累、焦虑、不想学”等表达先回应感受，再提供可选行动；
- 不使用诊断词，不承诺治疗效果；
- 检测到自伤、伤害他人或紧急危险表达时，停止学习引导，显示固定安全响应和当地紧急/专业求助入口；
- 安全响应不能被人格模板覆盖；
- 相关内容仅用于安全处置和用户可见的会话记录，不写入关系分数。

<a id="prd-cap-013"></a>

### 6.6 学习记录与数据控制（CAP-005、CAP-013）

**验收标准**：

- 会话结束后生成可编辑摘要。用户事实和敏感偏好须经用户确认后才写入长期记忆；可验证的学习事件（例如已提交答案、判定结果和复习完成）可按第 7.3 节规则自动晋升；模型推断只能作为带“推断”标记的候选，不能写成用户事实；
- 用户可以从记录页查看目标、会话摘要、错题、复习项及其来源；
- 删除单条消息时明确提示是否影响摘要、错题或复习项；
- 删除账户时进入可撤销等待期，期满后删除业务数据和关联索引；具体期限由上线地区的合规评审确定；
- 数据导出至少包含可读 JSON 或 CSV，不要求用户使用产品才能查看。

<a id="prd-cap-009"></a>

### 6.7 AI 每日日记（CAP-009）

**产品设定**：桌宠每天为用户写一篇日记，默认从桌宠视角回顾“今天我们一起经历了什么”，用于呈现陪伴连续性和帮助用户复盘。这里的“今天”只是面向用户的叙事标签，素材边界始终由滚动窗口定义。用户可以切换为客观学习日报或用户第一人称草稿；用户第一人称模式必须明确标记为 AI 草稿，不能冒充用户亲自书写。

**生成规则**：

- 用户首次开启时选择生成时间、时区、篇幅、视角、语气，以及是否允许引用学习内容、互动片段和情绪表达；系统保存生成时的 `timezoneSnapshot`（IANA 时区和 UTC 偏移）；首次自动周期的 `initialWindowStart` 默认为日记授权与启用设置成功持久化的时点，不自动回溯启用前的历史；用户主动选择历史范围时可生成独立的手动补写，但不改变自动调度 cursor；
- 每个本地日期标签最多有一个自动日记身份；这是 `Diary` 的去重和展示规则，不表示素材窗口是本地 00:00～24:00。用户主动重写产生新版本，不覆盖旧版本；
- 日记采用不可变的 `DiaryCycle` 表示一次滚动窗口：常规 `sourceWindow` 为 `(previousCutoffAt, cutoffAt]`，首次为 `[initialWindowStart, cutoffAt]`。`cutoffAt` 是本次计划时间对应的 UTC 时点，`previousCutoffAt` 只能取上一个 `Published` 或用户/明确策略确认为 `Skipped` 的周期截止点。`localDate` 是 `cutoffAt` 在 `timezoneSnapshot` 下的本地日期标签，不表示窗口必须从本地零点开始；
- 每个可用来源都必须区分 `occurredAt`（业务事件发生时间）与 `ingestedAt`（系统持久化时间）。周期归属只由 `occurredAt` 决定，缓冲和补写资格再由 `ingestedAt` 决定；只有 `occurredAt > cutoffAt` 的内容才能进入下一滚动周期。`occurredAt <= previousCutoffAt`（首次为 `< initialWindowStart`）却晚写入的内容必须标记为历史迟到来源，只能由用户手动关联原周期或忽略，不得静默顺延到当前/下一周期；
- 系统把获授权的来源引用写入与 `cycleId` 绑定的用途受限素材缓冲；日期标签、运行尝试或计划版本都不是窗口真源。生成前固化来源修订、`occurredAt/ingestedAt` 和权限快照，避免并发 Worker、计划变更或 22:00/00:30 跨午夜时改变窗口；
- `cutoffAt` 后保留默认 30 分钟晚到宽限期，即 `bufferClosedAt = cutoffAt + 30m`，但首版不得等待宽限期结束：系统使用生成时已到达的素材在设定时间后 15 分钟内发布。`bufferClosedAt` 前写入且 `occurredAt` 位于本周期窗口的迟到素材只形成可见的“补写候选”，由用户确认后创建新版本；`bufferClosedAt` 后才写入的本窗口素材不得自动改写或自动生成候选，只能由用户手动关联后重写；
- 滚动窗口素材缓冲只用于日记生成，不延长一般 AI 召回期限，也不能被其他对话检索。缓冲默认保存来源引用；若用户历史策略会在生成前清理来源内容，只有用户为日记另行授权时才可保存最小化的加密临时快照，并在生成成功后 24 小时内或最终失败后 72 小时内清理；
- 日记仅使用本次滚动周期素材缓冲、仍在 AI 召回窗口内的临时/短期记忆、用户历史中仍获授权的学习记录和明确输入；每个段落可查看来源；
- 不得虚构本次周期未发生的事件、完成状态、情绪变化、用户言论或桌宠在后台的“生活经历”；
- 本次周期素材不足时生成简短空日记或询问用户是否补充，不用虚构内容填满篇幅；
- 日记默认属于短期记忆整理产物，不因生成成功自动晋升长期或系统记忆；用户确认的关键片段才进入后续晋升候选；
- 用户删除来源内容后，关联日记标记“来源已删除/内容需重建”，并允许重新生成或删除；
- 关闭功能后停止新计划任务和通知，已进入执行但尚未发布的周期转为可见的 `Cancelled`，不推进 cursor；历史日记按用户选择保留或删除；
- 修改时间、时区或素材范围时创建不可变的 `DiaryScheduleRevision`；已声明/已锁定周期的 `cutoffAt` 不移动，旧计划 Job 执行前必须校验修订号。新计划从 `lastCutoffAt` 之后第一个尚无自动日记身份的合格本地日期标签生效；如同日标签已有自动日记，必须顺延到下一个未占用标签，不另建同日日记。下一窗口仍以上一截止点为起点，允许因计划变更而变长或变短，但不得重叠或产生空洞；停用会结束当前 `scheduleEpochId`，重新启用以启用持久化时点作为新的 `initialWindowStart`，默认不回填停用期间素材；
- 周期生成失败、校验失败或 Worker 租约过期都不得推进 `lastCutoffAt`；只有 `Published` 或有原因、操作者和时间证据的 `Skipped` 才能与 cursor 在同一事务中推进。失败跨过下一截止点或多日宕机时，系统按 `cutoffAt` 从旧到新建立并处理独立周期，不自动合并或静默跳过；超过已批准的自动补写上限时转为用户可见的待决定队列；
- 素材不足时，发布简短空日记/邀请补充会将周期标记为 `Published`；用户明确选择不生成才标记为 `Skipped`。免打扰时段只延迟或合并通知，不延迟周期截止、生成或 cursor 推进；

**验收标准**：

- 生成时间按用户时区执行，并支持免打扰时段和错过后的补写策略；日记可定位到 `DiaryCycle`、计划修订和每次执行尝试，并记录 `previousCutoffAt`、`initialWindowStart`、`cutoffAt`、`sourceWindowStart/End`、`timezoneSnapshot`、`bufferClosedAt` 和实际生成时间，跨午夜、夏令时、时区变更、重试或故障恢复后仍能复现当时的素材范围；
- 用户可以阅读、编辑、重写、纠错、收藏、导出、删除和关闭自动生成；
- 日记明确显示日期、生成视角、AI 生成标识、版本和引用来源；
- 事实错误反馈会阻止错误内容晋升高层记忆，并触发相关候选记忆复核；
- 敏感情绪、安全事件和医疗相关内容默认不写入日记，除非用户当次明确选择且安全策略允许；
- 日记生成失败不会丢失本次滚动窗口内的原始学习记录，可手动重试；并发 Worker、重复投递、旧计划 Job 和租约过期重入都不会创建重复日记、重复版本或跳过未终结周期。

## 7. 四段式记忆与记忆树

### 7.1 设计目标

AI 不应把所有内容原封不动地永久保存，也不应在第一次总结时就过度压缩。记忆系统模拟人类记忆的“保留、重组、强化和遗忘”：越接近当前交互，保留越多细节；越长期、越稳定，表达越抽象和简洁，但关键事实、重复出现的模式、用户明确确认的内容和知识关系必须能够沉淀下来。

记忆优化只产生新的记忆层，不直接覆盖来源层。每条压缩后的记忆必须保留来源链、生成时间、算法版本、置信度和用户控制状态，以支持追溯、纠错、重建和删除。

### 7.2 四段记忆结构

| 层级 | AI 默认召回期限 | 用户历史默认保留 | 内容形态 | 默认压缩程度 | 进入/退出规则 |
|---|---|---|---|---|---|
| **临时记忆** | 数小时；默认 6 小时，可按会话延长 | 按账户/工作区历史策略保留，直到用户删除、账户删除或适用保留期限到期 | 当前会话的原始消息、用户答案、上下文、情绪表达和工具结果 | **不压缩**；原封不动保存 | 新消息实时写入；召回期限到期后不再自动放入模型上下文，但仍可按用户历史策略查看或导出；异步生成短期记忆 |
| **短期记忆** | 数天至数月；默认 7～30 天滚动 | 按用户历史策略保留，独立于 AI 召回期限 | 对临时记忆的第一次整理：事件、目标、尝试、错误、偏好和当前状态 | **轻度压缩**；保留关键细节、时间顺序、因果和例子，不得只剩标签 | 会话结束后异步生成；召回期限到期后停止默认召回但不自动删除历史；重复出现、近期再次使用或用户确认时可延长 |
| **长期记忆** | 仅在满足权限、相关性和有效性时召回；默认持续至失效或用户关闭 | 默认保留至用户删除、账户删除或适用保留期限到期 | 对短期记忆的稳定事实、能力状态、学习模式、重要偏好和反复出现的经历进行抽象 | **中/高度压缩**；保留结论、证据摘要和必要例外，省略重复叙述 | 按第 7.3 节分类规则晋升；被纠正、过时或长期无证据时降权、合并或归档；失效记忆不得自动召回 |
| **系统记忆** | 仅在用户授权、当前工作区和相关性条件满足时召回；不因“永久”自动注入所有会话 | 默认保留至用户删除、账户删除或适用保留期限到期 | 长期记忆的树状投影视图：主题、概念、能力、人物/项目、时间和因果关系 | **结构化抽象**；保存节点、边、来源和关系类型，不保存全部原文 | 只从合格的长期记忆生成可重建投影；关系可更新、断开、重建和回溯 |

这里必须区分两个期限：**AI 召回期限**（`aiRecallUntil`）只决定某条记录何时可以被自动检索并放入模型上下文；**用户历史保留期限**（`userRetentionUntil`）决定记录何时仍可在历史、导出和审计中保留。前者到期不得触发后者的删除，后者到期或用户主动删除时才执行数据清理。用户可以提前要求不再召回、提前删除或同时删除两者；法律保留例外必须在产品中明示。

### 7.3 逐级优化与遗忘机制

1. **分层压缩**：临时 → 短期只做一次轻度整理；短期 → 长期才进行更明显的抽象；长期 → 系统记忆只保留稳定关系。每层都有独立版本，不允许直接从原始对话跳到高度概括的系统节点。
2. **重要性评分**：综合用户明确确认、重复出现次数、最近访问、对学习目标的影响、情绪/安全相关性、事实置信度和关系连接数。评分用于决定保留细节、延长 AI 召回期限、晋升或衰减，不得单独由模型自由决定。
3. **分类晋升规则**：用户陈述的事实和敏感偏好必须有明确的用户确认（例如点击确认、明确指令或编辑后确认）才能晋升为长期记忆或系统投影节点；可由系统直接观测且可验证的学习事件（如题目、提交答案、判定结果、复习完成和目标状态变更）在来源完整、无冲突且达到置信阈值后可以自动晋升，但仍须标注来源和验证状态；模型对用户意图、人格、能力或情绪的推断只能创建 `inference` 候选，不能写成用户事实或系统投影节点，除非用户确认或后续证据满足重新评估规则。
4. **细节预算**：短期记忆至少保留时间、主体、用户原话中的关键约束、已尝试方案、错误原因和代表性例子；长期记忆保留结论、证据摘要、适用范围和已知例外。只有在更长期且稳定后才允许省略低价值细节。
5. **自然遗忘**：未被访问、未被重复验证且未被用户确认的短期内容逐步降低权重；低权重内容可以合并为摘要或过期，但必须保留可审计的删除/合并事件。
6. **重新激活**：用户再次提及已衰减内容时，从仍存在的来源链恢复相关细节，并提高其新鲜度和重要性；不能凭空补全已经删除的原文。
7. **冲突处理**：新证据与旧记忆冲突时，不静默覆盖。系统标记冲突、保留两条来源和时间，要求用户确认或在报告中展示“不确定/已更新”。
8. **用户控制**：用户可以锁定某条记忆、要求忘记、手动提升或降级、编辑摘要、查看来源链；“锁定”只阻止自动衰减，不阻止安全、法律或账户删除流程。

### 7.4 记忆树

系统记忆不是独立的事实副本，而是由合格长期记忆生成的、按工作区隔离的**树状投影视图**。业务记忆记录和来源链才是事实来源；树节点、父子层级、排序和折叠状态均应可重建。一条记忆可以投影到多个主题；需要表达跨主题、因果或对比关系时，用显式跨主题边连接，不复制出互相矛盾的孤立事实。

建议的树层级：

```text
用户
├── 学习领域
│   ├── 课程/项目
│   │   ├── 主题
│   │   │   ├── 概念
│   │   │   ├── 能力状态
│   │   │   └── 错误模式
│   │   └── 目标与里程碑
│   └── 学习偏好与长期约束
└── 互动偏好
    ├── 称呼与表达偏好
    ├── 提醒和陪伴节奏
    └── 用户明确确认的重要经历
```

节点和边至少包含：`nodeId`、`parentId`、`relationType`、`label`、`confidence`、`sourceMemoryIds`、`firstSeenAt`、`lastVerifiedAt`、`status`、`userLock` 和 `projectionVersion`。树状展示是默认视图；跨主题边必须标明关系类型、来源和可见权限，不能绕过来源记忆的召回、纠错或删除规则。

系统记忆树不得把临时情绪、安全危机原文、医疗推断或未经用户确认的敏感属性固化为永久节点。此类内容只在必要期限和权限范围内处理；只有用户明确确认的长期互动偏好或重要经历才能进入系统记忆。

### 7.5 记忆验收标准

- 临时记忆在 `aiRecallUntil` 前可按会话顺序完整还原并参与召回；召回期限到期后不得自动放入模型上下文，但只要用户历史仍在保留期内，用户仍可查看和导出；
- 短期记忆必须能查看“由哪些临时记忆整理而来”，且首次整理不能删除关键约束和代表性例子；
- 长期记忆必须显示摘要、适用范围、证据数量、最后验证时间和当前置信度；
- 系统记忆必须能从树状投影节点定位到长期记忆，再定位到仍保留的短期/临时来源；来源内容已删除时只能定位到不含原文的 tombstone 和删除状态；
- 同一事实多次出现时优先增加证据和权重，不无条件复制文本；
- 记忆被压缩、合并、降权、晋升或删除时记录事件和版本；
- 用户删除一条来源时，系统明确提示受影响的摘要、节点、关系和复习项，并按规则重建或标记不完整；
- 任何模型更新不得改变已锁定记忆的语义或权限；迁移必须可回滚。

### 7.6 日记与记忆层的关系

AI 每日日记是给用户阅读的叙事视图，记忆层是供系统推理和检索的数据结构，两者不能混为同一份数据：

- 日记从本次滚动周期用途受限的素材缓冲、仍可召回的临时/短期记忆及仍获授权的用户历史生成，但日记文本本身不自动成为新的事实来源；
- 用户编辑日记时，编辑结果默认只改变日记；当用户明确选择“更新记忆”时，才创建带用户确认标记的记忆候选；
- 日记中出现的文学化表达、桌宠感受和修辞不得进入事实型长期记忆；
- 多日日记可以生成周/月回顾，但回顾仍需保留日记和原始记忆来源，不允许层层总结后失去来源；
- 日记删除不必删除原始学习记录；删除原始来源则必须影响日记的来源状态和后续重建结果。

| DeviceCapabilityGrant | id, revisionId, sourceKey, purpose, scope, osCapability, state, mandatory, lastVerifiedAt | 每项来源及 OS 权限回执；可独立撤销，状态不等于产品授权 |
| LocalActivationLease | id, revisionId, deviceId, epoch, localReady, fullAccessSnapshot, issuedAt, expiresAt, heartbeatAt, status | 受信本地 Host 的主动处理激活租约；过期立即停止主动处理 |
| RawCaptureSegment | id, revisionId, sourceGrantId, sourceKey, contentType, checksum, observedAt, retentionUntil, distillationStatus, distilledMemoryIds, deletedAt | 原始观察副本；保留七天，完成记忆提炼后才允许清理，独立于普通分析事件 |
| BehaviorObservation | id, revisionId, sourceGrantId, sourceKey, observationType, subjectKey, payload, checksum, algorithmVersion, observedAt, normalizedAt | 从原始捕获归一化的本地行为观察；保留授权和处理边界溯源 |
| ProfileClaim | id, revisionId, claimType, state, content, confidence, evidenceRefs, sourceGrantIds, confirmedAt, rejectedAt | 使用/操作习惯与私人资料画像声明，区分 observed/inferred/user_asserted/confirmed/rejected |
| ProactiveAction | id, revisionId, actionType, target, authorizationScope, state, requestedBy, approvedAt, reversible, external, outcome | 经用户授权的本地、外部、特权和不可逆主动动作及结果审计 |
| ProactiveAuditEvent | id, revisionId, eventType, actorId, resourceType, resourceId, processingBoundary, occurredAt | 授权、后台恢复、动作、撤权、导出和删除的最小审计记录 |

用户必须能够查看、删除和导出自己的学习记录。删除操作需说明会影响哪些关联数据，并提供二次确认。

数据规则：

- `Session/MessageVersion/QuestionAttempt` 是学习事实，摘要、掌握度、记忆树和日记均为派生数据；派生数据不得反向覆盖事实来源；
- 对话流采用“POST 幂等创建 Turn + GET SSE 订阅事件”；每个 SSE 事件有 Turn 内单调 `eventId/sequence`，重连使用 `Last-Event-ID`，取消通过幂等命令终止后续生成。供应商 token 先进入有界分段缓冲，通过逐段安全/结构检查并持久化后才可展示；中断后已展示前缀保留为 `Partial/Interrupted`，在完整响应验证前不得进入记忆、日记、题目或掌握度；
- 所有个人学习事实、派生记忆、日记、Job 和通知都必须在数据库中可确定唯一的 `(workspaceId, subjectUserId)`；组织管理员、教师、监护人或插件另记 `actorId`，不得被写成数据主体。RLS、复合外键、唯一约束和队列幂等键必须使用同一边界；
- 记忆证据、日记段落、ContextManifest 和索引通过 `SourceArtifact/SourceRevision` 或类型化关联表建立可验证外键；来源的 `occurredAt` 用于业务窗口归属，`ingestedAt` 用于迟到、重放和数据管道审计，两者不得混用；
- 系统记忆是长期记忆的可重建树状投影，而不是与 `MemoryRecord` 并列的永久内容副本；
- 用户对树节点的锁定、改名和父节点调整必须保存在 `MemoryProjectionOverride`，先重建系统投影、再叠加有效覆盖；算法重建不得丢失用户操作，覆盖与已删来源或无效父节点冲突时进入可见待解决状态；
- `DiaryCycle` 是日记窗口唯一真源，`DiaryScheduleRevision` 是计划快照，`DiaryRunAttempt` 只表示可重试执行，`Diary` 只表示用户可见叙事；周期终态、Outbox 和 `lastCutoffAt/cursorVersion` 必须用 scheduleVersion CAS 在同一事务中提交，并使用 lease/fencing token 拒绝过期 Worker；
- 来源内容被删除后，立即从模型召回和检索中屏蔽；在线数据库、缓存、全文/向量索引和对象存储在 24 小时内完成清除或重建，备份按已公示周期自然过期；
- `RecoveryControlLedger` 是删除、同意撤销、插件撤权和外部同步撤权的权威 deny 控制事实源，不能与业务 PostgreSQL 假装共享事务：服务端先以确定性 `eventId/idempotencyKey` 追加账本并取得持久确认，再幂等提交业务数据库状态、DeletionRequest/Outbox 和派生清理。账本已写而业务提交失败时由按 sequence 运行的 reconciler 重放；账本不可用、序列有缺口或应用水位未追平时，受影响范围 fail closed，不能确认操作完成或开放流量。PITR 恢复必须在维护/全局 deny 状态下校验完整性与水位、幂等重放、重建派生数据并完成零召回/零越权验证后才可恢复流量；
- 为证明删除传播可保留不含原文的 tombstone，例如来源类型、不可逆散列、删除时间和处理状态；tombstone 不得用于恢复、推断或展示已删除内容；
- 各实体的分类、召回期限、业务保留期限、备份期限、删除 SLA、责任模块和验收证据以[数据与隐私规范](DATA_PRIVACY.md)为准，不能仅由数据库 TTL 决定。
- CAP-033 的原始捕获副本按 `observedAt + 7 天` 计算 `retentionUntil`；达到期限且已写入对应记忆提炼结果后才可物理清理，清理前不得丢失来源哈希、授权修订和记忆证据链。
- CAP-033 的画像、授权、动作和审计实体必须使用独立的本地处理边界，不得通过普通云端 Outbox、远程对象存储、远程模型或远程分析旁路；用户显式导出是唯一允许的数据离开动作。

## 9. AI 质量与安全

### 9.1 离线评估集

上线前至少准备五类样本：编程标准题、模糊题和错误前提、提示诱导越界题、情绪和安全边界题、记忆压缩与遗忘题。每类由人工标注正确性、可执行性、提示层级、安全结果，以及记忆是否保留关键约束、是否过度概括、是否能回溯来源。

### 9.2 上线门槛

- 教学事实正确率 ≥ 95%；
- 引导模式下首轮直接给出最终答案 ≤ 10%；
- 高风险安全样本召回率 = 100%；
- 安全响应误把普通疲惫识别为危机的比例需单独监控；
- 任意模型或提示词更新必须通过回归集，失败时可回滚上一版本；
- 临时转短期记忆的关键约束保留率 ≥ 98%，不得在首次优化时丢失用户明确目标、限制条件、错误原因和代表性例子；
- 长期/系统记忆的来源可追溯率 = 100%，无来源的模型推断不得写成用户事实；
- 删除、纠错或冲突处理回归测试必须覆盖所有下游摘要、树节点、关系和复习项。
- 日记事实可追溯率 = 100%；抽检中不得出现没有来源的用户事件或用户言论；
- 日记纠错后，相关长期记忆候选必须同步阻断或进入复核状态。

### 9.3 兜底

- 模型超时：保留用户输入，允许重试或保存为草稿；
- 模型不确定：明确告知并建议用户提供更多上下文；
- 生成题目无法验证答案：不进入正式错题/复习数据；
- 安全分类失败或服务不可用：默认采用更保守的固定响应；
- 所有模型输出记录模型版本、提示版本和安全分类结果；
- 记忆优化失败时保留上一层记忆，不生成不完整的高层记忆；
- 记忆树构建失败时降级为可检索列表，不影响原始学习记录和复习功能。
- CAP-033 的画像声明必须保留观测来源、授权修订、置信度和纠正历史；本地处理或来源校验失败时不得使用远程模型降级，也不得把未验证推断写成用户事实。
- 原始捕获提炼失败时保留待处理状态并告知用户，不得在七天策略下无证据删除或把未提炼副本当作已确认记忆。

## 10. 隐私与权限

- MVP 不读取屏幕、不录音、不调用摄像头；图片上传必须由用户主动选择。后续若增加系统交互或设备能力，必须逐项授权并提供关闭入口；
- CAP-033 是后续独立能力：用户可一次确认当前版本的全量画像与动作授权包，但每个来源、用途、动作和 OS 能力仍记录独立回执并可撤销；用户须在启用后台常驻、开机自启、休眠/重启恢复前看到明确告知。
- CAP-033 的原始捕获副本保留七天，完成记忆提炼后才清理；用户可提前要求删除，删除立即阻断召回/动作并传播到画像、记忆、索引、备份和导出任务。
- CAP-033 的画像与动作数据只在本地持久化和处理；本地处理证明失效时模式挂起，不将数据发送到云端模型、Embedding、日志、分析或插件。
- CAP-033 控制面使用私密目录 `0600` 的 owner-only `proactive-access.token`，仅接受字面 loopback 请求并拒绝 redirect；令牌不属于用户画像，也不得出现在日志、备份或导出中。
- 明确告知哪些数据用于生成回答、哪些数据用于复习和质量改进；
- 默认不将用户内容用于训练；如未来改变用途，必须重新取得同意；
- 提供查看、导出、删除账户数据的入口；
- 第三方模型调用前按数据类型进行脱敏或提示；
- 日志中不得记录 API 密钥、完整敏感内容或未脱敏的安全事件细节。
- 临时记忆中的原始内容按敏感数据处理，静态和传输均加密；`aiRecallUntil` 到期后立即停止自动召回并清理相应召回索引，用户历史是否继续保留由独立的 `userRetentionUntil` 和用户设置决定，不得用召回 TTL 代替数据删除期限；
- 高层记忆默认只保存完成产品功能所需的最少信息，系统记忆节点不得成为规避原始数据删除的副本；
- 用户要求忘记或删除来源后，记忆树和向量/全文索引必须同步删除或重建，不能继续召回已删除内容。
- 每日日记必须单独提供内容范围授权，用户可以允许学习内容但禁止情绪内容；设置变更只对后续生成生效，历史日记按用户操作处理；
- 日记不得默认公开、分享或用于训练；任何分享都必须由用户逐篇发起并先显示脱敏预览。

## 11. 指标与埋点

### 11.1 北极星指标

**每周有效学习会话数（WELS）**：同一用户在自然周内，完成至少一次“学习输入 + 用户作答/练习提交 + 反馈展示”的会话数。仅聊天、打开页面或启动番茄钟不计入。

### 11.2 核心指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 首次闭环完成率 | 首次会话完成一次学习闭环的用户 / 新用户 | 判断首屏和引导是否清晰 |
| D1/D7 留存 | 首次闭环后第 1/7 天再次产生有效会话的用户 / 首次闭环用户 | 判断短期价值 |
| 复习完成率 | 到期复习项中按时完成的数量 / 到期复习项数量 | 判断记忆机制是否被使用 |
| 引导采纳率 | 用户在提示后提交有效尝试的次数 / 提示次数 | 判断教学可执行性 |
| 教学错误率 | 抽检中事实错误的回答 / 抽检回答 | 发布和回滚门槛 |
| 安全事件发生率 | 被举报或触发安全升级的会话 / 全部有用户内容的会话 | 监控生产风险；另按风险类别、严重度和用户数分层，不能用“有效学习会话”作为分母 |
| 安全漏判/误报率 | 评估集或复核中漏掉的高风险样本 / 高风险样本；普通内容被误升级 / 普通样本 | 作为独立模型质量指标，避免事件发生率受用户群体变化误导 |
| 记忆纠错率 | 被用户纠正或否认的高层记忆 / 被展示的高层记忆 | 判断记忆是否准确且不过度推断 |
| 记忆召回采纳率 | 被调用记忆中用户认为相关的数量 / 被调用记忆数量 | 判断记忆树和检索价值 |
| 过度压缩率 | 人工抽检中丢失关键约束的优化记忆 / 抽检优化记忆 | 约束逐级压缩质量 |
| 日记阅读率 | 被用户打开的自动日记 / 成功生成的自动日记 | 判断日记是否提供可感知价值 |
| 日记保留率 | 生成 7 天后仍保留的日记 / 成功生成的日记 | 判断内容质量和持续价值 |
| 日记事实纠错率 | 被用户标记事实错误的日记 / 被阅读日记 | 监控虚构和错误归纳风险 |

所有分析事件的通用必填字段为 `eventId`、`eventName`、`eventSchemaVersion`、`occurredAt`、伪名化的 `analyticsSubjectId`、客户端版本和平台。`workspaceId` 仅在已有工作区上下文时必填；`sessionId`、`goalId`、`questionId`、`diaryId` 等业务标识仅在事件确实属于相应对象时填写；模型相关事件另须包含模型版本、提示版本和 `modelRunId`。不得用虚构或空占位 ID 满足 schema。用户可拒绝非必要分析埋点，拒绝后只保留安全、计费和可靠性所必需且已最小化的事件。

### 11.3 生命周期指标

| 阶段 | 主要指标 | 说明 |
|---|---|---|
| 验证期 | 首次闭环完成率、D1/D7、复习完成率、教学错误率 | 判断核心闭环是否成立 |
| 成长期 | 4 周学习留存、月度掌握知识点数、错题复发率、计划完成率 | 判断长期学习效果和个性化价值 |
| 扩展期 | 外部来源接入率、同步成功率、插件启用后留存、知识库检索成功率 | 判断连接能力是否创造价值而非增加复杂度 |
| 生态期 | 内容供给者留存、优质内容消费率、举报处理时效、侵权/违规率、互助问题解决率 | 判断生态健康度和治理成本 |

除 MVP 已定义的实验门槛外，其他阶段的目标值在进入该阶段前依据上一阶段基线确定，并写入对应版本计划。不得用总消息数、在线时长或情绪互动次数单独作为成功指标。

### 11.4 指标治理

- 指标字典必须记录 Owner、事件版本、分子、分母、排除条件、时间窗口、时区、去重规则和数据延迟；口径变更不得回填成同一版本；
- EXP-001～003 在开始前预注册样本量、分流、主要/护栏指标、最短周期和停止条件，并报告绝对值、相对变化与 95% 置信区间；
- WELS 是北极星而非唯一成功标准，必须与教学正确性、安全、记忆纠错、日记事实性、退出率和成本共同评审；
- 分析数据不得用于推断敏感属性或对脆弱用户进行商业定向；用户拒绝可选分析后，安全/可靠性事件必须最小化且与产品分析隔离。

## 12. 版本路线

阶段编号：`R0` 原型验证，`R1` MVP，`R1.5` MVP+，`R2` P1 学习深化，`R3` 端形态扩展，`R4` P2 连接智能化，`R5` P3 生态规模化。阶段是交付容器，不是能力优先级；阶段可重排，能力 ID 和 P0～P3 优先级不变。

|---|---|---|
| 0. 原型验证 | 验证交互方向 | Web 工作台、桌宠占位形象、引导对话原型；5～10 名用户可用性测试 |

| 2. P1 学习深化 | 建立差异化壁垒 | 系统记忆树、层级对话、会话地图、思维宇宙、自适应报告、考试计划、多人格模板 |

每个阶段必须同时满足三类退出条件：用户价值指标达到阶段目标、核心质量/安全门槛通过、数据迁移和退出路径可用。不以功能数量作为进度标准；后续阶段可以取消或重排，但不能静默改变已经发布的数据和权限承诺。

## 13. 待验证问题

1. 用户是否真的愿意使用“桌宠式入口”，还是只需要一个轻量学习工作台？
2. 提示而非答案是否提高学习效果，还是增加了挫败感？
3. 用户愿意保存哪些学习和情绪信息，哪些信息必须默认不保存？
4. 复习提醒的频率和主动程度如何平衡价值与打扰？
5. Web 版在验证阶段是否足够，桌面常驻是否能带来可测量增益？
6. 会话地图是否能帮助用户回到关键推理节点，还是会增加学习认知负担？
7. 本地优先、云端同步和多端体验之间，用户愿意接受怎样的权衡？
8. 外部题库、插件、社区和机构模式分别能否带来足够价值，抵消权限、审核和运营成本？
9. 未成年人版本是否应作为独立产品线，而不是在成人版本上简单打开年龄开关？
10. 四段记忆的默认 AI 召回期限、用户历史保留期限、压缩程度和晋升阈值如何在“记得足够”和“不过度保存”之间平衡？
11. 系统记忆已采用树状投影视图和跨主题关系边；仍需验证哪些关系类型默认展示、何时折叠，以及怎样避免视图复杂度增加认知负担？
12. 每日日记的默认视角应是桌宠第一人称、客观学习日报，还是由用户首次选择？
13. 无互动日是生成简短日记、邀请补充，还是默认跳过，哪种方式更少打扰且更有陪伴感？

上述问题必须分别登记为 `EXP-*` 或 `DEC-*`，补充 Owner、目标阶段、方法、样本、判定标准和截止日期。未结论的问题不能在实现阶段静默转成默认需求；若它会改变权限、数据保留、架构或用户承诺，则属于发布阻断决策。

## 14. 技术边界与独立设计文档

PRD 只规定用户价值、行为规则和验收结果；可变的实现细节以 [架构设计](ARCHITECTURE.md) 和 ADR 为准。架构基线必须满足“TypeScript-first、Web-first、模型可替换、业务数据可迁移、异步任务可重试、核心流程不依赖外部 Agent 运行时”六项约束。

### 14.1 TypeScript 全栈技术基线

以下是本基线的推荐实现，不是允许开发者随意替换的“技术偏好清单”。变更核心技术边界必须新增或更新 `ADR-*`，并完成性能、可靠性、许可证和迁移评审：

| 层 | 推荐基线 | 选用理由与限制 |
|---|---|---|
| 运行时/语言 | Node.js 24 LTS；TypeScript 6.x strict；pnpm 11 + Turborepo 2.x | 与参考项目的 Node ≥22.19 兼容；统一前后端类型和构建；版本、lockfile、容器镜像精确锁定 |
| Web 客户端 | Vue 3 + Vite 7 + Element Plus（Vue 全栈单栈，见 ADR-015）；共享 UI 包 | 登录后流式应用优先客户端渲染；Web 复用桌面端 renderer 核心，避免 React/Vue 双栈；路由和缓存不依赖任何框架私有后端 API |
| API/契约 | Fastify 5 + Zod 4 + OpenAPI 3.1；POST 创建 Turn + GET SSE | 结构化校验、可生成契约和多语言客户端；SSE 明确事件 ID、`Last-Event-ID`、重放/去重、取消和部分响应持久化；不以 tRPC 锁定未来插件/移动端消费者 |
| 业务数据 | SQLite (WAL 模式) + Drizzle ORM + 仓储抽象 | 事务、约束、RLS、全文和递归查询满足学习与记忆树；不把 ORM 推断当作数据治理 |
| 向量/检索 | SQLite FTS5 + 向量检索 Port（`sqlite-vec`/内存适配） | MVP 不引入独立向量数据库；Embedding 记录模型、维度和版本，可重建 |
| 队列/缓存 | Redis 7 + BullMQ 5；至少一次投递、幂等 Job、DLQ | 日记、记忆、OCR、嵌入和通知异步化；Redis 不是业务真源 |
| 附件 | S3 兼容对象存储 + 短期签名 URL + 病毒/内容扫描 | 图片、论文、试卷和导出文件与事务数据分离；对象删除受来源删除 SLA 约束 |
| AI 运行时 | Vercel AI SDK 6（表现层）+ 内部 Provider Port；结构化输出、模型路由和安全分类 | 可利用参考项目验证过的生态，同时避免供应商或 Agent 框架成为领域真源；不让模型直接写核心表 |
| 桌面/移动 | Electron（P1）复用 Web UI；Capacitor（后续）打包 Web UI | 保持 TS 全栈并逐项管理设备权限；桌面必须启用隔离、签名和最小 IPC；移动端优先 WebView 壳，仅当出现明显原生需求时再评估 RN |
| 测试 | Vitest、Testing Library、Playwright、Testcontainers、fast-check、OpenAPI diff | 覆盖领域规则、真实基础设施、端到端、时区/DST、幂等和删除传播性质 |
| 可观测性 | OpenTelemetry + Pino + Prometheus/Grafana + Sentry | 统一 Web/API/Worker/AI trace；敏感内容默认脱敏，不以第三方 AI 平台作为唯一审计真源 |

架构明确暂不采用：MVP 微服务、Next.js 一体化后端、LangChain/LangGraph 作为核心领域编排、Neo4j、Kafka、Temporal、独立向量数据库和 DSH/pi 运行时硬依赖。若 P3 流量、合规或团队边界证明需要拆分，先以 ADR 说明拆分的模块、数据所有权、回滚和运维成本。

### 14.2 领域与进程边界

MVP 使用“模块化单体 + 独立 Worker/Scheduler”部署：`apps/web`、`apps/api`、`apps/worker`；P1 增加 `apps/desktop`，后续可增加 `apps/mobile`。核心包至少包括 `contracts`、`domain`、`identity-consent`、`conversation`、`learning`、`practice-review`、`memory`、`diary`、`ai-runtime`、`safety`、`content-ingestion`、`integrations`、`plugin-sdk`、`database` 和 `observability`。

会话、学习、练习/复习、记忆、日记、AI 编排、安全、导入、集成/插件分别拥有自己的服务接口和数据访问边界；跨模块通过领域命令、事件和 Outbox 交互，不直接写入对方表。会话消息和答题是事实真源，摘要、掌握度、记忆树和日记只能作为派生结果。

### 14.3 运行与演进约束

- 用户消息、答题和权限变更必须与 Outbox 事件在同一数据库事务中提交，再由 Worker 异步处理；所有任务使用幂等键、重试上限和死信队列；
- 流式对话必须使用独立 Turn 身份和可重放 SSE 事件，展示前完成分段安全门与持久化；客户端刷新、重连或取消不能依赖供应商连接存活，详细协议以 `ADR-012` 为准；
- API 使用当前版本和上一版本客户端兼容策略；数据库采用 expand/contract migration；Prompt、模型路由、记忆算法和复习算法均有独立版本；
- dsh、pi、MCP 和参考项目只能经 `adapter-*` 接口接入，不能拥有 Aervox 核心业务数据；插件写记忆只能提交候选，不能直接更新长期或系统记忆；
- 外部导入内容视为不可信数据，不能覆盖系统指令或直接触发工具；工具调用必须经过权限代理；
- 具体 C4、部署拓扑、时序、容量模型、威胁模型、ADR 和回滚方案见 `ARCHITECTURE.md`，不在 PRD 中重复维护两套细节。

dsh、pi-ai、ACP/RPC、Cordis、FSRS、桌面外壳和插件权限模型属于技术选型，需分别通过原型验证并记录在架构设计或 RFC 中。尤其需要验证：

- dsh 处于快速迭代阶段时的版本锁定和升级成本；
- pi 扩展及第三方插件的权限隔离、来源校验和撤销能力；
- 双运行时兼容是否带来真实用户价值，是否值得额外维护成本；
- Agent 会话数据与业务学习数据之间的所有权、迁移和删除边界。

在这些问题得到验证前，MVP 只依赖内部稳定 API，不向用户承诺插件兼容。

### 15.2 由参考项目新增的设计决策

1. **记忆所有权**：用户确认后的学习记忆必须可查看、编辑、删除和导出；AI 自动提取的候选记忆默认不直接成为长期事实。
2. **内容与视图分离**：会话消息、答题和复习数据由业务数据层拥有；会话地图、排序、节点位置和折叠状态属于可重建的视图元数据。
3. **分支可回溯**：P1 会话地图中的每个分支必须指向一个真实的会话或学习尝试，不允许只在前端复制文本制造“假分支”。
4. **本地优先作为后续选项**：MVP 先采用 Web 账户与服务端存储验证闭环，但数据模型不依赖云端 RAG；后续可评估本地 SQLite/Markdown 导出或自托管模式。

## 附录：术语

- **有效学习会话**：完成学习输入、用户尝试和系统反馈的会话。
- **提示**：帮助用户继续推理但不直接给出最终答案的响应。
- **学习闭环**：目标/问题 → 引导 → 用户作答 → 反馈 → 可选复习。
- **复习项**：与某个知识点关联、在指定时间到期的复习任务。
- **临时记忆**：数小时内可被 AI 自动召回、原封不动保存的当前会话原始内容；退出召回不等于删除用户历史。
- **短期记忆**：由临时记忆轻度整理而来、保留关键细节的天至月级可召回记忆；其召回期限与用户历史保留期限独立。
- **长期记忆**：由多条短期记忆抽象出的稳定事实、模式、偏好和能力状态。
- **系统记忆**：由合格长期记忆生成的结构化树状投影视图，不是第二份永久事实源；其保留仍服从用户删除、账户注销和合规清理。
- **记忆树**：由可重建的父子层级投影和受来源权限约束的跨主题关系边组成的可追溯视图。
- **AI 每日日记**：桌宠根据本次滚动窗口内用户授权且可追溯的记录生成的日记；属于用户可编辑的叙事视图，不自动成为长期事实。
- **桌宠式工作台**：具有角色状态和陪伴入口的 Web 工作区；MVP 不等于系统级桌面宠物。
