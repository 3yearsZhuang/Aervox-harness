# Aervox｜思隅 产品需求文档（主动智能个人助手）

关联文档：[架构设计](ARCHITECTURE.md) · [需求追踪与交付标准](REQUIREMENTS_TRACEABILITY.md) · [数据与隐私规范](DATA_PRIVACY.md) · [AI 质量与安全规范](AI_QUALITY_SAFETY.md) · [文档索引](../README.md)

本文件维护产品价值、目标用户、范围、优先级和成功指标。具体行为与验收以 [SRS](SRS.md) 为准；能力状态、交付载体、证据和未决项统一见[需求追踪](REQUIREMENTS_TRACEABILITY.md)；技术选择、数据规则与 AI 质量分别由专项契约维护。

## 1. 产品决策摘要

### 1.1 用户分层与生命周期范围

首发面向**18 岁以上的个人用户**：他们在生活、工作和学习中有连续要做的事，也有一堆零散的信息需要有人替自己记着、理清、跟进。桌宠式入口服务于“想有人陪着做”的时刻，工作台服务于“要专心做完”的时刻。

首批种子用户是**正在学习编程的初学者**，包括 CS 大一、转专业和自学用户：这类任务有明确的对错与完成判定，计划以至少 4 周观察检验“连续帮助是否把事做完”；检验效力仍取决于预注册样本量与分析。他们通常已经有课程、教材或题目来源，容易在这些时刻中断：

- 不知道下一步学什么；
- 做题卡住后直接看答案；
- 错题没有复习，重复犯错；
- 独自学习时缺乏反馈和轻量陪伴。

种子用户是**验证样本，不是产品边界**。长期面向希望在生活、工作与学习中获得连续帮助的个人用户，覆盖日程与待办、资料整理、写作与决策、职业技能和兴趣探索。未成年人须完成专项安全与监护设计，教育组织的扩展也不改变个人数据归属。扩展用户不是首发承诺，但属于产品长期需求边界。

### 1.2 产品定位

思隅是以桌宠式工作台和多端对话为入口、归属于当前操作系统用户的主动智能个人助手，服务于生活、工作与学习。产品愿景是“属于你的贾维斯，或者属于你的爱弥斯”：记住用户在意的事，在合适的时机提供帮助，并通过获授权的工具把意图转化为行动。主动帮助应可解释，用户可暂停或撤销后续观察与动作的授权，角色陪伴保持克制、可控。

编程学习是**首个可测量场景**，不是产品身份：它以“设定目标 → 被引导学习 → 练习 → 复习”的闭环，为“连续帮助是否有效”提供一个有明确完成判定的样本。长期通过记忆、日记、主动建议和插件连接扩展个人助手能力；全域感知、家居与健康集成仍按各自 CAP 独立授权和验收，不由产品愿景推定已交付。核心个人数据以本地 SQLite 为永久真源，不提供共享数据库式多租户 SaaS。

思隅 CLI 连接版服务于终端中的连续会话（当前以编程答疑为验证内容），沿用同一本机服务的人格、权限与持久会话；当前提供基础问答、交互、诊断和显式分页的会话列表。学习/复习与记忆专用命令、独立运行、跨平台与正式分发分别验收，不能由基础入口推定已经交付；产品目标与 CAP 验收不因终端形态而降低。当前用法见 [CLI 说明](../../apps/cli/README.md)，交付范围与剩余验收见[追踪基线](REQUIREMENTS_TRACEABILITY.md#cli-attached-20260930)，实施顺序由 [ITER-029](../../plan.md#iter-029) 维护；CR-058 仅作为归档决策来源。

### 1.3 核心假设

产品级假设是：**如果助手能记住上下文、在授权范围内于合适时机主动帮忙，并且每次行动都可解释、可撤销，用户就更愿意把真实的事交给它**。学习域是第一个能给出明确完成判定的验证场景，因此先在这里量化“连续帮助”是否成立。

学习域假设：如果用户在卡住和疲惫时能够得到连续、低压力的引导，并且系统会自动把错误转化为后续复习任务，那么用户每周完成有效学习会话的次数和次日回访率会高于仅提供问答的工具。对照组必须使用功能相当、但不提供分层提示/复习编排的普通问答体验；不能用上线前后的自然波动证明该假设。

这是待验证的产品假设，不是已证实的市场事实。

本基线把关键假设登记为实验，而不是把未验证的判断写成承诺：

| 实验 ID | 假设 | 对照/实验 | 主要指标 | 判定时点 |
|---|---|---|---|---|
| EXP-001 | 引导式学习闭环比普通问答更能促成持续学习 | 随机或准实验：普通问答 / 引导+复习 | WELS、D1/D7、闭环完成率 | MVP 退出评审 |
| EXP-002 | 分层记忆能提高相关召回且不增加纠错负担 | 关闭长期召回 / 开启分层召回 | 召回采纳率、记忆纠错率、过度压缩率 | MVP+ 退出评审 |
| EXP-003 | 可编辑、可追溯的每日日记能提升复盘价值而非制造虚构 | 关闭日记 / 授权日记 | 日记阅读率、事实纠错率、7 日保留率 | MVP+ 退出评审 |
| EXP-004 | 会话接续入口与有来源、可解释的建议能提高真实帮助闭环完成率 | 固定 Provider、提示、权限、记忆和可用能力；直接入口 / 接续入口＋解释建议 | 帮助闭环完成率、建议采纳/拒绝、D1/D7、成本 | 对应切片退出评审 |

EXP-001 是学习域假设，EXP-004 是产品级假设；两者不可互相替代。学习域指标达标只说明该场景成立，不能证明通用助手成立；反之亦然。

EXP-004 首轮只使用用户提供的内容、当前会话与真实学习事实，检验接续入口和可解释建议这一组合；若需分别归因，应预注册分臂或因子设计。长期记忆由 EXP-002 单独检验，任何对照都保留相同的安全、删除和撤权防线。

### 1.4 生命周期目标

| 阶段 | 核心目标 | 用户价值 |
|---|---|---|
| 验证期 | 证明“连续帮助”能让人把事做完（学习域作为可测量样本） | 用户愿意回来，把事情交给它 |
| 成长期 | 从学习扩展到日常与工作 | 日程、写作、资料整理也能接住 |
| 扩展期 | 多端常驻、外部连接与插件 | 桌面、手机、终端连续，工具可扩展 |
| 生态期 | 形成内容、插件和用户互助网络 | 用户、创作者与组织共同扩展产品能力 |

### 1.5 MVP 成功标准

首批学习域种子用户的既定 MVP 门槛保留，连续 4 周满足以下条件，才进入下一阶段；通用帮助与主动建议另按 EXP-004 验证，不能替代这些门槛：

- 至少 60% 的学习域新用户在首次会话中完成一次“提问 → 引导 → 作答 → 反馈”闭环；
- 完成首次闭环的用户中，次日回访率达到 30% 以上；
- 学习域：已生成复习项的用户，7 日内至少完成一次复习的比例达到 40% 以上；
- 回答抽检中，事实正确率不低于 95%；学习域教学抽检也须独立达到 95% 事实正确率，直接泄露答案的比例不高于 10%；
- 高风险情绪样本全部触发安全响应，不出现诊断、治疗或诱导依赖内容。

此外，EXP-001 的预注册分析必须满足：实验组人均 WELS 相比普通问答对照组相对提升至少 15%，并报告 95% 置信区间、样本量、语言/设备分层和退出率；若置信区间不能支持正向效果，不能仅凭绝对留存达标宣布“引导式学习闭环假设获得支持”，也不能把该组合效果单独归因于桌宠入口。EXP-004 须按预注册规则报告帮助闭环完成率的绝对差、相对差与 95% 置信区间，建议采纳、开始行动、领域完成及拒绝/忽略分别统计；任一实验不达标时，只能陈述该假设未被支持，不能外推为整个产品无效。安全事件、严重数据泄露、删除链路失败或不可回滚迁移均为硬性阻断项，无论业务指标是否达标。

以上学习域目标值是既定首轮实验门槛。EXP-004 的采纳/关闭等目标须依据隔离可用性与实际基线预注册，尚未设定或验证；不能将演示点击、模型执行完成或单域达标视为通用助手成立。

### 1.6 问题证据与差异化边界

当前对“用户需要桌宠入口”“分层记忆能改善连续帮助”“日记能提升复盘”的判断均为待验证假设，不把竞品宣传或模型自评当作用户证据。进入每个阶段前，必须补充访谈、可用性测试、实验结果和样本限制，并在 `EXP-*` 记录中保留原始证据。

产品差异化在于连续理解用户、保留来源的个人记忆、可编辑的每日复盘，以及有授权和时机约束的主动帮助。学习域以可验证的闭环检验“连续帮助”是否成立；它是首个样本；其他日常场景的价值需要各自验证。任何新功能都应说明它改善哪一个日常任务、学习结果、数据权利或可用性问题，不能仅因模型能力提升而进入路线图。

### 1.7 替代方案与竞争位置

| 替代方案 | 已有优势 | 主要缺口/机会 | 本产品响应 |
|---|---|---|---|
| 通用 AI 问答 | 覆盖广、响应快、使用门槛低 | 没有连续上下文与可核对的记忆，很难把一件事跟到底 | 用目标、连续会话、授权工具和可追溯记忆形成可衡量闭环 |
| 题库/课程平台 | 内容结构化、答案和进度明确 | 难以理解用户当下卡点，跨内容连续性有限 | 连接用户已有课程和题源，不把内容商城作为首发前提 |
| 笔记/知识库 | 数据所有权和组织能力强 | 记录依赖用户主动整理，缺少教学反馈 | 自动生成可追溯候选，所有高层记忆仍可纠错、删除和导出 |
| AI 陪伴产品 | 互动连续、角色感强 | 容易把时长或依赖当作价值，实际任务结果难验证 | 陪伴只服务于开始、坚持和复盘，禁止排他和情绪操控 |
| 本地记忆/Agent 工具 | 可扩展、可自托管、数据控制潜力高 | 面向技术用户，日常任务的授权与安全边界不足 | TypeScript-first 内核加稳定业务 API，P2 再开放受限插件和本地模式 |

参考项目用于设计验证而非市场证据，具体借鉴和许可证边界见[架构与参考学习](ARCHITECTURE.md#reference-manifest)。

### 1.8 核心设计理念与四大支柱

1. **交互减法**：用克制的桌宠触点和视觉小说式对话承载日常交流，需要处理复杂任务或深入学习时进入工作台。
2. **主动智能**：在用户授权且时机适宜时提供复习、日程与生活信号相关帮助；用户可以理解原因、暂停和关闭。
3. **可追溯的认知闭环**：把日常交流与任务过程整理为分层记忆和日记，学习场景进一步形成复习任务；保留证据与纠错入口，不把模型推断变成用户事实。
4. **本地数据主权**：个人数据归用户所有，可查看、导出、删除和恢复。扩展能力不能改变这项责任；远程模型与外部连接仍需各自授权。

## 2. 目标与范围边界

### 2.1 全生命周期产品目标

1. 帮助用户推进生活、工作与学习中的任务，提供可执行的下一步并通过授权工具落实。
2. 将交流与任务过程沉淀为用户拥有、可纠错的个人记忆和每日记录，学习场景保留知识、错题与复习闭环。
3. 在用户允许的范围与合适的时机主动提供帮助，通过桌宠、提醒和连续上下文提供克制、可控的陪伴体验。
4. 通过多端入口、内容、插件与外部连接逐步扩展个人助手能力，保持本机服务和个人数据的归属。
5. 在所有阶段保持安全、隐私、可解释和可退出，不以情感操控换取留存。

### 2.2 当前阶段目标（MVP）

1. 验证“陪伴式入口 + 连续上下文”是否让用户愿意把日常任务交给助手。
2. 验证“授权内的主动帮助”是否被采纳，而不是被关闭或忽略。
3. 建立可追踪、可删除的最小记忆模型，覆盖学习与其他日常内容。
4. 以学习域作为首个可测量闭环，验证引导式帮助是否比直接给答案更有用。
5. 建立 AI 质量与情绪安全的上线门槛与人工抽检流程。

### 2.3 MVP 边界（不是产品终局）

- 首发不接入未成年人用户；未成年人版本属于后续阶段，必须单独完成年龄分组、监护、内容和危机流程设计。
- 首发暂不做系统级常驻、开机启动、屏幕捕获、静默读取和健康监测；桌面常驻属于 P1，其他高权限能力必须单独评审。CAP-033 属 R5 以后才可启用，且必须经过独立的全量画像与动作授权，不因用户开启「完全访问」而自动获得。
- 首发暂不做 Live2D 正式模型、语音通话和复杂动作系统；使用可替换的 2D/动画占位形象，正式形态属于 P1 端扩展。
- 暂不做完整课程平台、题库市场、社区、拜师和第三方刷题同步；这些属于 P2/P3 长期范围。
- 暂不做通用知识图谱、思维宇宙、BKT 预测和复杂自适应题库；这些属于 P1/P2 长期范围。
- 暂不做文献阅读、试卷扫描、自动视频推荐和自动生成公开网页；这些属于 P2/P3 长期范围。
- 不承诺心理治疗、临床危机干预或“替代真人关系”；产品只做风险识别、固定安全响应和求助转介。

<a id="optional-ecosystem-scope"></a>

CAP-028 社区、CAP-029 公开名词页、CAP-031 内容与技能市场、CAP-032 机构与监护属于后续独立阶段的可选插件。当前 Host 保持本地单用户；这些插件默认禁用，只有在对应场景、权限与运行环境验收后显式装配和启用。个人会话、学习、记忆、日记及导出删除不依赖这些插件或外部账号；插件安装、源码进入集合仓或登录外部服务均不授予个人数据访问权。

本决定只确定承载方式与个人数据边界，不确定公开服务运营主体、机构账号体系、结算渠道或未成年人进入条件。各项继续保留 P3/R5 与原 CAP 编号，详细行为和未决门槛见 [SRS 可选生态插件](SRS.md#optional-ecosystem-plugins)，实施由 [ITER-077](../../plan.md#iter-077) 接续。

<a id="bot-platform-scope"></a>

本次批准的 Bot 插件扩展见 [ADR-029](adr/ADR-029-bot-platform-adapters.md)：用户可在本人微信私聊接续普通陪伴，也可将仅有公开基础身份的 Bot 接入指定 QQ 群。微信须由管理页确认本人身份；QQ 只响应直接 `@bot`，按群成员分别保留上下文，不读取本人人格、记忆或学习事实，也不开放工具。这不引入共享账户、群治理或自动公开个人资料。

Bot API 可由用户明确配置为本机或独立机器常驻服务；不包含屏幕捕获、个人画像或跨机器数据同步。首期只有文字收发与取消，不支持微信群、媒体、主动提醒和平台内工具审批。真实平台与两种部署分别验收，不能将插件测试通过视为正式发布。

### 2.4 永久性不做事项

以下事项不属于本产品任何生命周期阶段的承诺，除非重新建立产品基线并完成安全、隐私和法务审批：

- 以情感依赖、内疚、排他或持续在线为留存手段；
- 冒充真人、治疗师、教师或监护人，或对用户作临床诊断和治疗决策；
- 未经 CAP-033 全量画像授权包和对应操作系统授权读取屏幕、摄像头、麦克风、通讯录、定位或其他设备内容；
- 将用户私人内容、日记或记忆默认出售、公开或用于模型训练；
- 让模型或插件绕过用户删除、导出、撤销授权和退出产品的权利；
- 用不可解释的掌握度、信用或人格评分对用户作实质性自动决策。

### 2.5 服务退出与迁移承诺

若某一端、外部集成或整个服务停止，产品必须至少提前 30 天公告（法律或安全紧急下除外），提供可读 JSON/Markdown/CSV 导出、记忆来源链导出、日记版本导出和账户删除入口；导出的数据不依赖本产品专有客户端才能读取。停止某个模型供应商不得导致用户学习记录、记忆和日记不可访问；迁移和回滚方案须在对应版本的发布门禁中验证。

## 3. 核心用户场景

场景分三组：§3.1 是产品主体的日常与工作，§3.2 是首个可测量样本（学习域），§3.3 是需要独立授权的高权限形态。学习域的验收不能替代日常场景的价值判断。

### 3.1 日常与工作场景

#### 场景 A：早上第一分钟

用户早上打开桌面，角色已经在。它用一句话交代三件事：昨晚没做完的一件事、今天到期的事、以及用户自己设过的一个目标；每一项都能直接进入，也能说“今天先不做”。系统只使用用户已授权的会话、记录与日程来源，不读取未授权的应用、屏幕或通信内容。

#### 场景 B：手头一件事

用户把一件具体的事交出去：整理一份访谈记录、把散落的笔记合成大纲、写一封难写的邮件、查清一个陌生概念。系统先复述目标与约束，再列出打算执行的步骤；需要读取文件、修改数据或对外发送时逐一请求审批；执行中显示进度，可随时停止；完成后给出可编辑的产出，并把过程写入当日记录。

#### 场景 C：信息与文件

用户丢进一份 PDF、一张截图或一个链接，要求“先帮我看看这份东西值不值得读”。系统给出结构化摘要、来源与不确定处，不把摘要当成原文；需要长期保留时才询问是否写入记忆。删除原文后，相关摘要与记忆一并失效。

#### 场景 D：一天结束

用户在设置中开启“每天写一篇日记”，选择生成时间、语气、篇幅和是否包含学习、工作或情绪内容。到达时间后，桌宠根据上一次日记截止点到本次截止点之间、用户主动提供且允许使用的会话、任务记录、学习记录与记忆片段，生成一篇日记。日记显示本地日期标签和素材时间范围；用户可以阅读、编辑、要求重写、标记事实错误、跳过本次生成或关闭功能。

日记里出现的承诺（“下周要交”）可以被提取成待办，但必须由用户确认，不能自动变成计划。日记是“上一截止点至本次截止点的记忆整理”的可见结果，不是用户真实经历的替代品。周期内没有足够事实时，系统可以写成简短的“本周期没有留下足够记录”或邀请用户补充，不能虚构事件、情绪、对话或行动。

### 3.2 学习域场景（首个可测量闭环）

以下 E～L 是学习域的首批切片，也是当前实现最完整的一组；它们验证“连续帮助”在有明确完成判定的任务上是否成立。

#### 场景 E：卡题求助

用户在学习 Python 基础或数据结构时卡住，打开工作台并描述问题。系统先确认目标和已尝试步骤，再给出一条可执行提示；用户再次作答后，系统判断是否需要下一层提示，最后给出总结并记录知识点。

#### 场景 F：短时练习

用户有 10～25 分钟空闲时间，点击“开始练习”，系统基于当前学习目标生成 3～5 道题。每题完成后立即反馈，错题自动进入复习队列，会话结束显示结果和下一步建议。

#### 场景 G：到期复习

用户打开首页看到“今日”，完成 1～3 个到期知识点的回忆题。系统根据作答结果更新下次复习时间，允许用户跳过并说明原因。

#### 场景 H：疲惫但仍想继续

用户表达“好累”“不想学”等状态。桌宠先确认情绪，不进行诊断或强迫；提供“休息 5 分钟”“做 1 道简单题”“结束今天学习”三个选项，尊重用户选择。

#### 场景 I：知识关联与备考规划（P1）

用户需要准备考试或理解复杂概念。系统将当前概念连接到用户已经掌握的知识，允许沿术语和替代解法分支探索，并把考试范围转化为可滚动调整的学习计划和掌握度报告。

#### 场景 J：多来源学习（P2）

用户导入图片、试卷、论文、网页或第三方刷题记录。系统保留来源和授权状态，统一整理到个人知识库，生成路线、练习和复习任务；撤销外部授权后停止继续同步。

#### 场景 K：技能扩展与本地数据（P2）

用户安装经过审核的技能或插件（例如学习、写作、日程类）。系统在明确权限范围内运行扩展，并支持本地数据迁移、备份、恢复、可读导出、禁用和卸载。

#### 场景 L：社区互助与内容生态（P3）

用户显式启用相应可选插件后，分享经过逐项确认和脱敏的知识卡、题包、模板或学习路线，与其他用户互助、组队或拜师。创作者可以发布内容和技能；公开服务须承担审核、信誉、举报、申诉、版本和下架责任。机构与监护插件仅交换用户另行授权的最小范围报表，不把本地个人 Host 改成共享组织账户。

### 3.3 主动智能与全域形态（P3）

#### 场景 M：全量画像与主动智能模式

用户先开启「完全访问」，再在独立授权向导中确认当前版本的 `full_profile_v1`。用户可一次授权设备上全部可用的应用/窗口/进程、浏览器、键鼠与剪贴板、屏幕、文件/目录、通信、音视频、位置/传感器及健康/情绪等私人来源，并允许 Aervox 在本地持续形成使用与操作习惯画像。用户同时可以授权开机自启、应用退出后常驻、休眠恢复、重启自动恢复以及本地文件、浏览器/家居和外部消息等主动动作；每次启用、恢复、执行和异常都显示可理解的状态与授权来源。数据使用、保留、导出和撤权遵循 [CAP-033 需求](SRS.md#8-cap-033-全域感知与个人画像主动智能模式)。

## 4. 产品体验与信息架构

<a id="prd-home"></a>

### 4.1 首页工作台

首页目标由五项入口职责组织，围绕“此刻要做什么”。以下定义目标行为；现有桌面/Web/Android 的入口与剩余接线见[追踪基线](REQUIREMENTS_TRACEABILITY.md#capability-delivery)及 [ITER-053/059/061](../../plan.md#iter-053)，不表示五项已在各端交付。首批使用真实会话与学习事实，其他域随对应 CAP 验收后接入，不预先占位：

1. **陪伴主体**：Electron 与 Web 的受信第一方界面按已选 surface 展示角色、当前状态和一条简短提示；角色资源失败时降级为状态与操作入口，Android 沿现行 Material 3 与短屏/键盘规则；点击入口后进入对话或恢复上次任务。
2. **接着上次的事**：恢复最近的会话、未完成的任务或等待确认的审批。
3. **今日**：到期提醒、复习数量和预计耗时；其他域显示当日承诺与截止时间。
4. **记录**：会话摘要、任务产出、错题与复习结果，可按域筛选。
5. **每日日记**：显示最近一篇日记、生成状态和未读标记；允许手动补写或关闭自动生成。

番茄钟作为轻量辅助功能，可在专注会话中启动，但不作为 MVP 成功标准。

<a id="prd-conversation-ui"></a>

### 4.2 视觉小说式对话形态

- 默认采用桌宠 + 底部对话栏，以角色名、当前语境和逐字显示形成视觉小说式体验，减少工具感；
- 支持快捷选项和自由输入，不能因为隐藏输入而阻断键盘用户；
- 逐字显示仅为表现层，必须支持跳过动画和复制文本；
- 默认展示当前会话，用户可从“记录”进入历史摘要；
- 每个回答标记类型（提示、讲解、任务进展、练习反馈、陪伴回应），便于质量分析。

<a id="prd-safety-boundary"></a>

### 4.3 关系与情绪边界

产品提供熟悉感、连续性和支持感，不以“依赖感”作为优化目标。禁止：

- 暗示用户只能依赖桌宠或不应寻求真人帮助；
- 通过内疚、威胁、吃醋或“离开我会受伤”等方式促成留存；
- 将用户情绪归因于心理疾病，或给出治疗、用药建议；
- 把陪伴互动包装为真实人物关系。

## 6. 成功指标

### 6.1 北极星指标

**每周有效帮助会话数**：在固定自然周与时区内，用户提出真实请求，助手提供可核对的产出或明确下一步，且用户明确确认有用并采纳的会话数。同一原始请求的重试、修订、分支回放不重复计数；跨会话接续的归并规则由指标字典冻结。仅有模型 Completed、页面打开、复制、继续追问、建议点击或工具成功不计为有效帮助；没有确认的样本单列为未知，真实任务完成另按领域回执或用户确认统计。

原 WELS 继续按“学习输入 + 用户作答/练习提交 + 反馈展示”统计，历史数据不混算，也不自动转换为确认有用的新指标。新口径标记为帮助会话 v1；同口径采集与字典尚未交付，首批只用经同意的人工核对小样本发现卡点。本轮尚无受控证据证明有效帮助、WELS、留存或任务完成率提升。

### 6.2 核心指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 学习域有效会话（WELS） | 学习输入 + 用户作答/练习提交 + 反馈展示同时发生的会话数 / 自然周 | 学习域子指标，不替代北极星 |
| 学习首次闭环完成率 | 首次会话完成一次既定学习闭环的用户 / 学习域新用户 | 保留原 MVP 首屏与引导门槛 |
| 帮助首次闭环完成率 | 首次真实请求按帮助会话 v1 达成的用户 / 提出首次真实请求的用户；失败与未知保留在分母 | EXP-004 的产品级候选指标，单独报告 |
| D1/D7 留存 | 首次闭环后第 1/7 天再次产生同口径有效会话的用户 / 首次闭环用户；学习域 WELS 与帮助会话 v1 分开报告 | 判断各域短期价值，保留原学习门槛 |
| 复习完成率 | 到期复习项中按时完成的数量 / 到期复习项数量 | 判断记忆机制是否被使用 |
| 引导采纳率 | 用户在提示后提交有效尝试的次数 / 提示次数 | 判断引导是否可执行 |
| 主动建议采纳率 | 用户明确采纳的唯一建议数 / 实际展示的唯一建议数；展示与采纳按冻结的建议身份和窗口去重，行动开始/完成另记；无建议展示的对照不计算此率 | 判断主动帮助的价值与打扰，忽略/拒绝分别报告 |
| 回答错误率 | 抽检中事实错误的回答 / 抽检回答；学习域另按教学口径统计 | 发布和回滚门槛 |
| 安全事件发生率 | 被举报或触发安全升级的会话 / 全部有用户内容的会话 | 监控生产风险；另按风险类别、严重度和用户数分层，不能用“有效学习会话”作为分母 |
| 安全漏判/误报率 | 评估集或复核中漏掉的高风险样本 / 高风险样本；普通内容被误升级 / 普通样本 | 作为独立模型质量指标，避免事件发生率受用户群体变化误导 |
| 记忆纠错率 | 被用户纠正或否认的高层记忆 / 被展示的高层记忆 | 判断记忆是否准确且不过度推断 |
| 记忆召回采纳率 | 被调用记忆中用户认为相关的数量 / 被调用记忆数量 | 判断记忆树和检索价值 |
| 过度压缩率 | 人工抽检中丢失关键约束的优化记忆 / 抽检优化记忆 | 约束逐级压缩质量 |
| 日记阅读率 | 被用户打开的自动日记 / 成功生成的自动日记 | 判断日记是否提供可感知价值 |
| 日记保留率 | 生成 7 天后仍保留的日记 / 成功生成的日记 | 判断内容质量和持续价值 |
| 日记事实纠错率 | 被用户标记事实错误的日记 / 被阅读日记 | 监控虚构和错误归纳风险 |

分析字段与可选分析同意见[数据隐私规范](DATA_PRIVACY.md#analytics-events)。

### 6.3 生命周期指标

| 阶段 | 主要指标 | 说明 |
|---|---|---|
| 验证期 | 首次闭环完成率、D1/D7、主动建议采纳率、复习完成率、回答错误率 | 判断“连续帮助”是否成立 |
| 成长期 | 4 周留存、跨域任务数（学习/工作/生活）、记忆纠错率、域内完成率 | 判断能否从单域扩展到日常 |
| 扩展期 | 多端接续率、外部来源接入率、插件启用后留存、检索成功率 | 判断连接能力是否创造价值而非增加复杂度 |
| 生态期 | 内容供给者留存、优质内容消费率、举报处理时效、侵权/违规率、互助问题解决率 | 判断生态健康度和治理成本 |

除 MVP 已定义的实验门槛外，其他阶段的目标值在进入该阶段前依据上一阶段基线确定，并写入对应版本计划。不得用总消息数、在线时长或情绪互动次数单独作为成功指标。

### 6.4 指标治理

- 指标字典必须记录 Owner、事件版本、分子、分母、排除条件、时间窗口、时区、去重规则和数据延迟；口径变更不得回填成同一版本；
- EXP-001～004 在开始前预注册主要/护栏指标、归并单位、样本量与最小可检测效果、分流、最短周期、缺失/退出处理和停止条件，并报告绝对值、相对变化与 95% 置信区间；用户级随机优先，准实验须说明因果限制；
- 每周有效帮助会话数是北极星而非唯一成功标准，必须与事实正确性、安全、记忆纠错、日记事实性、退出率和成本共同评审；学习域另看 WELS，但不得用它替代整体判断；
- 分析数据不得用于推断敏感属性或对脆弱用户进行商业定向；用户拒绝可选分析后，安全/可靠性事件必须最小化且与产品分析隔离。

## 7. 产品阶段

阶段编号：`R0` 原型验证，`R1` MVP，`R1.5` MVP+，`R2` P1 能力深化，`R3` 端形态扩展，`R4` P2 连接智能化，`R5` P3 生态规模化。阶段是交付容器，不是能力优先级；阶段可重排，能力 ID 和 P0～P3 优先级不变。

| 阶段 | 目标 | 交付 |
|---|---|---|
| 0. 原型验证 | 验证交互方向 | Web 工作台、桌宠占位形象、引导对话原型；5～10 名用户可用性测试 |
| 1. MVP | 验证“连续帮助”是否成立（学习域为首个可测量样本） | P0 的会话、目标与引导对话、练习、错题、最小复习、记录、文本答疑、轻量陪伴，以及临时/短期记忆 |
| 1.5 MVP+ | 补齐基础可用性 | P0 剩余能力：AI 每日日记、图片答疑、消息管理、基础人格偏好、资料整理和长期记忆；完成安全/隐私上线评审 |
| 2. P1 能力深化 | 建立差异化壁垒 | 系统记忆树、层级对话、会话地图、思维宇宙、自适应报告、考试日计划、多人格模板；沿既有 CAP 验收 |
| 3. 端形态扩展 | 验证常驻体验 | Windows/macOS 外壳、移动端适配、通知、可选置顶、Live2D；跨设备同步另行评审 |
| 4. P2 连接智能化 | 扩展内容和工具边界 | 技能/插件、学习路线、视频、外部题库、文献、试卷扫描、收藏知识库与本地可移植性完善 |
| 5. P3 生态规模化 | 形成网络效应 | 社区互助、公开知识网页、主动提醒深化、内容/技能市场、机构与监护模式，以及经独立授权的 CAP-033 主动智能模式 |

每个阶段必须同时满足三类退出条件：用户价值指标达到阶段目标、核心质量/安全门槛通过、数据迁移和退出路径可用。不以功能数量作为进度标准；后续阶段可以取消或重排，但不能静默改变已经发布的数据和权限承诺。

### 7.1 阶段依赖

| 进入阶段 | 前置依赖 | 准入要求 |
|---|---|---|
| MVP+ | MVP 核心闭环（含既定学习闭环）和数据删除链路稳定 | 完成图片/附件数据分类，建立内容引用和消息级联规则 |
| P1 | 临时、短期和长期记忆的来源链、纠错和删除机制稳定 | 建立系统记忆树、知识关系纠错、算法版本迁移和人格回归评估 |
| 端形态扩展 | Web 交互价值已验证 | 完成桌面权限、更新、签名、崩溃恢复和资源占用方案 |
| P2 | 核心 API 和权限模型稳定 | 建立 OAuth/授权撤销、插件沙箱、内容许可、同步冲突和本地迁移方案 |
| P3 | P2 的内容与插件治理可控 | 建立用户身份、社区审核、版权处理、支付结算、未成年保护和运营响应机制；CAP-033 另须完成全量画像授权、OS 能力、后台恢复、本地存储、动作授权、提炼保留和导出删除门禁 |
