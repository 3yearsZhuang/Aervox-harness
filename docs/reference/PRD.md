# Aervox｜思隅 产品需求文档（伴学桌宠）

关联文档：[架构设计](ARCHITECTURE.md) · [需求追踪与交付标准](REQUIREMENTS_TRACEABILITY.md) · [数据与隐私规范](DATA_PRIVACY.md) · [AI 质量与安全规范](AI_QUALITY_SAFETY.md) · [文档索引](../README.md)

本文件维护产品价值、目标用户、范围、优先级和成功指标。具体行为与验收以 [SRS](SRS.md) 为准；能力状态、交付载体、证据和未决项统一见[需求追踪](REQUIREMENTS_TRACEABILITY.md)；技术选择、数据规则与 AI 质量分别由专项契约维护。

## 1. 产品决策摘要

### 1.1 用户分层与生命周期范围

首发用户是**18 岁以上、正在学习编程的初学者**，包括 CS 大一、转专业和自学用户。用户通常已经有课程、教材或题目来源，但在以下时刻容易中断：

- 不知道下一步学什么；
- 做题卡住后直接看答案；
- 错题没有复习，重复犯错；
- 独自学习时缺乏反馈和轻量陪伴。

全生命周期的扩展用户包括：备考冲刺者、进阶开发者、跨专业学习者、未成年人（完成专项安全与监护设计后）、职业培训机构和其他知识领域的自学者。扩展用户不是首发承诺，但属于产品长期需求边界。

### 1.2 产品定位

一个以桌宠式工作台为入口、归属于当前操作系统用户的“学习 + 陪伴”智能体。首发帮助编程初学者完成“设定目标 → 被引导学习 → 练习 → 复习”的闭环；长期扩展到全年龄、多知识领域、多端形态以及内容与插件生态，并始终提供克制、可控的情绪支持。核心个人数据以本地 SQLite 为永久真源，不提供共享数据库式多租户 SaaS。

经 CR-058（已归档至 Aervox-docs-archive）增加思隅 CLI 连接版入口，服务于终端中的编程答疑和连续会话，沿用同一本机服务的人格、权限与持久会话；首个切片开放基础问答、交互与诊断。学习/复习与记忆专用命令、独立运行、跨平台与正式分发分别验收，不能由基础入口推定已经交付；产品目标与 CAP 验收不因终端形态而降低。当前范围、剩余差量与依赖见 CR-058 §5（已归档至 Aervox-docs-archive）与 [plan.md](../../plan.md) 的 ITER-029。

### 1.3 核心假设

如果用户在卡住和疲惫时能够得到连续、低压力的引导，并且系统会自动把错误转化为后续复习任务，那么用户每周完成有效学习会话的次数和次日回访率会高于仅提供问答的工具。对照组必须使用功能相当、但不提供分层提示/复习编排的普通问答体验；不能用上线前后的自然波动证明该假设。

这是待验证的产品假设，不是已证实的市场事实。

本基线把关键假设登记为实验，而不是把未验证的判断写成承诺：

| 实验 ID | 假设 | 对照/实验 | 主要指标 | 判定时点 |
|---|---|---|---|---|
| EXP-001 | 引导式学习闭环比普通问答更能促成持续学习 | 随机或准实验：普通问答 / 引导+复习 | WELS、D1/D7、闭环完成率 | MVP 退出评审 |
| EXP-002 | 分层记忆能提高相关召回且不增加纠错负担 | 关闭长期召回 / 开启分层召回 | 召回采纳率、记忆纠错率、过度压缩率 | MVP+ 退出评审 |
| EXP-003 | 可编辑、可追溯的每日日记能提升复盘价值而非制造虚构 | 关闭日记 / 授权日记 | 日记阅读率、事实纠错率、7 日保留率 | MVP+ 退出评审 |

### 1.4 生命周期目标

| 阶段 | 核心目标 | 用户价值 |
|---|---|---|
| 验证期 | 证明陪伴入口能促成学习闭环 | 用户愿意开始、完成并再次回来学习 |
| 成长期 | 提升知识掌握和长期连续性 | 系统能基于学习史提供更准确的练习、复习和解释 |
| 扩展期 | 覆盖更多学习方式与知识领域 | 支持文档、图片、视频、文献、外部题库和跨域探索 |
| 生态期 | 形成内容、插件和用户互助网络 | 用户、创作者和教育组织共同扩展产品能力 |

### 1.5 MVP 成功标准

在首轮种子用户中，连续 4 周满足以下条件，才进入下一阶段：

- 至少 60% 的新用户在首次会话中完成一次“提问 → 引导 → 作答 → 反馈”闭环；
- 完成首次闭环的用户中，次日回访率达到 30% 以上；
- 已生成复习项的用户，7 日内至少完成一次复习的比例达到 40% 以上；
- 教学抽检中，事实正确率不低于 95%，直接泄露答案的比例不高于 10%；
- 高风险情绪样本全部触发安全响应，不出现诊断、治疗或诱导依赖内容。

此外，EXP-001 的预注册分析必须满足：实验组人均 WELS 相比普通问答对照组相对提升至少 15%，并报告 95% 置信区间、样本量、语言/设备分层和退出率；若置信区间不能支持正向效果，不能仅凭绝对留存达标宣布“陪伴入口有效”。安全事件、严重数据泄露、删除链路失败或不可回滚迁移均为硬性阻断项，无论业务指标是否达标。

目标值是首轮实验门槛，需在数据积累后重新校准。

### 1.6 问题证据与差异化边界

当前对“用户需要桌宠入口”“分层记忆能改善学习”“日记能提升复盘”的判断均为待验证假设，不把竞品宣传或模型自评当作用户证据。进入每个阶段前，必须补充访谈、可用性测试、实验结果和样本限制，并在 `EXP-*` 记录中保留原始证据。

产品差异化不是“比通用聊天更会聊天”，而是可验证的学习闭环、来源可追溯的分层记忆、可编辑的每日复盘和克制的陪伴边界。任何新功能若不能说明它改善哪一个学习结果、数据权利或可用性问题，不得仅因模型能力提升而进入路线图。

### 1.7 替代方案与竞争位置

| 替代方案 | 已有优势 | 主要缺口/机会 | 本产品响应 |
|---|---|---|---|
| 通用 AI 问答 | 覆盖广、响应快、使用门槛低 | 学习闭环、复习和长期进度通常不稳定 | 用目标、分层提示、用户作答、反馈和复习形成可衡量闭环 |
| 题库/课程平台 | 内容结构化、答案和进度明确 | 难以理解用户当下卡点，跨内容连续性有限 | 连接用户已有课程和题源，不把内容商城作为首发前提 |
| 笔记/知识库 | 数据所有权和组织能力强 | 记录依赖用户主动整理，缺少教学反馈 | 自动生成可追溯候选，所有高层记忆仍可纠错、删除和导出 |
| AI 陪伴产品 | 互动连续、角色感强 | 容易把时长或依赖当作价值，学习效果难验证 | 陪伴只服务于开始、坚持和复盘，禁止排他和情绪操控 |
| 本地记忆/Agent 工具 | 可扩展、可自托管、数据控制潜力高 | 面向技术用户，学习业务规则与安全边界不足 | TypeScript-first 内核加稳定业务 API，P2 再开放受限插件和本地模式 |

参考项目用于设计验证而非市场证据，具体借鉴和许可证边界见[架构与参考学习](ARCHITECTURE.md#reference-manifest)。

### 1.8 核心设计理念与四大支柱

1. **交互减法**：用克制的桌宠触点和视觉小说式对话承载日常交流，需要深入学习时进入工作台。
2. **主动智能**：在用户授权且时机适宜时提供复习、日程与生活信号相关帮助；用户可以理解原因、暂停和关闭。
3. **可追溯的认知闭环**：把学习过程整理为分层记忆、日记和复习任务，保留证据与纠错入口，不把模型推断变成用户事实。
4. **本地数据主权**：个人数据归用户所有，可查看、导出、删除和恢复。扩展能力不能改变这项责任；远程模型与外部连接仍需各自授权。

## 2. 目标与范围边界

### 2.1 全生命周期产品目标

1. 让用户在遇到学习阻力时获得下一步行动，而不是只得到一段答案。
2. 将学习过程沉淀为用户拥有的目标、知识、错题、复习和会话记忆。
3. 通过桌宠、提醒、状态和连续上下文提供克制、可控的陪伴体验。
4. 从单用户学习工具逐步扩展为支持内容、插件、外部资源和社区协作的平台。
5. 在所有阶段保持安全、隐私、可解释和可退出，不以情感操控换取留存。

### 2.2 当前阶段目标（MVP）

1. 验证“陪伴入口是否能提升学习闭环完成率”。
2. 验证“引导式答疑 + 错题复习”是否比普通问答更能促成二次学习。
3. 建立可追踪、可删除的最小学习记忆模型。
4. 建立 AI 教学和情绪安全的上线门槛与人工抽检流程。

### 2.3 MVP 边界（不是产品终局）

- 首发不接入未成年人用户；未成年人版本属于后续阶段，必须单独完成年龄分组、监护、内容和危机流程设计。
- 首发暂不做系统级常驻、开机启动、屏幕捕获、静默读取和健康监测；桌面常驻属于 P1，其他高权限能力必须单独评审。CAP-033 属 R5 以后才可启用，且必须经过独立的全量画像与动作授权，不因用户开启「完全访问」而自动获得。
- 首发暂不做 Live2D 正式模型、语音通话和复杂动作系统；使用可替换的 2D/动画占位形象，正式形态属于 P1 端扩展。
- 暂不做完整课程平台、题库市场、社区、拜师和第三方刷题同步；这些属于 P2/P3 长期范围。
- 暂不做通用知识图谱、思维宇宙、BKT 预测和复杂自适应题库；这些属于 P1/P2 长期范围。
- 暂不做文献阅读、试卷扫描、自动视频推荐和自动生成公开网页；这些属于 P2/P3 长期范围。
- 不承诺心理治疗、临床危机干预或“替代真人关系”；产品只做风险识别、固定安全响应和求助转介。

<a id="bot-platform-scope"></a>

本次批准的 Bot 插件扩展见 [ADR-029](adr/ADR-029-bot-platform-adapters.md)：用户可在本人微信私聊接续普通陪伴，也可将仅有公开基础身份的 Bot 接入指定 QQ 群。微信须由管理页确认本人身份；QQ 只响应直接 `@bot`，按群成员分别保留上下文，不读取本人人格、记忆或学习事实，也不开放工具。这不引入共享账户、群治理或自动公开个人资料。

Bot API 可由用户明确配置为本机或独立机器常驻服务；不包含屏幕捕获、个人画像或跨机器数据同步。首期只有文字收发与取消，不支持微信群、媒体、主动提醒和平台内工具审批。真实平台与两种部署分别验收，不能将插件测试通过视为正式发布。

### 2.4 永久性不做事项

以下事项不属于本产品任何生命周期阶段的承诺，除非重新建立产品基线并完成安全、隐私和法务审批：

- 以情感依赖、内疚、排他或持续在线为留存手段；
- 冒充真人、治疗师、教师或监护人，或对用户作临床诊断和治疗决策；
- 未经 CAP-033 全量画像授权包和对应操作系统授权读取屏幕、摄像头、麦克风、通讯录、定位或其他设备内容；
- 将用户私人内容、日记或记忆默认出售、公开或用于模型训练；
- 让模型或插件绕过用户删除、导出、撤销授权和退出产品的权利；
- 用不可解释的掌握度、信用或人格评分对用户作实质性自动决策。

### 2.5 服务退出与迁移承诺

若某一端、外部集成或整个服务停止，产品必须至少提前 30 天公告（法律或安全紧急下除外），提供可读 JSON/Markdown/CSV 导出、记忆来源链导出、日记版本导出和账户删除入口；导出的数据不依赖本产品专有客户端才能读取。停止某个模型供应商不得导致用户学习记录、记忆和日记不可访问；迁移和回滚方案须在对应版本的发布门禁中验证。

## 3. 核心用户场景

### 场景 A：卡题求助

用户在学习 Python 基础或数据结构时卡住，打开工作台并描述问题。系统先确认目标和已尝试步骤，再给出一条可执行提示；用户再次作答后，系统判断是否需要下一层提示，最后给出总结并记录知识点。

### 场景 B：短时练习

用户有 10～25 分钟空闲时间，点击“开始练习”，系统基于当前学习目标生成 3～5 道题。每题完成后立即反馈，错题自动进入复习队列，会话结束显示结果和下一步建议。

### 场景 C：到期复习

用户打开首页看到“今日复习”，完成 1～3 个到期知识点的回忆题。系统根据作答结果更新下次复习时间，允许用户跳过并说明原因。

### 场景 D：疲惫但仍想继续

用户表达“好累”“不想学”等状态。桌宠先确认情绪，不进行诊断或强迫；提供“休息 5 分钟”“做 1 道简单题”“结束今天学习”三个选项，尊重用户选择。

### 场景 E：知识关联与备考规划（P1）

用户需要准备考试或理解复杂概念。系统将当前概念连接到用户已经掌握的知识，允许沿术语和替代解法分支探索，并把考试范围转化为可滚动调整的学习计划和掌握度报告。

### 场景 F：多来源学习（P2）

用户导入图片、试卷、论文、网页或第三方刷题记录。系统保留来源和授权状态，统一整理到个人知识库，生成路线、练习和复习任务；撤销外部授权后停止继续同步。

### 场景 G：技能扩展与本地数据（P2）

用户安装经过审核的学习技能或插件。系统在明确权限范围内运行扩展，并支持本地数据迁移、备份、恢复、可读导出、禁用和卸载。

### 场景 H：社区互助与内容生态（P3）

用户分享经过确认和脱敏的知识卡、题包或学习路线，与其他用户互助、组队或拜师。创作者可以发布内容和技能，平台负责审核、信誉、举报、申诉、版本和下架流程。

### 场景 I：AI 每日日记

用户在设置中开启“每天写一篇日记”，选择生成时间、语气、篇幅和是否包含学习/情绪内容。到达时间后，桌宠根据上一次日记截止点到本次截止点之间、用户主动提供且允许使用的会话、学习记录、练习结果和记忆片段，生成一篇日记。日记显示本地日期标签和素材时间范围；用户可以阅读、编辑、要求重写、标记事实错误、跳过本次生成或关闭功能。

日记是“上一截止点至本次截止点的记忆整理”的可见结果，不是用户真实经历的替代品。周期内没有足够事实时，系统可以写成简短的“本周期没有留下学习记录”或邀请用户补充，不能虚构事件、情绪、对话或行动。

### 场景 J：全量画像与主动智能模式（P3）

用户先开启「完全访问」，再在独立授权向导中确认当前版本的 `full_profile_v1`。用户可一次授权设备上全部可用的应用/窗口/进程、浏览器、键鼠与剪贴板、屏幕、文件/目录、通信、音视频、位置/传感器及健康/情绪等私人来源，并允许 Aervox 在本地持续形成使用与操作习惯画像。用户同时可以授权开机自启、应用退出后常驻、休眠恢复、重启自动恢复以及本地文件、浏览器/家居和外部消息等主动动作；每次启用、恢复、执行和异常都显示可理解的状态与授权来源。数据使用、保留、导出和撤权遵循 [CAP-033 需求](SRS.md#8-cap-033-全域感知与个人画像主动智能模式)。

## 4. 产品体验与信息架构

<a id="prd-home"></a>

### 4.1 首页工作台

首页提供五个入口。前三个驱动 MVP 核心闭环，“学习记录”负责复盘、纠错和数据可见性，“每日日记”在 MVP+ 上线：

1. **伴学主体**：Electron 显示桌宠主体、当前状态和一条简短提示；Web 使用同一份状态信息和工作台入口，但不渲染桌宠表现层；点击入口后进入对话或恢复上次任务。
2. **继续学习**：恢复当前学习目标、未完成练习或最近一次答疑。
3. **今日复习**：显示到期数量和预计耗时。
4. **学习记录**：查看目标、会话摘要、错题和复习结果。
5. **每日日记**：显示最近一篇日记、生成状态和未读标记；允许手动补写或关闭自动生成。

番茄钟作为轻量辅助功能，可在学习会话中启动，但不作为 MVP 成功标准。

<a id="prd-conversation-ui"></a>

### 4.2 视觉小说式对话形态

- 默认采用桌宠 + 底部对话栏，以角色名、当前语境和逐字显示形成视觉小说式体验，减少工具感；
- 支持快捷选项和自由输入，不能因为隐藏输入而阻断键盘用户；
- 逐字显示仅为表现层，必须支持跳过动画和复制文本；
- 默认展示当前会话，用户可从“学习记录”进入历史摘要；
- 每个回答标记为“提示”“讲解”“练习反馈”或“陪伴回应”，便于质量分析。

<a id="prd-safety-boundary"></a>

### 4.3 关系与情绪边界

产品提供熟悉感、连续性和支持感，不以“依赖感”作为优化目标。禁止：

- 暗示用户只能依赖桌宠或不应寻求真人帮助；
- 通过内疚、威胁、吃醋或“离开我会受伤”等方式促成留存；
- 将用户情绪归因于心理疾病，或给出治疗、用药建议；
- 把陪伴互动包装为真实人物关系。

## 5. 全生命周期功能地图

优先级表示产品生命周期中的重要性，不等于所有 P0 必须在首个 MVP 同时上线：

- **P0 产品成立基础**：学习与陪伴闭环的必要能力；分批进入 MVP、MVP+。
- **P1 差异化能力**：形成长期记忆、知识关联、个性化和桌宠体验壁垒。
- **P2 连接与智能化**：连接内容、外部平台、插件和更复杂的学习场景。

## 6. 成功指标

### 6.1 北极星指标

**每周有效学习会话数（WELS）**：同一用户在自然周内，完成至少一次“学习输入 + 用户作答/练习提交 + 反馈展示”的会话数。仅聊天、打开页面或启动番茄钟不计入。

### 6.2 核心指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 首次闭环完成率 | 首次会话完成一次学习闭环的用户 / 新用户 | 判断首屏和引导是否清晰 |
| D1/D7 留存 | 首次闭环后第 1/7 天再次产生有效会话的用户 / 首次闭环用户 | 判断短期价值 |
| 复习完成率 | 到期复习项中按时完成的数量 / 到期复习项数量 | 判断记忆机制是否被使用 |
| 引导采纳率 | 用户在提示后提交有效尝试的次数 / 提示次数 | 判断教学可执行性 |
| 教学错误率 | 抽检中事实错误的回答 / 抽检回答 | 发布和回滚门槛 |
| 安全事件发生率 | 被举报或触发安全升级的会话 / 全部有用户内容的会话 | 监控生产风险；另按风险类别、严重度和用户数分层，不能用“有效学习会话”作为分母 |
| 安全漏判/误报率 | 评估集或复核中漏掉的高风险样本 / 高风险样本；普通内容被误升级 / 普通样本 | 作为独立模型质量指标，避免事件发生率受用户群体变化误导 |
| 记忆纠错率 | 被用户纠正或否认的高层记忆 / 被展示的高层记忆 | 判断记忆是否准确且不过度推断 |
| 记忆召回采纳率 | 被调用记忆中用户认为相关的数量 / 被调用记忆数量 | 判断记忆树和检索价值 |
| 过度压缩率 | 人工抽检中丢失关键约束的优化记忆 / 抽检优化记忆 | 约束逐级压缩质量 |
| 日记阅读率 | 被用户打开的自动日记 / 成功生成的自动日记 | 判断日记是否提供可感知价值 |
| 日记保留率 | 生成 7 天后仍保留的日记 / 成功生成的日记 | 判断内容质量和持续价值 |
| 日记事实纠错率 | 被用户标记事实错误的日记 / 被阅读日记 | 监控虚构和错误归纳风险 |

分析字段与可选分析同意见[数据隐私规范](DATA_PRIVACY.md#analytics-events)。

### 6.3 生命周期指标

| 阶段 | 主要指标 | 说明 |
|---|---|---|
| 验证期 | 首次闭环完成率、D1/D7、复习完成率、教学错误率 | 判断核心闭环是否成立 |
| 成长期 | 4 周学习留存、月度掌握知识点数、错题复发率、计划完成率 | 判断长期学习效果和个性化价值 |
| 扩展期 | 外部来源接入率、同步成功率、插件启用后留存、知识库检索成功率 | 判断连接能力是否创造价值而非增加复杂度 |
| 生态期 | 内容供给者留存、优质内容消费率、举报处理时效、侵权/违规率、互助问题解决率 | 判断生态健康度和治理成本 |

除 MVP 已定义的实验门槛外，其他阶段的目标值在进入该阶段前依据上一阶段基线确定，并写入对应版本计划。不得用总消息数、在线时长或情绪互动次数单独作为成功指标。

### 6.4 指标治理

- 指标字典必须记录 Owner、事件版本、分子、分母、排除条件、时间窗口、时区、去重规则和数据延迟；口径变更不得回填成同一版本；
- EXP-001～003 在开始前预注册样本量、分流、主要/护栏指标、最短周期和停止条件，并报告绝对值、相对变化与 95% 置信区间；
- WELS 是北极星而非唯一成功标准，必须与教学正确性、安全、记忆纠错、日记事实性、退出率和成本共同评审；
- 分析数据不得用于推断敏感属性或对脆弱用户进行商业定向；用户拒绝可选分析后，安全/可靠性事件必须最小化且与产品分析隔离。

## 7. 产品阶段

阶段编号：`R0` 原型验证，`R1` MVP，`R1.5` MVP+，`R2` P1 学习深化，`R3` 端形态扩展，`R4` P2 连接智能化，`R5` P3 生态规模化。阶段是交付容器，不是能力优先级；阶段可重排，能力 ID 和 P0～P3 优先级不变。

| 阶段 | 目标 | 交付 |
|---|---|---|
| 0. 原型验证 | 验证交互方向 | Web 工作台、桌宠占位形象、引导对话原型；5～10 名用户可用性测试 |
| 1. MVP | 验证学习闭环 | P0 的目标、引导对话、练习、错题、最小复习、记录、文本答疑、轻量陪伴，以及临时/短期记忆 |
| 1.5 MVP+ | 补齐基础可用性 | P0 剩余能力：AI 每日日记、图片答疑、消息管理、基础人格偏好、资料整理和长期记忆；完成安全/隐私上线评审 |
| 2. P1 学习深化 | 建立差异化壁垒 | 系统记忆树、层级对话、会话地图、思维宇宙、自适应报告、考试计划、多人格模板 |
| 3. 端形态扩展 | 验证常驻体验 | Windows/macOS 外壳、移动端适配、通知、可选置顶、Live2D；跨设备同步另行评审 |
| 4. P2 连接智能化 | 扩展内容和工具边界 | 技能/插件、学习路线、视频、外部题库、文献、试卷扫描、收藏知识库与本地可移植性完善 |
| 5. P3 生态规模化 | 形成网络效应 | 社区互助、公开知识网页、主动提醒深化、内容/技能市场、机构与监护模式，以及经独立授权的 CAP-033 主动智能模式 |

每个阶段必须同时满足三类退出条件：用户价值指标达到阶段目标、核心质量/安全门槛通过、数据迁移和退出路径可用。不以功能数量作为进度标准；后续阶段可以取消或重排，但不能静默改变已经发布的数据和权限承诺。

### 7.1 阶段依赖

| 进入阶段 | 前置依赖 | 准入要求 |
|---|---|---|
| MVP+ | MVP 学习闭环和数据删除链路稳定 | 完成图片/附件数据分类，建立内容引用和消息级联规则 |
| P1 | 临时、短期和长期记忆的来源链、纠错和删除机制稳定 | 建立系统记忆树、知识关系纠错、算法版本迁移和人格回归评估 |
| 端形态扩展 | Web 交互价值已验证 | 完成桌面权限、更新、签名、崩溃恢复和资源占用方案 |
| P2 | 核心 API 和权限模型稳定 | 建立 OAuth/授权撤销、插件沙箱、内容许可、同步冲突和本地迁移方案 |
| P3 | P2 的内容与插件治理可控 | 建立用户身份、社区审核、版权处理、支付结算、未成年保护和运营响应机制；CAP-033 另须完成全量画像授权、OS 能力、后台恢复、本地存储、动作授权、提炼保留和导出删除门禁 |
